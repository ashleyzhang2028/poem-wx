# 跬步小程序 · 架构说明

> 本文说明「poem 网页版 → 微信小程序」的移植口径：哪些照搬、哪些换掉、为什么。
> 界面细节看代码与 `README.md`，这里只写形状与边界。

## 一、总原则

移植的判据不是「和网页版长得一样」，而是**主体界面颜色与风格一致、呈现方式按小程序的最佳实践走**。

- **照搬**：语料、复习算法、排期逻辑、每日计划、四套算法、宋代传统色与宋体排版口径
- **换掉**：账号体系（邮箱密码 → 微信）、页面外壳（顶栏/底栏 → 原生 tabBar 与导航栏）、离线方案（Service Worker → 小程序包 + 后台缓存）
- **不做**：用户报告审核、家庭子用户
- **后来补上**（Issue #1 评论追加）：注音渲染、语音朗读、题库与飞花令、正文全文检索、云端同步、管理页与权限分层

## 一点五、能力不可用时，界面上就不该有它

用户原话：**「当 TTS 不可用时，所有界面中的播放按钮、播放工具栏、播放设置都不在任何 UI 界面显示。」**

这句话被当成一条通用规矩执行，而不是只针对朗读：

| 能力 | 不可用时的界面表现 |
|---|---|
| 语音朗读 | 详情页工具栏那格、播放工具栏、设置里的朗读卡、「我的」页入口 —— 全部不渲染 |
| 注音 | 读音表没生成时，阅读页的注音切换与设置页的注音卡都不渲染 |
| 正文全文检索 | 索引没生成时，搜索页不出现「正文全文」模式切换，退回索引字段搜索 |
| 云端同步 | 后端没就绪时，「我的」页如实写「后端未就绪 · 已攒 N 条」，不做假成功 |

判定这件事的函数一律叫 `readiness()`，**同步返回**，因为界面要在渲染时就决定显不显示：

```js
{ visible: false, usable: false, state: "unsupported", reason: "当前环境不支持播放音频" }
{ visible: true,  usable: false, state: "awaiting",    reason: "朗读通道待接入" }
{ visible: true,  usable: true,  state: "ready" }
```

- `visible` —— 界面里该不该出现这个元素
- `usable` —— 出现了也不能播时，显示成「待开通」并在点了之后给一句人话原因

**已授权但通道没就绪**（awaiting）与**压根没这个能力**（denied / unsupported）是两件事，
前者可见但灰着，后者连位置都不占。把这两者混起来，就会出现「按钮亮着、点下去弹 toast」
这种假存活 —— 那正是这轮要消掉的东西。

自检里有一条**源码扫描**守着它：`pages/reader/reader.wxml` 里每个 `speak-bar` /
`speak-ctrl` / `sp-btn` 元素，往上 30 行内必须撞到 `speakVisible` 门禁，否则自检直接红。
比字符串比对结实，也比人眼可靠。

## 一点六、朗读：三条通道，谁先就绪用谁

1. **微信同声传译插件**（`WechatSI`）—— 免费，但要企业/个体户主体申请插件
2. **自家 TTS**（腾讯云 / 讯飞 / 火山）—— 收费或自带额度，要后端签名
3. **已缓存的音频** —— 上次联网读过的句子，这次离线还能读

整句合成一次拿 mp3，**不逐字合成**（那会把 QPS 烧光）。合成结果按
`provider + 文本哈希` 缓存进本机存储 —— 合成要钱也可能要 QPS，同一句诗不该合两次；
按 provider 分开缓存是因为换通道时音色变了，不能拿旧音频冒充。

> ⚠️ **微信不允许个人主体做虚拟支付。** 所以付费档不能在小程序内下单，
> `pro` / `max` 只能由管理员发放（兑换码，或后端名录里改档）。
> 这一条决定了管理页长什么样，见 § 四。

## 二、目录形状

```
miniprogram/
├── app.json / app.js / app.wxss     # 路由表 / 启动预热 / 全局样式
├── styles/tokens.wxss               # 设计令牌（与网页版 css/style.css 的 :root 一一对应）
├── utils/                           # 纯逻辑，全部可在 Node 里跑
│   ├── corpus.js                    # 语料读取（索引 + 正文分片）
│   ├── store.js                     # 本机存储与设置
│   ├── review-models.js             # 四套复习算法
│   ├── scheduler.js                 # 每日计划与进度总览
│   ├── quiz.js                      # 出题与判分内核
│   ├── pinyin.js                    # 注音（多音字消歧，与网页版同口径）
│   ├── speech.js                    # 朗读（三通道 + 可用性判定）
│   ├── text-search.js               # 正文全文检索（倒排索引）
│   ├── feihua/index.js              # 飞花令（令字池 / 查一查 / 接句判定）
│   ├── entitlement.js / tiers.js    # 权限分层
│   ├── auth.js                      # 微信登录（含无后端时的降级）
│   ├── remote.js                    # 后端契约（同步 / TTS / 管理）
│   ├── sync.js                      # 同步调度（启动 / 背完 / 手动）
│   └── admin.js                     # 管理页数据层
├── pages/                           # 主包：四个 tab + 列表 + 详情
├── packages/                        # 分包：设置 / 大会 / 进度 / 管理
└── data/                            # 由 scripts/build-data.js 生成，不入库

scripts/
├── build-data.js                    # 语料编译（从 poem 仓库取）
└── check.js                         # 离线自检
```

`utils/` 里的模块**一律不碰 `wx` 之外的平台 API**，`wx` 只在 `store.js` 与 `auth.js` 里出现。
这样排期与算法可以在 Node 里直接验，不必开开发者工具。

## 三、数据存哪：冷热分离，正文一律上云

这是 Issue 里点名要回答的问题。判断依据是**实测体积**，不是感觉：

| 项 | 实测 |
|---|---|
| 全部正文（5575 条，网页版 `data/text-master.js`） | 24.3 MB，gzip 后 4.9 MB |
| 其中**课内 251 首** | **223 KB**，中位 0.41 KB，最大 8.7 KB（《屈原列传》） |
| 全部索引（不含正文，5575 条，按 17 部集子拆分） | 1.0 MB |
| 代码与样式 | 104 KB |
| **主包合计（索引 + 课内正文 + 代码）** | **1.30 MB** |
| 小程序主包上限 / 总包上限 | 2 MB / 20 MB |

结论：**全量正文不可能进包，课内正文可以，而且应该。**

一部《昭明文选》加一部《名著导读》就超了 20 MB 总包；但课内 251 首只有 223 KB，
进包后主包 1.30 MB，离 2 MB 上限还有 0.7 MB 余量。这笔账值得花，因为它买的是
**首页「每日背诵」与详情页不必等网络** —— 这两个页面是每天真正被打开的地方，
用 223 KB 换掉一次列表到正文的云端往返，是这轮唯一划算的体积支出。

于是按三层落：

1. **包内（免网络）**
   - 各集子索引 `data/books/<book>.json`（篇名/作者/朝代/出处/分组，不含正文）
   - **课内 251 首的正文与译文 `data/course.json`**
   - 集子表 `data/books/books.json`、分片清单 `data/texts/manifest.json`
   - 索引里**不带正文**，这是主包能压住的前提

   ⚠️ 索引**只按集子存一份**，不另存全站投影。第一版曾同时产出
   `search.json`（全站）与各集子索引，两者是同一份数据的两种投影，
   把主包顶到 2.6 MB —— 超了 2 MB 上限。去掉重复后降到 1.08 MB。
   代价是「全站搜索」要逐集子遍历，但索引按集子拆开本就是这个目的：
   搜一次的成本跟命中集子数走，而不是跟全站条数走。

2. **正文分片（走云）**
   - 课内之外的 5324 条正文按 200 KB 分桶成 119 个文件（合计 23 MB），每条正文的桶号由清单固定
   - 落到 **腾讯云 COS + CDN**，客户端按需取；同一条永远落同一个文件，便于做版本号增量缓存
   - 不选「小程序云开发数据库」：几万条级查询的性能与成本都不划算，而这里要的只是**静态文件分发**
   - **课内条目不再进分片**：同一份正文不该在包内和 CDN 各存一份，
     否则以后改课内正文会出现「哪一份是新的」这种要命的歧义

3. **本机**
   - 背诵进度、设置、已读标记、自选集合 —— 只存在本机
   - 未登录一行数据都不外发

为什么不做成「全量放本地 + 按需解压」：包内解压要占运行内存，5 MB 正文解出来是 24 MB 字符串，
低端机上直接触发内存回收，换来的是「省一次 CDN 请求」，不划算。

**为什么课内不跟着走分包**：分包上限虽是 2 MB，但分包要**先进去才下载**，
而「每日背诵」在首页上就要拿正文出题。把课内放进分包，等于首页出题前先等一次分包下载 ——
那正是要避开的卡顿，所以它走主包。

**边界写死在自检里**：`scripts/check.js` 会验「包内正文就是课内那 251 条」「包内与分片不重叠」，
并给课内正文单列 400 KB 预算 —— 超了就得重新算账，不是悄悄涨上去。

## 四、管理页与权限分层

与 poem 同一张权限表，三档 `free` / `pro` / `max` 外加一个「登录」门槛。
15 条能力，见 `utils/entitlement.js` 的 `CAPS`。**档位逐条对齐网页版**，
自检里把网页版的口径钉成期望值 —— FSRS 曾经在这里写成 `pro`（网页版是 `max`），
那属于会真实惹事的那种漂移：同一份进度跨端同步，一端说能用一端说不能用。

小程序端**故意不做**的五条不在表里（PDF 打印、子用户、注音勘误审核、
正式考试、文学常识考试），依赖后端或跑不了，所以界面上也不留入口 ——
列一个点不动的入口比没有更糟。

> `login` 不是第三档，是「免费 + 登录」：它比 `free` 高一点，但不用付费。
> 所以 `can()` 里把它单独拎出来判，不跟 `s.tier` 比大小 ——
> 直接比会把「免费已登录」的人挡在朗读门外（`free` 的 rank 是 0、`login` 是 1）。

**但这里有一条平台现实必须写在最前面**：微信不允许个人主体做虚拟支付。
所以付费档不能在小程序内下单，`pro` / `max` 只能由管理员发放 —— 兑换码，
或后端名录里改档。管理页做的就是这件事，不是收银台。

三条口径：

1. **客户端的档位不是安全边界**。改一下本机存储就能提档，所以它管的只是
   「界面给谁看」；真正扣配额必须在服务端做。云端就绪前，付费能力一律按
   未授权处理（`status().blocked === "local"`），宁可少给，也不能让改个存储就提档
2. **本机宿主**。没登录时所有能力可用 —— 本机数据只属于本机，
   这是网页版那条边界在小程序端的落点。朗读的界面显隐用「宿主可用性」而不是
   「授权档位」判断，原因就在这里
3. **名录不许进代码库**。名单里是别人的账号标识。走环境变量 `POEM_ROSTER` 导入，
   构建产物 `data/roster.json` 落在 `.gitignore` 里。没有名单就不生成，
   管理页如实显示「名录未导入」，不凭空编人

> 这条口径有出处。poem 网页版的 `docs/auth-design.md` §4.4（Issue #276）
> 已经删掉了「首次打开这个浏览器就是管理员」那种兜底，理由是用户原话：
> **「清一次浏览器存储就能当管理员的所谓权限，不是权限。」**
> 小程序端照抄这条结论。

## 五、账号体系：微信登录

网页版是「邮箱 + 密码 / 随机码」两条路签同一枚会话。小程序端整块换掉：

```
wx.login() 拿 code
  → 自家后端 code2Session 换 openid / unionid
  → 后端下发 access（7 天）+ refresh（30 天）双 token
  → 客户端只存 token，不落 openid 明文
```

边界沿用网页版那三条，一条都不松：

- **不登录也能用全部功能** —— 登录只增加「数据不丢 + 跨设备」，不拿现有功能当人质
- **后端没就绪时降级** —— `utils/auth.js` 在未配置 `baseUrl` 时落一个本机身份，功能一个不少，只是不同步
- **不静默抓取** —— 昵称头像走 `chooseAvatar` 与 `type="nickname"`，由用户主动给；不做静默 `getUserProfile`
- **提供注销入口** —— 微信强制要求，见「我的 → 清空本机数据」

## 六、界面口径

- **颜色**：主色 `#2f6055`（雨过天青）、底色 `#f6f1e3`（素绢）、朱砂 `#a83b32`、琥珀 `#a55c19`、缃色 `#f0cd7c` —— 与网页版逐值相同，见 `styles/tokens.wxss`
- **能力显隐**：见 § 一点五 —— 不可用的能力在界面上不留空位，也不留假按钮
- **字体**：正文宋体、界面黑体，与网页版同一口径；小程序端不外挂字体文件，落系统自带的宋/黑体
- **外壳不做照搬**：网页版那套自绘顶栏与底栏换成原生导航栏 + 原生 tabBar，这是小程序的推荐呈现方式，也免掉一整套安全区与胶囊避让的计算
- **进度环**用纯 CSS 锥形渐变，不引 canvas，也不带图片资源

## 七、还没做的

诚实记账，免得看成「已补齐」：

这一节原来的五项都做完了，写清楚各自的做法与仍然待外的部分：

- **注音渲染**：读音表构建时进包（`data/pinyin-table.json`，71 KB / 3609 字 / 117 条词组）。
  多音字消歧**与网页版 `js/pinyin.js` 逐条对齐**：词组优先 → 「一 / 不」变调 →
  序数词判读 → 回退首读。词组表由构建脚本从网页版源码里**原样抠出来**，
  不抄副本 —— 抄一份就等于留了个会漂的镜子，那边改了口径这边不会知道
- **朗读**：三条通道都接了，见 § 一点六。**仍待外的部分**：同声传译插件要企业主体
  申请，正式 appid 下来前 `readiness()` 会如实报 `awaiting`
- **题库 / 飞花令**：题库页 + 模拟考试共用 `utils/quiz.js` 的出题器与 `judge()`，
  判分口径只此一处（两页各写一遍，迟早会有一个先把「模糊」算成对）。
  题型从 3 种扩到 5 种（接下句 / 接上句 / 认作者 / 填朝代 / 认篇名），可按需勾选。
  飞花令补了「接句」：给一个字，玩家先说一句再翻答案，不然只是高级搜索。
  查一查留在大会页就地翻句，闯关进独立页 `packages/game/feihua` ——
  闯关要输入、要判句、要记轮次，塞进列表页会把它压塌。
  判句三条判据（句中有令字 / 这句真的在语料里 / 这一关没说过的）
  在 `utils/feihua/index.js`，不依赖正文倒排 —— 只扫课内 251 首，
  所以断网也能玩
- **正文全站搜索**：倒排索引只记「字 → 分片」，**不记行号偏移**。
  行号能把索引撑到 2-3 倍，而一片才 200KB，读进来再定位一次的开销远小于把索引做大。
  课内正文不进索引 —— 它已经在主包里，现场扫比查索引还快
- **云端同步**：`utils/remote.js` 把契约写死（pull / push / 增量按时间戳），
  本机离线队列攒着，联网后一次推。**没后端时不上报成功**，如实说「已攒 N 条」
- **管理页**：见 § 四、五
- **权限分层判据**：`entitlement.can()` 是唯一入口，界面不许自己拼「能不能用」
  （措辞也归 `entitlement.hint()`，不然「为什么不能用」会散在十几个页面里）。
  自检里有一组断言把**宿主关掉**再走三档 —— 宿主模式下三档长得一模一样，
  判据写反了也一路绿，只有关掉宿主才暴露

## 八、怎么验

```bash
POEM_WEB_DIR=/path/to/poem node scripts/build-data.js   # 生成语料
node scripts/check.js                                    # 离线自检，397 项
```

自检 **397 项**，覆盖：页面四件套齐全、require 可解析、语料完整性（含分片抽查）、
**包内/分片的边界**（课内正文进包且不与分片重复、课外仍走分片、主包体积与课内正文预算、
读音表预算、全文索引不在主包）、四套算法的关键行为、排期内核（到期优先 / 不重复 /
范围正确 / 跨天归零）、WXML 字段粗查与标签配平、事件处理函数存在性、页面跳转目标存在性。

其中三节是这轮为「能力不可用就不显示」加的：

- **§5.5 可用性开关**：把三种运行环境真的摆出来（无音频接口 / 有音频无插件 / 全就绪），
  看 `readiness()` 说什么。另含读音表的多音字消歧断言（`白发→fà`、`作为→wéi`、
  `不是→bú`、`一行→yì`）与全文检索的候选分片收敛
- **§7.5 界面显隐源码扫描**：朗读元素必须挂在门禁之内，页面必须从 `readiness()`
  取状态而不能自己写死
- **§7.6 / §8.5 权限分层与分包**：三档顺序单调、能力矩阵不漏项、
  本机写 `max` 不外溢成服务端授权、新页面注册进了分包

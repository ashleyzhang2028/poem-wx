# 跬步小程序 · 架构说明

> 本文说明「poem 网页版 → 微信小程序」的移植口径：哪些照搬、哪些换掉、为什么。
> 界面细节看代码与 `README.md`，这里只写形状与边界。

## 一、总原则

移植的判据不是「和网页版长得一样」，而是**主体界面颜色与风格一致、呈现方式按小程序的最佳实践走**。

- **照搬**：语料、复习算法、排期逻辑、每日计划、四套算法、宋代传统色与宋体排版口径、
  注音的读法判据、飞花令的判定口径、**free/pro/max 的整张能力表**
- **换掉**：账号体系（邮箱密码 → 微信）、页面外壳（顶栏/底栏 → 原生 tabBar 与导航栏）、
  离线方案（Service Worker → 小程序包 + 后台缓存）、朗读（speechSynthesis → TTS 服务）
- **不做**：用户报告审核、注音勘误审核、家庭子用户、PDF 打印
  （前两项依赖后端审核队列，后两项小程序端做不划算或不支持）

## 二、目录形状

```
miniprogram/
├── app.json / app.js / app.wxss     # 路由表 / 启动预热 / 全局样式
├── styles/tokens.wxss               # 设计令牌（与网页版 css/style.css 的 :root 一一对应）
├── utils/                           # 纯逻辑，全部可在 Node 里跑
│   ├── corpus.js                    # 语料读取（索引 + 正文分片 + 读音表）
│   ├── store.js                     # 本机存储与设置
│   ├── review-models.js             # 四套复习算法
│   ├── scheduler.js                 # 每日计划与进度总览
│   ├── pinyin.js                    # 注音：多音字消歧与排版单元
│   ├── fulltext.js                  # 正文全文检索（位次倒排）
│   ├── feihua.js                    # 飞花令：令字池、查一查、闯关判定
│   ├── quiz.js                      # 出题内核（六种题型）
│   ├── entitlement.js               # free / pro / max 能力表
│   ├── sync.js                      # 云端同步（离线队列 + 冲突判定）
│   ├── speech.js                    # 朗读：多 TTS provider
│   ├── remote.js                    # 云端数据通道（COS + CDN）
│   └── auth.js                      # 微信登录（含无后端时的降级）
├── pages/                           # 主包：四个 tab + 列表 + 详情
├── packages/                        # 分包：设置（含管理层级）/ 大会 / 进度
└── data/                            # 由 scripts/build-data.js 生成，不入库

scripts/
├── build-data.js                    # 语料编译（从 poem 仓库取）
└── check.js                         # 离线自检，352 项
```

`utils/` 里的模块**一律不碰 `wx` 之外的平台 API**，`wx` 只在 `store.js`、`auth.js`、
`remote.js`、`sync.js`、`speech.js` 里出现。算法与判据这几块（pinyin / fulltext /
feihua / quiz / entitlement / scheduler / review-models）完全不碰 `wx`，
所以能在 Node 里直接验，不必开开发者工具 —— 自检就是这么跑的。

## 三、数据存哪：冷热分离，正文一律上云

判断依据是**实测体积**，不是感觉：

| 项 | 实测 |
|---|---|
| 全部正文（5575 条） | 24.3 MB，gzip 后 4.9 MB |
| 全文倒排（44 列） | 8.8 MB |
| 全部索引（不含正文，按 17 部集子拆分） | 1.0 MB |
| 读音表（1517 字，只留多音与生僻） | 21 KB |
| 代码与样式 | 约 190 KB |
| **主包合计** | **1.21 MB** |
| 小程序主包上限 / 总包上限 | 2 MB / 20 MB |

**正文不可能进包**：一部《昭明文选》加一部《名著导读》就超了总包上限。
**倒排也不可能进包**：9 MB 顶主包四倍。

于是按三层落：

1. **包内（免网络）**
   - 各集子索引 `data/books/<book>.json`（篇名/作者/朝代/出处/分组，不含正文）
   - 集子表 `data/books/books.json`、分片清单 `data/texts/manifest.json`
   - 读音表 `data/pinyin.json`

   ⚠️ 索引**只按集子存一份**，不另存全站投影。第一版曾同时产出
   `search.json`（全站）与各集子索引，两者是同一份数据的两种投影，
   把主包顶到 2.6 MB —— 超了 2 MB 上限。去掉重复后降到 1.08 MB。

   ⚠️ 读音表**只收需要标注的字**：多音字 60 + 生僻字 1457 = 1517 字。
   全表 3609 字原始 55 KB，「床前明月光」那些常用单音字标出来没有意义，
   砍掉后 21 KB。

2. **正文分片（走云）**
   - 按 200 KB 分桶成 120 个文件（23 MB），每条正文的桶号由清单固定
   - 落到腾讯云 COS + CDN，客户端按需取
   - 不选「小程序云开发数据库」：几万条级查询的性能与成本都不划算，
     而这里要的只是**静态文件分发**

3. **全文倒排（走云）**
   - 详见下面第五节。44 列合计 8.8 MB，同样走 COS + CDN

4. **本机**
   - 背诵进度、设置、已读标记、自选集合 —— 只存在本机
   - 未登录一行数据都不外发

为什么不做成「全量放本地 + 按需解压」：包内解压要占运行内存，5 MB 正文解出来是
24 MB 字符串，低端机上直接触发内存回收，换来的是「省一次 CDN 请求」，不划算。

## 四、账号体系：微信登录

网页版是「邮箱 + 密码 / 随机码」两条路签同一枚会话。小程序端整块换掉：

```
wx.login() 拿 code
  → 自家后端 code2Session 换 openid / unionid
  → 后端下发 access（7 天）+ refresh（30 天）双 token
  → 客户端只存 token，不落 openid 明文
```

边界沿用网页版那三条，一条都不松：

- **不登录也能用全部功能** —— 登录只增加「数据不丢 + 跨设备」，不拿现有功能当人质
- **后端没就绪时降级** —— `utils/auth.js` 在未配置 `baseUrl` 时落一个本机身份，功能一个不少，只是不同步
- **不静默抓取** —— 昵称头像走 `chooseAvatar` 与 `type="nickname"`，由用户主动给；不做静默 `getUserProfile`
- **提供注销入口** —— 微信强制要求，见「我的 → 清空本机数据」

## 五、全文检索：为什么是单字倒排

索引字段搜索搜不到正文里的字。用户搜「明月几时有」——那是正文，索引里没有，
一无所获。那是他真正想要的东西。

**做法**：把全站正文首尾相接铺成一条位次长串（286 万位），对每个字记下它出现的
所有位次，按 64K 位次一列切成 44 个文件。

**为什么是单字不是分词**：语料是文言，通用分词器切出来更不准；而单字 + 位置校验，
一次遍历就能做真正的子串匹配。

**为什么位次不是条目序号**：第一版把「第几条」当位次，于是 5000 字的《昭明文选》
与 20 字的五绝占的位次一样近，子串能横跨两条正文凑出假命中。改成「正文里第几个字」
之后，两条之间自然断开 —— 相邻两条的字号不连续，凑不出假的。

**踩过的坑：差分编码不能裸拼 base36。**

为了省体积，位次用差分 + base36 压成字符串。问题是差值 ≥ 36 时
`toString(36)` 会吐两位（`(967-308).toString(36) === "ib"`），裸拼就没有边界了，
解码方按单字符累加，从那里开始整段错位。

表现是「明月几时有」搜出「白发三千丈」：五个字各自都命中，连起来却不成句。
数据看着完全合理，代码读起来也完全合理。

修法是加显式长度位：每段先给「数字占几位」，再给数字本身。

**为什么 44 列**：一列 64K 位次约 200 KB（压缩前），全站 44 列。
列多则单文件小但请求多，列少则反之。44 个并发请求在弱网下也能接受；
再小就会把请求数推上千位，不如直接下整包。搜一个字最多拉 44 个文件，
且只有第一次搜才拉，之后落本机缓存。

**取不到怎么办**：退回索引字段搜索，并**如实告诉调用方「这次没搜正文」** ——
界面上会显示「正文索引未接入，这次只搜了篇名与作者」。不报错，也不假装搜过了。

## 六、注音：读音表进包，判读顺序照搬

判读顺序与网页版 `js/pinyin.js` 一致：

1. 表里只有一读 → 直接用
2. 多音字 → 先查词组表（117 条），命中就按词组读
3. 「一」「不」按后一字的声调变读
4. 都不中 → 表里第一个读音

网页版还有第 0 优先级的「用户注音勘误」（PinyinFix），小程序端没搬 ——
那套依赖后端审核队列。

**渲染**：小程序没有 `<ruby>`，拼音只能自己排。`utils/pinyin.js` 返回的是
分段数组（`[{c, py, on}]`）而不是 HTML，WXML 用 flex 竖排两个字，
字号与行距全交给 WXSS。这样避开了 `rich-text` 的白名单麻烦，
也让「全文注音」与「只标生字」只差一个 `on` 字段。

## 七、朗读：三条路，免费的那条有门槛

| 方案 | 费用 | 门槛 |
|---|---|---|
| 微信同声传译插件 | 免费 | 公众平台申请插件权限，**个人主体走不通** |
| 自建 TTS | 收费 | 自家后端签名，微信后台要配 request 域名 |
| 都没有 | — | 明确告知不可用，不静默失败 |

`utils/speech.js` 按多 provider 写：`si`（同声传译）与 `remote`（自建）。
默认 `si`，没申请到插件时 `available()` 返回 false，试听按钮会弹出
「要先去公众平台申请插件权限」而不是没反应。

**合成策略**：整篇一次请求，不逐字、不逐句。插件有 QPS 限制，一句一个请求
会被限流；而一篇五绝合起来才三四十字。长文按句读切段顺序合成，段间预取
下一段，播放不中断。

**音频不留档**：合成出来的临时文件播完即弃，不做本地音频库 ——
网页版也没有音频文件，这条口径保持一致。

## 八、界面口径

- **颜色**：主色 `#2f6055`（雨过天青）、底色 `#f6f1e3`（素绢）、朱砂 `#a83b32`、
  琥珀 `#a55c19`、缃色 `#f0cd7c` —— 与网页版逐值相同，见 `styles/tokens.wxss`
- **字体**：正文宋体、界面黑体，与网页版同一口径；小程序端不外挂字体文件，
  落系统自带的宋/黑体
- **外壳不做照搬**：网页版那套自绘顶栏与底栏换成原生导航栏 + 原生 tabBar，
  这是小程序的推荐呈现方式，也免掉一整套安全区与胶囊避让的计算
- **进度环**用纯 CSS 锥形渐变，不引 canvas，也不带图片资源
- **注音的排法**欠讲究但够用：一个汉字一个竖排单元，flex 换行，
  标点不占注音位。字号变了不会压字

## 九、还没做的

诚实记账，免得看成「已补齐」：

- **注音勘误**：网页版有用户提交读音修正的审核队列（`PinyinFix`），
  小程序端没搬 —— 依赖后端审核流，与「不后端也能用全部功能」的边界冲突
- **子用户 / 家庭**：能力表里留了 `profile.family`（Pro 起，1→3→180），界面没做
- **PDF / 打印**：小程序端做不了，`export.paper` 这条在网页版用
- **正式考试 / 文学常识考试**：依赖后端组卷与判分，入口没列出来 ——
  列一个点不动的入口比没有更糟
- **云端同步的后端**：`utils/sync.js` 的契约、离线队列、冲突判定都写好并测过，
  但 `/api/sync/*` 还没部署，现在实际走的是本机
- **用户报告**：网页版能提交勘误并进审核队列，小程序端没做

## 十、怎么验

```bash
POEM_WEB_DIR=/path/to/poem node scripts/build-data.js   # 生成语料
node scripts/check.js                                    # 离线自检，352 项
```

自检覆盖：

- 页面四件套齐全、require 可解析、WXML 字段与事件粗查
- 语料完整性（含分片抽查）、索引不带正文
- 四套算法的关键行为、排期内核（到期优先 / 不重复 / 范围正确 / 跨天归零）
- **注音**：多音字按词组消歧（白发 / 长 / 少小）、「一」「不」变读、生字模式放过常用字
- **全文倒排**：差分编码往返、位次基址升序、命中真实短语、不把词序搞反
- **飞花令**：令字分档、查一查只列含令字的句子、闯关拒编造 / 拒重复 / 容忍漏标点
- **题库**：六种题型都能出题、四选一唯一正确答案、填字题真的挖了空
- **权限表**：20 条能力逐条对照网页版的 minTier，漂了就报错
- **同步**：拉回落地、旧记录不覆盖新记录、删除能记、键名与网页版一致
- **包体积**：主包 ≤ 2MB，且倒排确实没被打进包

# 跬步小程序 · 架构说明

> 本文说明「网页版 → 微信小程序」的移植口径：哪些照搬、哪些换掉、为什么。
> 界面细节看代码与 `README.md`，这里只写形状与边界。

## 一、总原则

移植的判据不是「和网页版长得一样」，而是**主体界面颜色与风格一致、呈现方式按小程序的最佳实践走**。

- **照搬**：语料、复习算法、排期逻辑、每日计划、四套算法、宋体排版口径
- **换掉**：账号体系（邮箱密码 → 微信）、页面外壳（顶栏/底栏 → 原生 tabBar 与导航栏）、离线方案（Service Worker → 小程序包 + 后台缓存）
- **不做**：用户报告审核、家庭子用户
- **后来补上**（Issue #1 评论追加）：注音渲染、题库与飞花令、正文全文检索、云端同步、用户列表与权限分层
- **边界改过一次**（Issue #1 最后一条评论）：原本是「不登录也不缺功能」，现在改成
  **「能进门，不能白用」** —— 未登录只能看首页目录，点不动；free / pro / max 三档
  都由管理员按人分配。这条改动撤掉了 README 里原来那句「打开即用，不登录也不缺功能」，
  见 § 四

## 一点五、能力不可用时，界面上就不该有它

用户原话：**「通道不可用时，所有界面中的播放按钮、播放工具栏、播放设置都不在任何 UI 界面显示。」**

这句话被当成一条通用规矩执行，而不是只针对某一个能力：

| 能力 | 不可用时的界面表现 |
|---|---|
| 注音 | 读音表没生成时，阅读页 / 背诵弹层的注音切换不渲染 |
| 正文全文检索 | 索引没生成时，搜索页不出现「正文全文」模式切换，退回索引字段搜索 |
| 同步进度 | 通道没开时，「我的」页如实写「换手机进度不跟随 · 点一下重试」，不做假成功。**界面不出现「后端 / 云端」这类实现词汇**（2026-10-04，见 design-system「别跟用户说数据存在哪」） |

判定这件事的函数一律叫 `readiness()`，**同步返回**，因为界面要在渲染时就决定显不显示：

```js
{ visible: false, usable: false, state: "unsupported", reason: "这台设备出不了声" }
{ visible: true,  usable: false, state: "awaiting",    reason: "通道还没接上" }
{ visible: true,  usable: true,  state: "ready" }
```

- `visible` —— 界面里该不该出现这个元素
- `usable` —— 出现了也不能播时，显示成「待开通」并在点了之后给一句人话原因

**已授权但通道没就绪**（awaiting）与**压根没这个能力**（denied / unsupported）是两件事，
前者可见但灰着，后者连位置都不占。把这两者混起来，就会出现「按钮亮着、点下去弹 toast」
这种假存活 —— 那正是这轮要消掉的东西。

自检里有一条**源码扫描**守着它：能力不可用时的元素（`sfxVisible` 这类门禁之外的）
一冒出来就红。比字符串比对结实，也比人眼可靠。

> ⚠️ **微信不允许个人主体做虚拟支付。** 所以付费档不能在小程序内下单，
> `pro` / `max` 只能由管理员发放（兑换码，或后端名录里改档）。
> 这一条决定了权限页与用户列表长什么样，见 § 四。

## 二、目录形状

```
miniprogram/
├── app.json / app.js / app.wxss     # 路由表 / 启动预热 / 全局样式
├── styles/tokens.wxss               # 设计令牌（与网页版 css/style.css 的 :root 一一对应）
├── utils/                           # 纯逻辑，全部可在 Node 里跑
│   ├── corpus.js                    # 语料读取（索引 + 课内正文）
│   ├── table.js                     # 语料里的框线表格 → 行列（详情页画成真表格）
│   ├── store.js                     # 本机存储与设置
│   ├── review-models.js             # 四套复习算法
│   ├── scheduler.js                 # 每日计划与进度总览
│   ├── pinyin.js                    # 注音（多音字消歧，与网页版同口径）
│   ├── sfx.js                       # 音效：温习三态与答题（Web Audio 现场合成，零音频文件）
│   ├── entitlement.js / tiers.js    # 门禁：登录门（block）+ 三档分层
│   ├── author-index.js              # 作者索引：朝代归一 / 异名归一 / 名册构建
│   ├── tab-page.js                  # 跳 tab 页的唯一出口（navigateTo 去 tab 页静默失败）
│   ├── auth.js                      # 微信登录（含无后端时的降级）
│   ├── wire.js                      # 报文形状（本机 ↔ 服务端），见 § 二点五
│   ├── remote.js                    # 后端契约（同步 / 管理）
│   └── sync.js                      # 同步调度（启动 / 背完 / 手动）
├── pages/                           # 主包：四个 tab + 列表 + 详情（底栏五项，见 design-system「底栏」）
├── packages/                        # 分包：设置 / 大会 / 进度 / 管理 / 作者索引
│   └── <分包>/<页>/lib.js            # 只有本分包用的内核（出题 / 飞花令 / 管理数据层）
└── data/                            # 由 scripts/build-data.js 生成，不入库

scripts/
├── build-data.js                    # 语料编译（读 scripts/corpus/）
├── check.js                         # 离线自检
└── parity.js                        # 与网页版能力表逐项对照，见 § 三点五
```

`utils/` 只放**主包与多个分包共用**的模块：每个文件都要被入口链（页面 / 组件 / `app.js`）
引用到，只有单个分包用的内核放在那个分包的页目录里（`packages/<包>/<页>/lib.js`），
否则它会随主包下发却没有主包页面用它。这一条由 `scripts/check.js` 的可达性断言钉住。

`utils/` 里的模块**一律不碰 `wx` 之外的平台 API**，`wx` 只在 `store.js` 与 `auth.js` 里出现。
这样排期与算法可以在 Node 里直接验，不必开开发者工具。

## 二点二、掌握度：四套算法共用一把尺子

四套算法各自只定义**档位怎么走、下一次落哪天**，谁都没有定义「掌握到什么程度」。
这个词在界面上出现得比算法本身多（进度页的环与分布、每一行的百分比、背诵弹层的读数），
所以另有一条口径，写在 `utils/review-models.js`，不散在页面里：

| 数 | 定义 | 位置 |
|---|---|---|
| 档位 `level` | 0 – `LEVEL_MAX`（9）。四套算法连续答对都能走到 9，这是它们唯一共有的刻度 | `clampLevel()` |
| 掌握度 | `level / LEVEL_MAX`，向下取整成百分比；没学过的一律 0 | `mastery(rec)` |
| 已掌握 | 掌握度 ≥ `MASTERED_PERCENT`（80%，即第 8 格起） | `mastered(rec)` |
| 档位读数 | `已牢固` / `8 / 9` 这样的短串，给篇目身份行用 | `levelName(level)` |

`mastery()` 是唯一入口，界面与排期都调它 —— 自检里有一条断言不许
`components/`、`pages/`、`utils/scheduler.js` 里再出现 `/ 9` 这样的除法。

**自选集合不另立一套进度。** 一篇的进度记在篇目 id 上（`store.getRecord(id)`），
同一首既在课内又在自选里，就只算一份；集合的读数是用这把尺子把它的篇目逐条汇总。
汇总函数与课内那两份并列：`collectionProgress(c, opt)` 内部调 `overview()` / `dueList()`，
所以「已掌握」「平均掌握」「掌握度分布」「今日到期」在自选与课内是同一次计算。
进度页与自选管理页都只读这个函数的返回，不自己翻本机记录。

**画也只有一份。** `components/progress-view` 把一块「环 + 四数 / 七天日历 / 到期篇目与延后温习 /
五档分布」摊成组件，页传 `view` 进场：课内那页传 `courseView()`，自选那页对每个集合传
`collectionView(c, allPoems, getRecord)`（内部就是 `collectionProgress`）。组件只管画，
背诵弹层仍挂在页上，行上抛 `open` / `defer` 事件；读数与记录一条都不在组件里算。

## 二点五、报文一层：本机形状 ≠ 服务端形状

跨端同步最容易错的地方不是算法，是**字段名**。上一版把本机形状直接当报文发：

```
本机   { id, kind: "p", rec: {...}, at }
服务端 { id, payload: {...}, updatedAt }     ← api/_lib/core.js syncPushInner
本机   { id, kind: "r", book, at }           ← 一篇一行
服务端 { id: "reads:<行 id>", payload: { v, updatedAt, marks: {...} } }   ← 一集子一行
```

两边一个字段都对不上。而当时的自检问的是「本机发得出什么」：

```js
ok("打包含进度行", packed.rows.some((r) => r.kind === "p" && r.id === "probe-1"))
```

一路绿灯。也就是说：**接上后端那一刻，同步是坏的，而且报错会指向服务端。**
拉的那一头更安静 —— `pull()` 读的是 `data.rows`，服务端根本没有这个字段，
于是「同步成功但永远拉回 0 条」，界面上还写着「已同步」。

所以另起一层 `utils/wire.js`，只做一件事：本机形状 ↔ 服务端形状。
判据不靠文档推测，靠读仓库里那份服务端契约（`scripts/parity-web/`），并且**把这件事变成会红的检查**：

| 检查 | 判据出处 |
|---|---|
| 每条 rec 有非空 id、正数 `updatedAt`、`payload` 对象 | `syncPushInner` 的三条前置校验 |
| 进度行 payload 只带白名单字段 | `sanitizePayload` |
| 已读按集子成行、载荷是 `marks` | `sanitizeReads` + `readRowKeyOf` |
| 行 id 是 `poem_<book>_read_v1` | `js/sync-coverage.js` 与 `js/read-sync.js` |
| 加背 / 自选温习有打包 | `sanitizeDailyExtra` / `sanitizeCollections` |
| 拉回的行能落回本机 | `applyRecords` 往返 |

最强的一条是**把报文喂给真实的 sanitize 函数**（`scripts/check.js` §8.8）：
`require` 仓库里那份 `scripts/parity-web/core.js`，用它的
`sanitizePayload` / `sanitizeReads` / `sanitizeDailyExtra` / `sanitizeCollections`
过一遍我们发出去的数据，**问的是「有没有字段丢了」**而不是「字符串等不等」
—— 服务端会补齐 `deleted: 0` 这类 canonical 字段，那不算错。
那是服务端契约的**只读副本**，照原样摆着不跟着本仓库改 —— 界定了「报文该长什么样」，
所以它不该被顺手改成「这样就过了」。

三处具体修掉的错，各自都值得记一笔：

1. **进度行字段全错**：`kind/rec/at` → `payload/updatedAt`
2. **已读行 id 张冠李戴**：本机集子 id 与网页版的存储行 id 是两套命名
   （`poems` ↔ `poem_poems_read_v1`，`dwang` ↔ `poem_dwang_cn_read_v1`），
   写错一个字服务端就**静默丢掉这一行**，不报错
3. **加背与自选温习压根没打包**：服务端那两行永远收不到，换台机器这两样就没了

（同步这一层管的是「加背这份数据送得出去、拉得回来」。
它**怎么产生**是另一件事：直到 Issue #42 才补上界面 ——
在那之前 `setDailyExtra()` 全项目只被这里的回写调过一次，
本机永远生不出加背来。所以「能收到」不等于「有人在产生」，
两件事得分开验。）

## 二点七、与网页版的对照怎么守

Issue #12 的原话是「看看有没有缺失的」。这件事靠人逐页对一定会漏，
而且漏掉的恰好是「我以为有、其实没有」的那几项 —— 最该被发现的。

所以对照本身也变成可执行的一件事：

- **`docs/parity.md`** 是人看的：六张表逐条列两端，四类记号
  （✅ 两端都有 / ⚠️ 换个做法 / ⏸️ 没做 / ❌ 是缺口）。它有一条硬纪律 ——
  **表里不许出现「差不多了」这种没判据的话**，要么写在表里，要么不写。
- **`docs/todo.md`** 是「未做」的唯一出处，另附一张「明确不做」的表。
  把「不做」写成「以后做」，就是给自己留一句假话。
- **`scripts/parity.js`** 是机器守的：网页版 `js/entitlement.js` 的每个能力键，
  都要在小程序端落成「已实现的能力键 / 页面路由 / 文件」，
  或者落成 `docs/todo.md` 里的一条（`kind: "none"` 时必须能追到那个编号）。
  漏一项、或者 `todo.md` 里那条被删了，**当场报红**。

拿不到网页版源码时（本地没 clone）它**跳过并出声**，不静默放行 ——
「检查没跑」和「检查通过」是两件事。

## 二点八、排行榜：一次交卷一行，档位在写入时定死

排行榜（`packages/ranking`）是**网页版没有**的那一层，所以它的口径只能自己定，
也就只能靠自检钉住。

**一行 = 一次交卷**（`score_records`），不存昵称。榜单上的名字是读的时候从
`accounts.nickname` 现取的 —— 改名一次全站生效，历史行不用回灌。
打码同理只做一次：首末字留着，中间两个星号（`1 字 → 首字 + **`，
`2 字及以上 → 首 + ** + 末`），服务端与端上各有一份实现，口径写在同一处断言里；
端上把服务端给的名字再过一遍同一个函数（`maskRow`），它认得出已打码的形状，
所以不会把 `张**三` 再打成 `张***三`。

**昵称的敏感词拦两道。** `api/_lib/nick-guard.js` 把全角折成半角、剥掉符号与空白
再比对一份词表（辱骂 / 色情 / 广告导流 / 违禁交易 / 涉政 / 冒充官方）。
`nicknameSet` 先过它，脏名字进不了库（`E_NICK_BLOCKED`，端上退回改之前那个名字并说一句）；
`boardMaskNick` 再过一次 —— 口径落地之前已经存进去的脏名字，在榜上退回「诗友 + 尾号」。
只拦写入是不够的：改词表之前的历史数据会一直摆着。

**分档在写入时定死，不跟着人走。** 成绩行记下当时的学段 / 年级 / 学期，
用户之后在温习设置里改成别的年级，旧成绩仍留在原来那一档 —— 否则一个人
换年级会把整段历史挪到另一个榜上，榜单就没有「同时同届」可言。

- 档：「全部学段」+ 小学（1-6）/ 初中（7-9）/ 高中（10-12）。学段内再按年级、
  上下册收窄；「全部学段」不带年级与册次，端上也不留这两种档位（`queryOf` 剔除
  本学段之外的年级、以及没选年级时的册次）
- 期限：今日 / 本周（周一起）/ 本月 / 今年，`from` 由服务端按自然周期算，端上不自己算时间。
  **窗口一律按东八区零点切**（`BOARD_TZ_OFFSET_MS` 写死 +8，不读进程的 `TZ`）：
  容器跑在 UTC 时 `setHours(0,0,0,0)` 落的是早上 8 点，换一台机器就换一套日界
- 一人一行：同一个人在同一档同一窗口里只算他最好的一次
  （分数 → 总分 → 用时 → 先到），名次按这个顺序排
- 领奖台只认前三，第四名起进列表；不够三行时那几格写「虚位」，不出假名次
- 只列前 100 名（`BOARD_SIZES = [100]`，端上 `ranking.DEFAULT_SIZE` 同值）。
  100 名之外的自己单给一行，名次照实，列在 100 名下面，中间隔一句「还有多少位」

**看榜与参与是两个开关。** 榜本身默认开着，没有后台拨杆：`app_settings` 的
`ranking:<game>` 缺行按**开**算，只有显式写 `0` 才算关，要关只能直接改库里那一行，
`boardGate` 会挡住列表（提交仍照收）。

看榜与参与都随 `league` 这一项能力门禁走（Max 起，`utils/league.js` 是唯一判据：
`canJoin` 管看榜、`optedIn` 管上报、`canSwitch` 管设置里那颗开关）。
Free / Pro 打开排行榜页看到的是「Max 起可用」，设置里那颗开关是灰的。

参与与否由用户在「设置 · 综合」自己定，落在本机设置的 `leagueBoard` 键
（随账号同步，服务端 `SETTINGS_KEYS` 里有这一项）。关掉之后
`ranking-submit.submitPlay` 直接在端上返回，请求根本不发 —— 隐私政策里
「关掉这个开关就不再上报」这句说的是这件事，别把它又挪到服务端去拦。
`optedIn` 读的是 `league.optedIn`，档位与开关在同一处判定，不各写一份。

接口一律 `POST /api/ranking` + `op`（`visible` / `list` / `submit`），
与 `exam/records` 那种「一个口几件事」同形，不另立一套风格。
成绩只从考试交卷与飞花令结束那一轮上报。关着的时候照收不拒
（`boardSubmit` 走 `boardGate(deps, input, false)`），只是不展示 ——
先拦后收的话，开了之后榜上仍然一片空白，管理员得等下一批人来考。

## 三、数据存哪：冷热分离，正文一律上云

这是 Issue 里点名要回答的问题。判断依据是**实测体积**，不是感觉：

| 项 | 实测 |
|---|---|
| 课内正文（251 条，`data/course.js`） | **235 KB** |
| 集子目录（10 部 1476 条，`data/books/catalogs.js`） | 45 KB |
| 全部索引（不含正文，课内那一部一张合表） | 18 KB |
| 读音表（`data/pinyin-table.js`） | 62 KB |
| 代码与样式 | 104 KB |
| 小程序主包上限 / 总包上限 | 2 MB / 20 MB |

结论：**课内正文进包，其余一律不进。**

主包实测体积随构建变化，取数入口是 `scripts/check.js` 那条「主包在 2MB 内」的断言输出
（它按 `app.json` 的分包表减掉分包，量的是主包本身）。
这笔账值得花，因为它买的是**首页「每日温习」与详情页不必等网络** —— 这两个页面是
每天真正被打开的地方，用 235 KB 换掉一次列表到正文的往返，是这轮唯一划算的体积支出。

于是按两层落：

1. **包内（免网络）**
   - 集子索引 `data/books/index.js`（篇名/作者/朝代/出处/分组，不含正文）
   - **课内 251 首的正文、译文与生字生词注释 `data/course.js`**
     （注释语料在 `scripts/corpus/data/gloss-notes.js`，一篇一组「词、释义」，
     只收课内这 251 篇；`utils/gloss.js` 把组按每行两条排给模板）
   - 集子表 `data/books/books.js`、读音表 `data/pinyin-table.js`、名录 `data/roster.js`、
     作者索引里只在集子目录出现的那些名字 `data/roster-extra.js`
   - 索引里**不带正文**，这是主包能压住的前提

   ⚠️ 落盘的索引是**薄索引**：一行只有「id / 篇名 / 作者 / 朝代 / 出处 / 分组 /
   选本 / 年级学期 / 异名」这些列表页真要用的字段，**不带正文与译文**，也不带
   集子 id、集子名、`hasT` 与空字段。`utils/corpus.js` 的 `ofBook()` 读进来时
   按集子表把这几样填回去，语料的每一层都走 `ofBook()`（列表 / 检索 / 阅读 /
   作者索引 / 试题），外面看到的形状与从前一致。

   ⚠️ 索引**只装课内那一部**：`books` 与 `rows` 都只有 `poems` 一张表。

2. **集子目录另起一份**：`data/books/catalogs.js` 装十部课外集子的
   「书名 + 标题 + 作者或出处」，一行三个短字段，作者与出处各自去重成字典。
   条目 id 是 `<书名>-<次序>`，源 id 由 `data/site-catalogs.js` 里那部书的 `src`
   加同一次序拼成（`tangshi300-11`），按部存前缀、读时拼，不逐条落盘。集子表 `books.js`
   带这十部的名字与单位（合计 11 条），列表页与入口卡要用。

3. **不在包里的**：十部集子的正文，以及课内那 251 首之外的一切正文。
   目录里没有源 id 的条目取不到正文，界面按「没取到」处理并给一次重试 ——
   见 [`poem-source.md`](poem-source.md)。

**为什么课内不跟着走分包**：分包上限虽是 2 MB，但分包要**先进去才下载**，
而「每日温习」在首页上就要拿正文出题。把课内放进分包，等于首页出题前先等一次分包下载 ——
那正是要避开的卡顿，所以它走主包。

**边界写死在自检里**：`scripts/check.js` 会验「包内正文就是课内那 251 条」「目录只装书名标题作者、
正文一个字都不在包里」「目录里每一条都有源 id」，并给课内正文单列 400 KB 预算 ——
超了就得重新算账，不是悄悄涨上去。

### 以上是「内容」。账号那一份另有一层，见 [`data-backend.md`](data-backend.md)

内容走文件（全在包内），**账号走数据库** —— 两件事的归属完全不同，
混成一件事就会得出「换掉数据库要重写一遍」这个错结论。账号那一层：

```
小程序 → wx.cloud.callContainer（微信内网，免域名免备案）
        → 云托管容器（我们的 Dockerfile，我们的 api/ 代码）
        → 服务端存储层（腾讯云 MySQL；**一个接口，两个实现**）
```

**存储层是一个已经把接口定死的插槽，不是长在代码里的东西**：`store.js` 里
`api` 对象那组 `getX / putX / listX` 就是契约，`getStore()` 一句
`cfg.hasMysql() ? mysqlStore(cfg) : memoryStore()` 就是全部的分派。
线上那份实现就在本仓库（`deploy/store-mysql.js` + `deploy/sql/mysql-schema.sql`），
**路由层与小程序端一个字都不动**。

三件事（数据在哪 / 后端依赖怎么解 / 跨仓库依赖怎么撤的）
逐条写在 [`data-backend.md`](data-backend.md)：存储层那一个接口两个实现、
腾讯云 MySQL 的三处坑、以及语料搬进仓库这件事。
**这一节不重复它** —— 一份口径只写一处，抄一份就是给自己留一面会漂的镜子。


## 四、谁能用：一道门 + 三档

Issue 里定的边界，一句话：**能进门，不能白用。**

```js
// utils/gate.js —— 能不能进
{ browse-home, browse-grade, login, about }   // 未登录只给这四件事
// utils/entitlement.js —— 进来之后能给到哪一档
free  → 每日温习 / 诗词漫读 / 注音辅助 / 艾宾浩斯 / 进度总览 / 全站搜索 / 同步进度
pro   → 新增温习 / 莱特纳盒 / SM-2 / 题库 / 自选温习   （管理员发放）
max   → FSRS / 飞花令 / 考试                        （管理员发放）
```

对比表里只有这三档：**未登录一条能力也拿不到**。表的行名与格子文案是权限对比表自己的写法：
题库 / 飞花令 / 考试在那一列写作「古诗文大会·题库」「古诗文大会·飞花令」「古诗文大会·考试」，
别处（大会首页入口卡、页面标题、提示语）仍用原名。带英文名的四项在表里中文一行、英文一行，
括号不写；自选温习的额度不进格子，落在图标下方那行小字（`1 个集合` / `200 个集合`）。
登录是拿到 free 的前提，不是第四个档位 —— 界面上不出现「登录就有」这个分段
（2026-10-16 起原先那一档已并入 free，见 `docs/parity.md`）。

**同步与网页版故意不同档**：网页版的云同步是 `pro`
（`sync.multiDevice`），小程序端 2026-10-04 起一登录就有。
这条差异写死在自检里（`check.js` 的 V34），免得下一个人看两边表不一样顺手改回去。

未登录能开首页、能看到一年级上下册的**目录**（篇名、朝代、作者），
点任意一首弹一句人话 + 一个登录按钮。这是 Issue 原话的直接落点：
**「不登录用户只能浏览首页，首页默认列出一年级诗词，无法点击」**。

### 这道门在代码里长什么样

门与档位都在 `utils/entitlement.js`，**一个入口**：`can()` / `decide()`。
界面不许自己拼「能不能用」，措辞也归 `hint()` —— 散在十几处早晚不一致。

| 函数 | 管什么 |
|---|---|
| `decide(name)` / `can(name)` | 这条能力此刻能不能用（未登录一律 false，`home.browse` 除外） |
| `block(name, { page })` | 页面上那道门：放行返回 true；挡下弹「去登录」并调 `page.onLoginGate()` |
| `hint(name)` | 「为什么不能用」那一句话（未登录统一是「登录可用」） |
| `guestScope()` | 游客首页的范围：一年级本册、只读 |
| `CAN_GUEST` | 免登录清单，**有且只有 `home.browse` 一项**（自检按它断言） |

游客首页**不读用户设置**，强制走 `guestScope()`，进度环与「已读」一律归零 ——
不拿本机别人的进度充数。其余页面各自贴一遍 `block()`：分享卡片与深链能绕过
首页直达详情页，没有哪个入口是靠「用户不会那么点」守住的。

### 为什么不做「打开即强制登录」

因为技术上写不出来。`wx.login` 是静默的 —— 它只换一个临时 code，
用户看不见、也不需要点；而 `wx.getUserProfile` / `getPhoneNumber` 这类
要用户点头的接口，**必须由用户手势触发**，没有任何 API 能在启动时弹一个授权框。

所以「要求登录」在小程序里只有一种写法：进门容易、用起来要求登录。
这也正是 Issue 那句话的意思，不是妥协。

「用起来要求登录」落到底栏上，就是**课外 / 搜索两项在未登录时不渲染门禁页**，
点了直接切到「我的」——那一屏有整块的登录按钮。比留一屏只有一个按钮的
`lock-card` 好看，也少一次返回。

### 档位怎么来：虚拟支付（道具直购）+ 管理员分配

`pro` / `max` 有两个来源：用户在定价页购买，或管理员在用户列表里分配。
两者写的是同一对字段 `plan` / `plan_until`，到期由 `planTier()` 即刻按 free 算。

- 一个「档位 × 周期」对应 MP 后台的一个道具；价格以服务端价目表为准，
  生效道具由管理员在「支付与价格」页选择，促销价 = 另建的道具。
- 流程：`POST /api/pay/order`（服务端签名）→ `wx.requestVirtualPayment` →
  发货推送 `/api/pay/notify`（主）/ `POST /api/pay/confirm` 查单（兜底）。
  发货以 `pay_orders.status` 的条件更新为准，重复推送只顺延一次；续订在原到期日后顺延。
- 订单与凭据落 `pay_orders`；小程序里没有退款入口，退款在 MP 后台操作，
  `xpay_refund_notify` 回收对应时长。
- 发货推送的消息格式要选 JSON，令牌配 `WX_PAY_PUSH_TOKEN`。

### 同步跟着账号走：一份清单，两条边界（2026-10-04）

用户的原话是：

> 「我现在是微信小程序项目，不是之前的 web 应用，需要修改，同步功能只要用户登录
> 就全部提供，确保用户数据不丢失，背诵进度换设备也能得到。请重新设计」

于是这件事有了一个**逐项能对的清单**（此前只有半份，见下）：

| 跟账号走（登录就有） | 存在哪 | 换台手机 |
|---|---|---|
| 身份与档位 | 服务端 | ✅ 认回来 |
| 温习进度（每篇一行） | 云 | ✅ |
| 已读标记（每集子一行） | 云 | ✅ |
| 新增温习（跨 0 点不搬） | 云 | ✅ |
| 自选温习（集子一行，含名字 / 每日首数 / 篇目） | 云 | ✅ |
| **全部设置**（年级 / 册次 / 范围 / 首数 / 算法 / 主题 / 注音 / 字号 / 对齐 / 自动翻篇） | 云 | ✅（2026-10-04 补） |
| 昵称 | 云（`accounts.nickname`） | ✅ |
| 服务端存下的头像 | 云（`avatars` 表） | ✅ 登录后按 `/api/avatar/<uid>` 取回 |
| 孩子头像 | 只在本机 | ❌ **刻意的**：它只有微信一个来源且不上传（Issue #111），换台手机就是没有 |
| 音效开关 | 只在本机 | ❌ **故意的**：它取决于这台机器的扬声器 |

两条边界：

1. **跟人走 vs 跟设备走**，判据不是「这个设置重不重要」，而是
   **「它在另一台手机上还成不成立」**。落在 `store.js` 的
   `DEFAULTS` / `DEVICE_DEFAULTS` 两份表里，写设置的页面只写一个 key，
   分流收在 `saveSettings()` 一处 —— 散在十几个调用点上，早晚有一处漏。
2. **整份快照，不逐键合并**。设置是「一台机器上的全部选择」，
   逐键合并会造出「年级是我的、算法是他的」这种谁都没选过的中间态。

上一版为什么不是这样：`settings` **压根没打包**，而设置页改完
**连 `sync.markDirty()` 都没调** —— 那不是「同步失败」，是「从来没进过同步」。
现在每一个会改到同步数据的入口都挂了记账（自检 V34 第 7 条逐个点名）。

**头像与昵称为什么不在这一列里**：头像只有微信一个来源且**不上传**
（`open-type="chooseAvatar"` 给回的是 `wxfile://…` 临时路径，见
[`design-system.md`](design-system.md)「头像」一节、Issue #111），
所以换台手机就是没有；昵称走服务端的 `accounts.nickname` —— 用户在小程序里一改
（`onNickname`）就走 `PATCH /api/me` 落到 `accounts.nickname`，登录与刷新时随会话下发，
不占同步这条链（进度那条报文从来不打包昵称）。

⚠️ 服务端那一半**必须一起做**：`sanitizePayload` 对认不出的行 id
一律返回 `{}`，所以 `settings:v1` 不加白名单就会被**静默清空** ——
表现是「同步成功但什么也没发生」。详见
[`wx-login-server.md`](wx-login-server.md#-服务端必须给这两行加白名单否则数据会被静默清空)。

### 三条口径

1. **客户端的档位不是安全边界**。改本机存储就能提档，所以它管的只是
   「界面给谁看」；真正扣配额必须在服务端做。
2. **档位只有一个来源：管理员**。这一版拆掉了上一版的两条口子 ——
   一条叫「本机宿主」（未登录时把所有人当 `max`，理由是「本机数据只属于本机」，
   结果未登录反而拿得比 `pro` 多），另一条叫「改本机层级」（早先名录卡上一张卡片，
   点两下就升到 max）。两条都在，`can()` 里那三档差别就只是装饰。
   `entitlement.status()` 现在只认三样：服务端下发的档位、授权码、其余按免费。
   本机自己写的档位**无签名，一律降级**（`blocked === "unsigned"`）。
3. **名录不许进代码库**。名单里是别人的账号标识。走环境变量 `POEM_ROSTER` 导入，
   构建产物 `data/roster.js` 落在 `.gitignore` 里。没有名单就不生成，
   用户列表页如实显示「名录未导入」，不凭空编人。

> 第 2 条有出处。网页版的 `docs/auth-design.md` §4.4（Issue #276）已经删掉了
> 「首次打开这个浏览器就是管理员」那种兜底，理由写得直白：
> **「清一次浏览器存储就能当管理员的所谓权限，不是权限。」**
> 「本机宿主」和它是同一类东西，只是换了个方向 —— 不是白送管理员，是白送 max。

### 权限页与用户列表做什么

三块页：**用户权限**（`packages/mine/tier`，从「我的 → 用户权限」进）把能力对照表
摆一页，给人自己看；**后台管理**（`packages/admin/index`）是 `owner` / `admin`
的入口，页上只有一张「用户列表」卡；**用户列表**（`packages/users/index`）看别人。

那一块表是 `components/tier-view`，只有用户权限页写一个 `<tier-view />`。

| 栏 | 谁能看 | 内容 |
|---|---|---|
| 我的权限 | 所有人 | 当前档位与能力计数，只读；未登录按 Free 算，卡上说清这一句 |
| 权限对比 | 所有人 | 一张表四列：能力 ｜ Free ｜ Pro ｜ Max。列头由 `entitlement.compareCols()` 出，行由 `compareRows()` 一次铺满能力表；格子由 `cellFor()` 从能力表的档位算出来，不许手写，只有「有没有」两态（对勾 / 叉，见 `utils/icons.js`），有量的项（自选温习）才另写额度，额度写在图标下方那行小字；`compareSummary()` 另给每档合计。三列等分整宽，**整表铺在页面上、卡片里不滚**，当前档位列标「现在」 |

这两张卡讲的正是「登录能多拿什么」，未登录也看得到 —— 顶端不挡 `lock-card`。
入口是「我的 → 用户权限」那一行（头像右边那枚档位胶囊也到这一页），登录与否都在。

门禁的两种对话框都由 `utils/entitlement.js` 出（`block()` / `gateTier()`）：
登录那道是「登录 / 取消」，档位那道是「升级 / 取消」，确认后走页面自己的
`onLoginGate` / `onTierGate`。`onTierGate` 一律落到开通会员页
（`packages/mine/pricing`，通道是 `entitlement.openPricing()`），页面不另写文案。

版式**照网页版 `/plans/`**：列头就是档位名，三档各占等宽、功能名一栏占左约四成，
表格跟着页面滚。这三条都由 `check.js` 钉着 —— 退回「三列挤在右侧、卡片里定高滚」
会红。

名录只有一处入口：后台管理页那张卡（登录后显隐），不按 `owner` / `admin` 分叉。

`packages/users/index` 只管名录：每人一行，行首一枚序号胶囊（末位的号就是用户总数），
接着昵称与 uid，右侧是档位与「改档」按钮，按注册时间倒序；
`owner` / `admin` 才有那一枚改档按钮，其余人一行「只读」。
改角色**不在这页做** —— 授权走 `OWNER_EMAILS`，名录里摆一枚「角色」只会误导。

### 意见反馈（Issue #520）

用户入口只有一条：**设置 → 关于 → 意见建议**（`packages/settings/about`，
`packages/feedback/index`）。管理员入口是**后台管理 → 用户反馈**
（`packages/admin/feedback/index`，详情在 `packages/admin/feedback/detail/detail`）。

反馈只认登录身份：三条用户路径（建 / 读 / 跟帖）都以 `uid` 认人，
没有会话回 `401 E_NO_SESSION`。页面进来先过 `gate.open`，登录流程走完再画。
限流也按 `uid`（`cfg.rate.uid`），不按设备号：拿设备当桶等于删掉限流。
两页共用 `utils/feedback-api.js`
（类别 / 状态 / 处理方式三张表 + 校验 + 装饰）与 `utils/admin-feedback.js`
（分组与回复），不在页面里各抄一遍名单。

| 维度 | 取值 | 谁定 |
|---|---|---|
| 类别 | Bug 反馈 / 内容纠错 / 功能建议 / 体验优化 / 篇目推荐 / 性能问题 / 账号问题 / 虚拟支付 / 其他 | 用户提交时选 |
| 处理结果 | 未处理 `open` / 处理中 `replied` / 已处理 `closed` | 管理员 |
| 处理方式 | 待定 / 已采纳 / 排期中 / 不采纳 / 重复 | 管理员 |

几件事落在服务端，不在客户端：

1. **重复提交只落一条**。`feedbackCreate` 按「谁 + 类别 + 标题 + 正文」算一枚
   `sha256`，与这位用户一分钟内的最近五条比，撞上就不再写行，回 `duplicate: true`。
   这枚哈希**只在内存里比**，不入库 —— 线上那张表没有 `dedupe_hash` 这一列
   （`deploy/sql/mysql-schema.sql` 里也没有），带上它就是整条写不进去。
   页面上的按钮另加一次 `submitting` 锁 —— 那是手感，不是判据。
   类别只认那一张表，认不出的回 `400 E_KIND`，不改成「其他」落库。
2. **能改哪一条由服务端判**。用户那条路径只认自己的 `uid`；
   管理员那条路径先认角色（`isAdminRole`），别的人来了回 403。
   客户端 `canWrite` 只管「界面给谁看」。
3. **用户跟进会把这条打回未处理**（只对 `closed` 生效）。`feedbackComment`
   写给用户的那条路只动 `status` 与 `updated_at`，不碰类别与其他列 ——
   管理员正在处理的那条，不该因为用户补一句就换了类型。
4. **删除只归管理员**。用户撤不回自己提的那一条，也删不掉自己跟的那几句：
   `/api/feedback` 只认建 / 读 / `op: "comment"`，页面不摆删除入口，
   服务端下发的字段里也没有 `canDelete`。管理员删得掉整条与单段讨论，走
   `/api/admin/feedback` 的 `op: "delete"`（带 `tid` 删整条并级联沟通记录，
   带 `cid` 只删那一段），先认角色，其余人回 403；不认的 op 回 `400 E_BAD_OP`。
   入口在后台列表行内（点「删除」或长按）与详情页各一处。

后台列表**按处理结果分三张卡**（未处理 / 处理中 / 已处理），组内按创建时间倒序；
卡片上是主题、用户名、创建时间与最后处理时间。点进详情才带上处理意见、
处理方式与全部沟通记录 —— 列表那一路不拉评论。

`feedback_threads` 加了两列：`title`（标题）与 `resolution`（处理方式），
建表语句在 `deploy/sql/mysql-schema.sql`，线上库照那一份补
（`CREATE TABLE IF NOT EXISTS` 不会改已有表，得单独 `ALTER TABLE ... ADD COLUMN`）。

`dedupe_hash` **不落库**：线上那张表不一定有这一列，带上它就是整条写不进去
（`Unknown column`），而去重本来就是应用层这六十秒的事。建表语句里也不再列它。

后端地址与云调用两栏**不在界面上**：两个都是运维配置，不该给普通用户。
值由部署方写在 `miniprogram/utils/server.js`（构建期由密钥仓库
`CLOUD_ENV` / `CLOUD_SERVICE` 覆写），随包走。要换后端就改代码库里那份
（`baseUrl` 同理），不走界面。

改档**只走服务端**（`POST /api/admin/grant`），没有「改本机档位」这条路。
后端没就绪时如实说「改不了」，不给假成功 —— 与全文检索、同步同一套准则。

角色分 `owner` / `admin` / `user`，与网页版一致：`admin` 能发档位、看名录，
`owner` 还能改别人的角色。改角色只对 `owner` 开放（服务端也会再挡一层），
但小程序界面里没有这个入口 —— 授权不在名录里做。

### 作者索引页做什么

`packages/authors/index` 一块页，**两层都在这一页里**（不新开页面）：

| 层 | 内容 |
|---|---|
| ① 名册 | 朝代表（点一格就地滚到那一段）+ 一段一段的作者（人数与段数以 `utils/author-index.js` 现算为准）|
| ② 一位作者的作品 | 分组标题 + 行 + 已读标记 + 未读筛选 —— 与列表页同一套长相 |

**为什么不分成两个页面**：小程序的「返回」是页面栈给的，而用户要的是
**一层退一层**（详情 → 作品列表 → 名册）。分成两页的话，名册自己又是从
搜索页进来的 —— 一共三层栈，返回手势要点三次，中间任何一层被系统回收
（微信后台超过 5 个页面就开始回收），用户就被弹回搜索页了。

**「下一篇只在这一位作者里走」怎么落**：从作者索引进详情页时 URL 带
`?from=<作者名>`，reader 认它 —— 评完分自动跳的那一首在这位作者名下找，
走到头退回他的作品列表。这段跨搜索页 / 作者索引 / reader 三个文件，
静态扫描看不出来，所以自检 V41 **真跑阅读页**验（连翻五首不跨作者、
不跳进词条）。见 `README.md`「作者索引」一节。

**名册现算，不进包**：十部集子的索引本来就在包里，名册只是按作者重摆
一遍。比多背一份静态表划算，也不会跟语料错开版本。
两张归并表（`ERAS` / `ALIAS`）与网页版 `data/author-index.js` 同口径，
V40 拿两端逐段比。

**名册收谁**：课内那 251 首里的作者（`items` 就是他的作品，点开直接列），
加上 `data/roster-extra.js` 里的人 —— 十部集子目录里出现过的每一位，
包里没有作品行。这些人在名册上照常占一格（名字 + 朝代），点开时按名字
现问诗词漫读：先 `GET /authors` 找 id，再 `GET /poems?author=<id>` 一页 100 首。

作者一格填的不是人的（书名与带编者 / 译者的署名，例如《公羊传》《礼记·檀弓》
《国语》《战国策》、`戴圣编`、`求那毗地译`）不进名册：两边各有一张同名表
（`data/author-index.js` 的 `SKIP`、`utils/author-index.js` 的 `COLLECTIVE`），
自检拿名册整体验一遍。这些条在各自集子的列表页照旧读得到。

**一位作者一个朝代**：目录行本身不带朝代，作者与朝代的对应关系在语料里
定死，编译期落成「名字 → { 朝代, 段 }」，一位一条：

- `scripts/corpus/data/catalog-dynasty.js`：按集子列作者朝代（照录选本与
  作者小传；`docs/parity.md` 记着这条口径）；
- `scripts/corpus/data/catalog-fix.js`：跨集子重名的按作者一人一行定一次 ——
  《昭明文选》题「宋玉」、别处题「屈原」的同一批人，不能因为哪部集子先编译
  就落到哪一朝。这一层优先于上一条；
- 两处都没有的（只在目录里出现、别的集子也没收过的名字），取
  `scripts/corpus/data/site-roster.js` 那一列自带朝代。

三层的顺序是「按集子 → 按作者 → 自带」。目录里既查不到、三处都没写的，
构建直接报错，不做「落到其他」的兜底 —— 那等于把一个人塞进错的一段。

**作者搜索**：页顶一格，只匹作者名，不匹篇名。先出包内名册的命中（前缀
优先，其次名字短的），停手 0.6 秒后再问 `GET /poems/search?type=author`，
把全库那 13700 位里的命中补在下面。包内有的名字不重复出；远端那几位只
带得到朝代与名字，点开照上面那条现问作品。

**一万多位作者的边界**：全库作者不整表进包，也不整表拉 —— 一次冷启动翻
137 页换一份长名单，不值。名册给人翻，搜索给人找。

## 五、账号体系：微信登录

网页版是「邮箱 + 密码 / 随机码」两条路签同一枚会话。小程序端整块换掉：

```
wx.login() 拿 code
  → 自家后端 code2Session 换 openid / unionid
  → 后端下发 access（7 天）+ refresh（30 天）双 token + 档位 + 角色
  → 客户端只存 token，不落 openid 明文
```

要补的东西（路由、报文、建表、部署顺序）单独写在 **[`docs/wx-login-server.md`](wx-login-server.md)** ——
那是接手的人唯一需要读的一份。

**接口契约**（`utils/remote.js` 里的 `PATHS`，两边都在这一份里）：

| 路径 | 方法 | 谁写的 | 说明 |
|---|---|---|---|
| `/api/wx/login` | POST | 本仓库 `api/` | `{ code, device }` → `{ accessToken, refreshToken, expiresIn, tier, role, caps, nickname, userId }`（`avatarUrl` 不再回值：头像只落本机，见 Issue #111） |
| `/api/wx/refresh` | POST | 本仓库 `api/` | `{ refreshToken }` → 同上 |
| `/api/me` | GET | 本仓库 `api/` | 认回会话（本机没 token 时用它） |
| `/api/me` | PATCH | 本仓库 `api/` | `{ nickname }` → `{ nickname, account }`。改昵称走这条，不占同步链 |
| `/api/sync/pull` `/api/sync/push` | POST | 本仓库 `api/` | 含条件 upsert 那套时间戳规则 |
| `/api/avatar` | POST / DELETE | 本仓库 `api/` | 服务端头像（落 `avatars` 表，≤1MB 的 PNG / JPEG） |
| `/api/avatar/<uid>` | GET | 本仓库 `api/` | 取回那张头像；带 ETag，`If-None-Match` 对上回 304 |
| `/api/admin/accounts` | POST | 本仓库 `api/` | 名录 |
| `/api/admin/grant` | POST/DELETE | 本仓库 `api/` | 改档 / 回收 |
| `/api/admin/role` | POST | 本仓库 `api/` | 改角色（仅 owner） |
| `/api/feedback` | GET / POST | 本仓库 `api/` | 自己的意见反馈：`GET` 列自己的（含沟通记录），`POST` 新建 / `op: "comment"` 追加一句 |
| `/api/admin/feedback` | POST | 本仓库 `api/` | `op: "list"` 全量（带各状态计数）/ `"thread"` 单条 / `"reply"` 回复并改处理结果与处理方式 / `"status"` 只改状态与方式 / `"delete"` 删整条或单段讨论 |

**登录这道门不依赖后端**：`utils/auth.js` 在服务器没接上时落一个本机身份，
门一样开、登录照旧能点，只是不同步。别把「没后端」变成新的一道墙 ——
§ 一点五 那条「通道没就绪就如实说」说的是**通道**（同步 / 检索），
不是**门**。两件事混起来，后端一没配全站就点不动了。
**同步与管理沿用同一套路径与报文**：小程序端另起一套等于同一份进度走两条入库逻辑，
迟早有一边先写出「旧数据覆盖新数据」。代码在本仓库 `api/` 里，
线上那次实现落在 `deploy/store-mysql.js`。微信登录那一层必须在服务端做
`code2Session` —— 因为 `appsecret` 不能进小程序包。

第二条要说清的是**降级后的样子变了**。上一版写的是「后端没就绪时降级为本机身份，
功能一个不少」——现在功能不是「一个不少」了：

- **本机身份照旧落地**（`logged: true`），能标记「登录过」
- **档位一律按 `free`**，不假装拿到了服务端授权 —— 没签名的高档位等于白送
- 所以后端没就绪时，登录用户拿到的是 free 那一档：每日温习、诗词漫读、注音、
  艾宾浩斯、进度、搜索、同步（同步这一项「拿得到入口」但「没有通道」，
  界面如实写「后端未就绪 · 已攒 N 条」）。
  `pro` / `max` 要等后端就绪后由管理员发

边界沿用网页版那几条：

- **不静默抓取** —— 头像走 `open-type="chooseAvatar"`、昵称走 `wx.showModal({ editable: true })`
  里键盘上方那一格（`type="nickname"` 放进隐藏层要用户先点一次键盘才回值，Issue #498），都由用户主动给；
  头像**只落本机、不上传**（Issue #111：不为它养一份对象存储）
- **提供注销入口** —— 微信强制要求。「我的 → 设置 → 清空数据」删本机与云端记录
  （清空落成删除标记推上去，见 `utils/wire.js` 的 `clearRecords`），「辞别」（退出登录）断会话。
  自选集合里指向已不在语料中的篇目一并剔掉（`utils/collections.js` 的 `prune`），
  否则集子留着一条点进去是空壳的条目
- **隐私政策** —— 「我的 → 关于 → 隐私政策」一页（`packages/settings/privacy/`），
  未成年人那一条写在页面里，不另立文件。头像只在本机、昵称会进榜单，这两件事
  在「会不会给别人」一节里分开写：榜上只给打码后的昵称与成绩，不给头像
- **客户端不存管理员密钥** —— 能不能改别人由服务端的角色判。网页版后台要密钥是因为
  它跑在浏览器里打的是一套运维接口；小程序端复用同一套会话即够，少一个泄漏面

## 五点五、出网两条路：一张名单，和一个免掉它的办法

Issue #1 问：「小程序怎么还要域名？做什么用的，怎么申请。」

### 那张名单

小程序跑在微信客户端里，`wx.request` 的域名必须事先在微信后台登记，否则真机上一律报
`url not in domain list`（开发者工具里勾了「不校验合法域名」才看着像能跑）。
一张名单分四类，各管各的流量，互不通用：

| 名单 | 管什么 API | 本项目用不用 |
|---|---|---|
| request 合法域名 | `wx.request` / `wx.uploadFile` | 云调用时用不上 |
| socket 合法域名 | `wx.connectSocket` | 不用 |
| uploadFile / downloadFile 合法域名 | `wx.downloadFile` | 暂不用 |
| 业务域名 | web-view 打开的网页 | 不用 |

名字里带「域名」却只管到**端口上的 host**：`https://a.com` 与 `https://a.com:8443` 算两个，
`a.com` 与 `www.a.com` 算两个。漏掉的那个不是偶尔失败，是每次都失败。

### 要它干嘛

只有三条路要出网，都写在 `utils/remote.js` 的 `PATHS` 里：

| 接口 | 干什么 | 为什么非上云不可 |
|---|---|---|
| `/api/wx/login` `/api/wx/refresh` | `code2Session` 换 openid，下发双 token | `appsecret` 不能进小程序包，只能服务端换 |
| `/api/sync/pull` `/push` | 进度同步 | 换机不丢进度；离线队列攒着，联网一次推 |
| `/api/admin/*` | 名录 / 发档 / 改角色 | 权限判据必须在服务端 |

反过来说，**没有域名这个小程序也不是不能跑**：首页目录、课内 251 首、复习算法、注音、
进度与排期全在本机，断网照背，丢的恰好是上面那三样。所以降级策略是「如实说没就绪」。

### 两条路

| | `wx.request` + 域名 | `wx.cloud.callContainer` |
|---|---|---|
| 域名 / 证书 / 备案 | 要（备案 3–20 个工作日） | **都不要** |
| 谁能调 | 小程序 + 浏览器 | **只有小程序** |
| 平台给的身份 | 无 | 「这个请求来自本小程序」（不是「这是谁」） |
| 服务端看到的 | Host 头 | `X-WX-SERVICE` 指定的服务 |

**`wx.request` 那条路的门槛在备案**：名单只收已备案的域名（https + 有效证书 +
ICP 备案 + 不带端口不写 IP）。云托管的默认域填不进去 —— 微信提示
「云托管域名仅用作测试使用，不可用在正式环境下」。

**云调用把这张网整个免掉**：它走微信内网，不经过那张名单，于是域名、证书、备案
三样一起免。代价只有一条 —— 浏览器拿不到调用方身份，所以网页版只能走另一条。
本项目两端本来就是两份部署，这条代价不落到任何一处。

三条边界要记（各自都能伪装成别的错）：

1. **不省登录**。平台只保证「来自本小程序」，不告诉后端「这是谁」——
   access token 照旧装在 `authorization` 头里，服务端认的还是同一枚会话
2. **`config.env` 与 `X-WX-SERVICE` 是两个环境**。前者是**云开发**环境 ID
   （`poem-d9g1bqeq978682c58` 形），后者是云托管的**服务名**。
   拿云托管那个数字环境 ID 去填 `config.env` 是最常见的一种错，报的是 `env not exists`
3. **它不走那份 `baseUrl`**。客户端按「有 baseUrl 就走 http，只配了 cloud 就走云调用」
   分派（`remote.useCloud()`），两个都填时以 baseUrl 为准

接进客户端只多一层分派，**契约一个字没动**：`PATHS`、报文、401 重试、错误形状
全在 `remote.js` 里共用，换通道不影响任何一条业务逻辑。

### 本项目现在填什么

`appid` 是正式号（`wx200a0c667fc67fcb`），`project.config.json` 里
`setting.urlCheck: true` 是**故意的** —— 本地关掉校验只是联调开关，
配置文件里不许关，免得把「真机上必然失败」当成「跑通了」。

- **主路：云调用（免备案）** —— 两格的值**构建期从密钥仓库注入
  `miniprogram/utils/server.js`**（空壳入库、值不入库），随包走，用户不必填。
  界面上**没有**配置入口：换部署改代码库里那份，
  或改密钥仓库两个变量重跑流水线。`baseUrl` 与 request 合法域名那张名单同样留空
- **备选：request 合法域名** —— 名单里填 `https://<已备案域>`，客户端
  `configure({ baseUrl })` 填同一个（协议 + 主机，不带端口、不带路径）

云托管默认域**联调够用、正式环境不行**，要换自有已备案域名时顺序是
**先备案 → 再绑自定义域 → 最后改名单**。展开见
[`wx-cloud-setup.md`](wx-cloud-setup.md) 的 P.S.。

## 六、界面口径

- **颜色**：**这一版不再与网页版逐值相同** —— UI 已按 Issue #12 重做，见 [`design-system.md`](design-system.md)。主题色默认是黛青 `rgba(2, 54, 51, 1)`（清单与色值见 `utils/theme.js`），底是中性浅灰 `#f5f5f7`，卡片白；`--green` / `--amber` / `--red` / `--blue` 退成状态色，不再按页面分派
- **能力显隐**：见 § 一点五 —— 不可用的能力在界面上不留空位，也不留假按钮
- **字体**：正文宋体、界面黑体，与网页版同一口径。分两层办，见 § 六「字体与高度」
- **外壳不做照搬**：网页版那套自绘顶栏与底栏换成原生导航栏 + 原生 tabBar，这是小程序的推荐呈现方式，也免掉一整套安全区与胶囊避让的计算
- **进度环**用纯 CSS 锥形渐变，不引 canvas，也不带图片资源
- **交互控件一律用小程序自有的** —— 见 § 六点五

### 字体与高度：这一轮的两条硬口径

#### 诗词宋体：先系统，后外挂

要求原话：**「所有页面中，古诗词的标题，无论在列表中，还是在详情页中，
全部使用宋体，或者比宋体更好看的类宋体 / 古文风格。」**

一整套中文宋体 woff2 有 3MB，主包只剩不到 400KB，**塞不下** ——
所以「不外挂字体文件」这条不能松（§ 六 原本就是这么定的）。松不得，
那就分两层：

1. **先把系统里那个宋体找准。** `--font-poem` 按平台排一串名字：
   iOS / macOS 的 `Songti SC`、Windows 的 `SimSun`、
   Android 各家 ROM 的 `Source Han Serif SC` / `Noto Serif CJK SC` /
   `STSong`……缺一个，那台机上就**静默退回黑体**，而这件事界面上看不出来。
   所以这一串在自检里逐个守着（V12）。

2. **兜不住时用外挂子集补。** 子集不进包，放在云存储上（微信云托管自带的对象存储
   + CDN），由 `wx.loadFontFace` 在真机上注册一次，落在这条链的**首位**：
   系统名命中时这笔根本用不到，没命中才有一次网络。

文件名只有档位一个词，款由所在目录区分；`utils/font.js` 的 `files(dir, size)`
只拼这一处。换一款、换一份裁剪都不用动页面。

每款各注册一个字族，`--font-poem` 的首位跟着 `settings.font` 换名字 ——
换字体不重排正文，也不影响后面那串系统衬线兜底。

字体档与可选档是两件事：`shelf()` 只管取哪一份子集（随当前档位走），
`pickable()` 管能不能换款（pro 起）。未登录与 Free 落在默认那款的 `free` 子集，
Pro 取 `pro`，Max 取 `max`，档位变了下一轮 `font.refresh()` 就换一份。

- 谁可选：`font.pickable()` 取 `entitlement.status().tier`，pro 起。
  Free 那里 `font.set()` 直接拒（`{ ok: false, reason: "tier" }`），
  不静默改、也不假装成功；`current()` 另挡一道，档位掉回 Free 时
  停在非默认款上的用户退回默认那款。
- 每份按 woff2 → woff 的顺序试：第一份 `fail` 才往下一份走，
  老 iOS 不认 woff2 时得到的是 woff，不是黑体；woff2 成了就不再发 woff 那一笔。
- `auth.fontUrl` 仍可覆盖（字符串或数组），显式给空串就是不启用这条链。

档位与所选那款都会在一次启动内变（登录、刷新拿到 `plan.tier`、登出、在主题页
点另一款），`font.load()` 按「款 + 档位 + 地址」去重，同一款连着调用只发一次
`wx.loadFontFace`；`app.js` 在启动、回前台、登录回调与整点档位刷新后都走
`font.refresh()`。

**`wx.loadFontFace` 一次只吃一份文件**，所以 `@font-face` 那种「woff2 在前、woff 兜底」
的多 `src` 写法用不上 —— 小程序不解析页面里的 `@font-face`，兜底只能写在 JS 里排队试。

**字表有洞，按「显示不好拉倒」处理**：仍缺的字不走这份字族，落到后面的系统宋体；
系统也没有的，才是豆腐。要补就重新裁一份、换 `FACES` 里的地址，页面一处不用动。
生成脚本 `scripts/font-subset.js`。

**地址里不带 `sign` / `t`。** 带签名的下载链是会过期的一次性地址，
写进代码就是给线上埋一颗定时炸弹；云存储桶上的文件默认公开读，
`FACES` 用的是公开域名那几份。挑字表由前端按档位决定，服务端不校验 ——
这是观感增强，不是权限边界。

**全站只留一条字体链。** 详情页的题名、身份行、诗句正文，与列表里的书名、
词牌、诗句摘句同取 `--font-poem`：行与行、页与页之间不该有两种宋体，
同一批字在两张页面上字形不同，看起来是「两种字体」而不是「两个来源」。
`--font-poem` 只排所选那一款，之后就是系统衬线。

**「应用选中字体到全局」＝所有页面、所有用字都换。** 开关打开后 `--font-ui`
（页面基础字族）与 `--font-poem` 同时指向选中那一款，页面根节点的 `style` 一换就整页生效。

`wx.loadFontFace({ global: true })` 把字族注册在**当前页面**的作用域里，换一页就认不出这个名字。
所以每页都要注册一次：

- 页面自己的 `applyFont()` 里走 `font.registerHere()`；
- `App.onPageShow()` 再补一次，页面 `onShow` 里漏了也不至于退回系统字；
- 记账按「版本号 + 当前路由」记（`registerPage` / `scopeMark`）。按字族名记会让第二页直接
  跳过注册 —— 字族在那页根本没注册过，全局开关就只在第一页作数，这正是 Issue #744。
- `globalData.fontScope` 是版本号，`setGlobal` / `set` 各推一次，`app.repaintFont()`
  逐个页 `applyFont()`，回前台由 `font.restore()` 补一次。
- 页面只注册当前那一款，全量注册会把十几份上兆的子集压进单页的内存。

**自绘导航栏与底栏**（`components/nav-bar`、`custom-tab-bar`）是组件，页面根上的
`--font-*` 变量继承不下来，两处各自内联 `font.groupOf()` 拿到的那串字族；
导航栏在 `attached` 里注册一次，底栏在 `setActive` 里按当前款重算一次。

**原生外壳**（`navigationBarTitleText` 与系统 tabBar）由微信绘制，页面里的字族与 CSS 都够不到，
那里一律系统字。全站自定义导航栏只有 `pages/home` 与主题页两处，其余页面用原生标题栏。

**预览与正文是两套字族。** 主题页的字体格与预览壳里那七个字取 `font.preview()`，
每款注册的是自己目录下的 `7.woff2` / `7.woff`，字族名为 `Kuibu Preview <款>`，
与正文的 `Kuibu Poem <款>` 不相干。进页面把各款的 7 子集各注册一次，
点哪款、换哪款都不等网络。正文与预览是两条链，选哪款都不改预览那一份。
预览子集只含七个字，拿它排正文其余的字会落到系统衬线。预览字族不带系统兜底名，
只靠这一份子集：掉下来就是「预览没生效」那一格。

**预览字族的注册在页面作用域里。** `wx.loadFontFace` 带 `global: true` 时，
字族名只在调用那一刻的页面作用域里认得出，换一页就没了 —— 所以主题页把
各款的 `Kuibu Preview <款>` 挂在一层 `page-font-size` 的节点上，作用域跟着整页走；
没这层壳，卡里那几格会安静地退回系统衬线，看着像「预览没生效」。

**那层壳是隐藏的，不放 `<page-meta>` 里。** `page-meta` 只能是页面第一个节点、
只能有一个子节点，`page-font-size` 这属性又只供标记，所以里面写什么都是渲染得出来的
普通文字 —— 每款一行 `Kuibu Preview <款>` 会实打实铺在 banner 上。壳改挂在页面根里、
绝对定位、`1px` 见方、`overflow: hidden` 加 `clip-path: inset(50%)`：既不占位，
也不在无障碍树里念字。`opacity: 0` 不算数 —— 那是「透明」，不是「没画」。

**壳排在最前头，压在自己那一层。** 它必须排在 `page-banner` 之前，并且 `z-index: -1`：
字形得真的画过一次才算注册成，而排在 banner 之后、又没定层级的绝对定位节点
会被后面画的兄弟节点整块盖住。遮住了就等于没画，那几格照样是系统衬线。

**字族在启动时一次注册齐。** 早先只注册所选那一款，`--font-poem`
一换名字就是换到一个从未 `wx.loadFontFace` 过的字族，`load()` 的网络请求
赶不上这一帧的排版，页面按后备链渲染并就此停住；切回朱雀之所以「能显示」，
只是因为它从冷启动起就注册过。现在 `font.refresh()` 同时走 `load()`、`preview()` 与 `loadAll()`：
正文按档位取当前那款的 free / pro / max，预览注册各款的 `7`，
另外几款各取自己目录下、按档位的子集（地址直接来自 `FACES`，不从所选那款的地址里
换名字 —— 那样各款拿到的都是默认款那一份），于是切换、回退、档位没了退回默认，
都不需要等一次网络。字体是观感增强，多注册几款只是多几次静默下载。

**题名与正文一律不做加粗**：详情页的标题、身份行、诗句正文都用常规，
重点交给字号与留白。字号与字重是两个旋钮，一起拧就是「两处同时在喊」。
全站只剩页面顶部「今日诵读」一处粗体，口径在 `design-system.md` § 三。

**没地址就一笔不发起** —— 与 § 一点五 那条口径一致：
`utils/font.js` 的 `readiness()` 同步返回 `unsupported`，
`load()` 直接 `resolve(false)`，界面上不留任何「字体加载中」的假状态。
加载失败也一律吞掉：这是观感增强，退回系统宋体时用户不该看到任何提示。

#### 「能点的那一块」只有三种高度

要求原话：**「忘记 / 模糊 / 记住 三个按钮的高度过高，请看看其他按钮是否有类似问题，全部改进。」**

实测那三个是 112rpx（58px），而主按钮是 88rpx —— 高出一头半，
三个并排像三块砖，可每块里只有两个字。全站扫了一遍交互块的高度，
**只有这一处越界**，其余都在 60–88rpx 内。

所以收成三个令牌（`--h-btn` / `--h-btn-mini` / `--h-act`）：

| 令牌 | 高 | 用在哪 |
|---|---|---|
| `--h-btn` | 88rpx | 主按钮，一屏最多一两个 |
| `--h-btn-mini` | 60rpx | 一行里的小动作（搜索键、开关） |
| `--h-act` | 88rpx | 「忘记 / 模糊 / 记住」这类平铺的动作块 |

「点着舒服」的下限是 88rpx（≈46px，比 iOS 的 44pt 目标略宽），
**往上是浪费，不是体贴**。自检里加一条：按钮类选择器不许再写死 rpx 高度（V11）。

### 界面与交互的整改（这一轮）

要求原话：「界面和交互能美化和优化的请进行整改」。逐条说改了什么、以及为什么是这么改：

**一屏一件事。** 首屏那张卡只回答「今天背什么」。之前它只有标题 + 一个按钮，
现在补了三样：日期小字（知道看的是哪一天）、一道斜向微光（纸的质感，
比纯色块耐看且不抢字）、一条细进度条。环上给「几比几」，横条给「走到哪了」——
两个都要：只有环看不出还剩多少，只有横条看不出总数。

**门禁只有一张脸。** 13 个页面都有「未登录」这道门，原先各页各写一份，
措辞与长相都不太一样。收进 `components/lock-card`：一枚印章式圆标 + 一句人话 +
一个登录键。各页只给措辞（`note`），长相归一。这样用户看到的是一道门，
而不是十三道长得都不同的门。

**可点就得有反馈。** 挂着 `bindtap` 的行、集子卡、译文折叠头、选项卡，
一律补上 `hover-class` 或 `:active`。`<view>` 的 `:active` 在小程序里不生效，
所以导航型元素借 `hover-class`，控件型元素才用 `:active`。

**空状态给出路。** 「没有匹配的篇目」这几个字太干。统一成
「一枚淡印章 + 一句人话 + 一个下一步」：印章给个出处感（`诗` / `寻` / `空`），
人话里带上用户输入的那个词（`「明月」没有匹配的篇目`），
下一步直接告诉怎么走（`试试切到「正文全文」，正文里的句子也搜得着`）。

**慢的时候先立版式。** 首页读语料要时间。`components/skeleton` 先把版式占位画出来，
内容到了再换 —— 观感上是「很快」而不是「卡了一下」。

**搜索给个交代。** 结果上方加一行「命中 N 篇 · 篇名作者 · 全站」。
不写这行的话，用户看完一屏结果也不知道是全量还是抽样、搜的是哪一层。
空结果时也提示可以切到全文模式。列表一次 20 条，末尾写明「往下拉，再接 20 篇」，
到底了写「到头了，共 N 篇」—— 下拉有没有东西接得上，得让人看得出来。

**进度不再是三个孤零零的数字。** 进度页原先是「已学 / 已掌握 / 今日到期」并排，
三者是什么关系没人知道。改成一张总览卡：一枚温习进度环（已掌握 ÷ 已学）+
一行数字 + 逾期提醒。自选集合另起一页，用的是同一套四块（`components/progress-view`），
不另画一份简版（Issue #588）。那枚环与首页「今日诵读」第三格的那枚同规格。未来七天那七行各加一条按峰值归一的细条，
光看数字感觉不出哪天重。

**字号九档的类名。** `size--2` 与 `size-2` 是两档（负档与正档），
原先的写法里 `size--1` 与 `size-1` 贴在一起，很容易看漏一个减号。
现在负档统一两个减号，样式表里也按档位顺序排列，读起来是一条线。

**页面顶部是那张画。** `icons/hero.png`（1717×916）铺满屏宽，`mode="widthFix"`
按原比例落高 —— 它是带文字的成品画（图里已有「跬步诗词」四个字），
拉伸或裁切都会把字压歪，所以只许等比缩放。宽度铺满后左右不留白，
否则页面底色会在两侧各露一条；高度取 `min(屏宽 × 916/1717, 360px)`，
与伸缩后的画同高，画因此完全落在框里。

几何由 `components/page-banner` 一个组件给：盒宽 = 屏宽（用页面左右各一个
`--sp-3` 的负 margin 抵消 `.page` 的内边距），画高由组件自己算。
`icons/hero.png` 四周没有透明边，所以盒子按 PNG 的 1027×558 取比，
不再用「导航两段 + 折高」——那会让每一屏顶部多出一块空白。

页面级 `navigationStyle: "custom"` 时组件带 `banner-full`，再上移
`utils/page-banner.coverOf()` 算出的那段（导航行高的两成，4~10px），
盖住刘海区与导航行，微信胶囊浮在画上。上移量按屏幕与胶囊位置算，
不再按 `--sp-3` 算 —— 那会推过头，把画的顶边甩到屏幕外（Issue #610）。

上移是否生效由 `utils/page-banner.pagePadding()` 判：页面自己把顶内距归零
（`.home` / `.theme-page` 的 `padding-top: 0`），上移才是「推过空内距」；
页面留着 `.page` 的整份顶内距时不做上移 —— 两条叠起来盒顶就跑到屏幕外
（Issue #620）。同一口径下首页与主题页 banner 顶边都在屏幕顶，首卡同高。

页面自有导航（`components/nav-bar`）绝对定位在画里，标题压在画上。
画里的标题行占掉画的上一段，首卡因此不再压到画的下沿，改为让出
`--banner-lead-gap`（`-60rpx`）落在画里，并自带 `position: relative; z-index: 1`，
否则会被导航行盖住。
主题页（`packages/settings/theme`）与首页同一套：banner、导航行、首卡位置一致，
切主题时图与配色同时换；页面底色取 `--surface`，卡片去底留框线。
首卡只留 `.card` 那一份内距与横向外边距，外加上面那笔 `--banner-lead-gap`，
不再叠页头自己的内距与底 —— 两处各写一份就会差出几像素（Issue #588）。

画随主题换一张：`THEMES` 每一项带 `banner` 字段，页面读 `theme.bannerOf(key)`。
大好河山那几张走云托管对象存储的 `themes/city/` 路径（包内不放这几张，
`banner` 字段存完整 URL），其余一律包内的 `/icons/hero.png`。

城景与包内那张画同法：盒宽同样是屏宽，画按等比落高（`widthFix`），盒高由组件
按原画的比算出并封顶 360px。城景的长宽比与原画接近，所以盒高、首卡压画下沿的
位置都不随主题挪。

**首页可下拉刷新。** 首页是「今天要背什么」，下拉是对着它最自然的动作。
另外补了 `onShareTimeline` —— 分享到朋友圈的入口。

**颜色只定一次。** 页面样式表里再写一遍色值的字面量就算回归：写死一次就会漂一次。
（重做后字色令牌 `--ink` 是 `#1c1c1e`，主题色另走 `--theme`；V13 守的是「页面样式表里不写死任何色值」——
原先附带的那张「上一版八个身份色」黑名单已撤，用户明确那些颜色可以使用。）
自检里有断言守着。

## 六点五、控件用系统的，颜色用跬步的

要求原话：「所有设置、选项、输入框、按钮等尽量用小程序自有控件，顶多是色彩搭配需要适配跬步风格。」

这条比它看起来更值钱：原生控件的行为、无障碍、键盘、读屏、iPhone 上的惯性
都由平台保证，自绘一遍只会得到一堆「看着像、用着不像」的东西。
所以判据是 —— **凡是要用户选一件事、开一个开关、填一个字的，都用原生标签**：

| 场景 | 控件 | 用在哪 |
|---|---|---|
| 选一个 | `radio-group` + `label` + `radio` | 学段 / 年级 / 学期 / 温习范围 / 每日首数 / 复习算法 / 注音方式 / 本机档位 / 已读筛选 / 搜索范围 / 搜索模式 / 飞花令难度 |
| 选多个 | `checkbox-group` + `checkbox` | 题库与考试的题型 |
| 开与关 | `switch` | 音效（「背完自动下一首」2026-10-04 删了：它写的那个键没人读，按了不动） |
| 连续值 | `slider` | 无（字号改为阅读页与背诵弹层上的逐档加减，见 `design-system.md`） |
| 从列表里挑 | `picker` | 出题范围（集子） |
| 从系统菜单里挑 | `showActionSheet` | 用户列表页改档、改角色 —— 一次点击一次选择，比在行里摊三个按钮更原生 |
| 点一下 | `button` | 所有动作；卡片式入口、索引开关、改档、播放控制条也是 `button`，只把外观压成卡片 |
| 输入 | `input` | 搜索框、昵称（「我的」页头像右边那个名字，就地改）、兑换码、飞花令作答 |

### 唯一允许留下的自绘：导航行

列表行、篇目行、正文卡片是**导航**，不是控件 —— 塞进 `<button>` 会把语义搞坏
（`<button>` 包住一整首诗？）。它们保持 `<view bindtap>`，
但触碰反馈借的是原生的 `hover-class` 与 `hover-stay-time`，
不自己写 `:active`（小程序不认 `view` 的 `:active`，写了也不生效）。

### 配色怎么落到原生控件上

原生控件的外观**只能通过组件属性给**，WXSS 改不到它内部结构。所以：

- `switch` / `slider` / `radio` / `checkbox` 统一带 `color="{{themeHex}}"`（当前主题色），
  滑块的滑块头另给 `block-color`，进度轨给 `backgroundColor="#ece3d2"`
- 尺寸、圆角、间距、字体由 WXSS 负责（`.native-group` / `.native-label` / `.opt-row` 三个公共类）
- 圆点想小一点就用 `transform: scale()` 缩放外观 —— 命中区不受影响，反而更好点

### 一处「更原生」的选择

用户列表页的改档原先是一行里摆三个档位小标签，点哪个改哪个。现在换成
`wx.showActionSheet` —— **它是系统画的**，比页面里的自绘按钮更接近「用平台的东西」，
而且一次点击换一次选择，选完就落。同理，题库页的「至少留一种题型」不去禁用手势，
只把空清单折回去。

### 自检会盯着这条

「尽量用原生控件」写在 Issue 里，没人会每次改页面时回来读它，所以把它变成会红的检查
（§7.7）：

- **§7.7 A 该有的原生控件必须在**：逐页列出「本页至少要出现哪个原生标签」——
  温习设置没 `radio-group`、飞花令没 `input`，都会当场红
- **§7.7 B 自绘控件不许复活**：扫「挂着 `bindtap` 的元素上出现了 `.seg-item` / `.chip` /
  `.tier-chip` / `.sp-btn` 这类自绘控件类名」的组合。只看类名会误伤纯展示元素
  （`.tag` 是标签、`.char-n` 是字数），所以要求它同时挂了点击事件才算
- **§7.7 C 死掉的样式不许留在样式表里**：类名还在，就是在等下一次被用上
- **§7.7 D 原生控件的配色必须对齐主题**：`<switch>` 少一个 `color="{{themeHex}}"` 就红

A 条的名单里**没有用户列表页**：它这一版没有「选一个档位」的控件，改档改角色都走原生
`showActionSheet`。系统菜单比页面里的控件更原生，所以它在 B 条的保护范围内，
不需要 A 条再要求一个 `radio-group`。

## 六点六、观感上的哨兵（§7.8）

「美化和优化」听起来没法断言，但拆开之后**有几条是能断言的**，能断言的就不该靠人记住：

| # | 断言 | 为什么值得守 |
|---|---|---|
| V1 | 13 个页面一律用 `<lock-card>`，不许再自绘门禁卡 | 各写一份，措辞与长相必然分叉 |
| V2 | 全局组件必须四件套齐全并注册 | 少一个，WXML 里写了也是白写，报「组件未找到」 |
| V3 | 每页都留 `safe-bottom` 垫片 | 少了 iPhone 的横条会压住最后一行 |
| V4 | 挂着 `bindtap` 的元素必须有 `hover-class` 或 `:active` | 「点了没反应」是手机上最差的一种体验 |
| V5 | 每个 `.empty` 里必须有 `empty-mark` | 干巴巴一句「没有」不给出路 |
| V6 | 页面样式表里不许再写 `#1c1c1e` | 写死一次就会漂一次 |
| V7 | 首页必须有骨架屏，且 `loading` 会落回 `false` | 骨架屏卡着不收，比没有更糟 |
| V8 | 自定义组件的四件套、`component:true`、事件处理函数、标签配平 | 组件不在 `pages` 列表里，按页的检查全都盖不到它 |
| V10 | **登录后每道门禁都会真的打开** | 静态扫描看「这个词出现过没有」，看不出「会不会变假」——见下 |

V1、V4、V5、V10 四条都**反向验过**：把自绘门禁卡塞回 `library.wxml`、
把 `hover-class` 从集子卡上摘掉、把阅读页那行解锁删掉 ——
自检都当场红；改回来即绿。

### V10 是怎么来的

V10 不是设计出来的，是**踩出来的**。写这一轮的时候顺手把阅读页跑了一遍，
发现它无论如何都停在「登录可用」那张锁卡上 —— 正文一个字都渲染不出来。

原因：PR #6 给阅读页加门禁时，`data` 里写了 `locked: true`，
`onShow` 的未登录分支又补一次 `locked: true`，
而**登录分支从没把它设回 `false`**。也就是说从那一次合并起，
**所有登录用户在详情页看到的都是一张登录卡**，连自己背到哪了都看不见。

它躲过了之前所有的检查，因为那些检查都在问「这个词出现过没有」：
`locked` 在 `wxml` 里出现过 ✅、在 `js` 里出现过 ✅、门禁判据能被 `onShow` 触达 ✅ ——
三项全绿。**「出现过」与「会变假」是两回事**，而当时只查了前者。

所以 V10 换成**真跑**：用最小 `Page` 运行时把 9 个带 `locked` 的页面挂起来，
按「已登录」跑 `onLoad` + `onShow`，`locked` 必须落回 `false`。
判据从「有没有这个词」变成「门开不开」。
把阅读页那行解锁删掉，V10 立刻报「登录了还锁着（locked=true）」——
这次它是真能拦住的那一条。

这也是这一轮最值得记的一笔：**检查的形状要跟结论的形状对上**。
门禁是个开关，只验「存在」不验「开合」，就等于没验。

不往这一节里塞「字号是否协调」「留白是否舒服」这类 —— 那些没有客观判据，
写成检查只会得到一堆要人手动放行的例外，最后这条自检就没人看了。

## 六点七、语料里的框线表格

`scripts/corpus/` 有一批条目把内容写成了 ASCII 框线表格（`┌─┬─┐ │ ├─┼─┤`），
集中在文学常识、名著导读、名家、帝王四族。渲染前它们只是普通正文，
按诗句的折行规则排版，出来是断掉的竖线和被劈开的字。

`utils/table.js` 把这类块解析成行列：以 `┌├└` 开头的行是表格行，
其余行归段落。列边界取表格行里 `│` 的位置（同一列在每行 `│` 都出现的位置优先），
取不到（右侧补空格被破坏的那种）就退回按 `│` 切分。列宽只作各列占比（`flex-grow`），表格铺满屏宽，格内文字自动折行，不横向滚动。详情页有表格时走另一条渲染路径：段落块仍按原排版画，
表格块画成 `<view>` 网格，注音不参与（表格里没有可注音的诗句）。

### 语料侧的两类缺陷

解析器只负责画对已有内容，不改语料。语料本身的两种毛病仍在，按集子分批修：

- **右侧没补齐**（名家「外国」约 410 条）：左侧一格的 `│` 对不齐右侧，解析器退回按 `│` 切分，
  列内容仍能取出；根治要在语料里补齐空格。
- **一列吃掉一整篇**（名著导读几乎全是）：某些行的单元格宽度超过一千字符，
  解析器把列宽压到 120，这类表会被压成窄列、折成很多行；根治要重排表结构。

## 七、还没做的

诚实记账，免得看成「已补齐」。上一节列的五项功能都落地了，下面是各自**仍然待外**的部分：

- **注音渲染**：读音表构建时进包（`data/pinyin-table.js`，71 KB / 3609 字 / 117 条词组）。

  序数词判读 → 回退首读。词组表由构建脚本从网页版源码里**原样抠出来**，
  不抄副本 —— 抄一份就等于留了个会漂的镜子
- **题库 / 飞花令**：题库页 + 考试共用 `utils/quiz.js` 的出题器与 `judge()`，
  判分口径只此一处（两页各写一遍，迟早会有一个先把「模糊」算成对）。
  题型从 3 种扩到 5 种，可按需勾选
- **飞花令**（`packages/game/feihua`）：与真实飞花令同一口径。
  - **一令到底**：一轮只有一个令字（居中大字），用户依次接含该字的诗句，答对令字不变、续接下一句；
    令字位置不限。
  - **判词**：三条 —— 句中含令字；是某首诗里完整的一句（可连写相邻几句，须逐分句相等）；
    这一轮没说过。任一条不满足即接不上，当场收令。时间到同样收令。
  - **换令**：本令作结（有接上的句子就落一条成绩并上报），另出一个新令字、开新一轮。
    收令后「再开一轮」同样换新令字。
  - 令字按出题范围随机出（`feihua.pick()`，字池按范围与学段分键缓存，范围拉不到东西时逐级放宽）。
  - 作答查全量库，不按范围收窄（`feihua.judgeAsync()` → `search?type=content`）：范围只管令字，
    不管作答。诗词漫读 6 秒不回话，退回 `feihua.judge()`（只扫当前范围内的课内）兜底并提示。
  - 「看看还有哪些」同样查全量库（`feihua.lookAtSource()`），按 `exclude` 剔掉这一轮已接上的，
    走 `page` 翻页凑够条数。
  - 一轮从点「开始计时」起算；连对到 3 / 5 / 10 / 20 / 30 句各多一句激励。
- **三个游戏的出题范围**（`utils/game-scopes.js`）：四档。
  1. 课内·当前学段：按温习选项里的年级与册次，取课内 251 首里「本册及之前」，进页面默认选它；
  2. 课内：小学到高中全部；
  3. 诗词漫读：课内 + 十部课外集子；
  4. 不限：不限范围，完全取自诗词漫读。

  飞花令的令字池四档都取自课内。题库与考试里，第 3 档联网时从十部集子目录抽 12 篇
  （按标题取正文，`quiz.buildAsync()`）混入课内，第 4 档联网时向诗词漫读随机取 12 篇、只在这 12 篇里出题；
  取不到或不足 6 篇就退回课内并提示。范围名只写「自己是谁」，具体到哪一册由卡头那一行（`nameOf()` 现读设置）说。
- **考卷可以回头改**（`packages/game/exam`）：题号一排（`.dot`）点了就跳到那一题，
  「上一题」往回走。页面只有 `index` 与 `answers` 两份状态 —— 选中项永远是
  `answers[index]`，所以跳回去改与顺着做是同一条路。交卷前若还空着题，
  先压一句提醒（`cheer.ofQuit()`）并把「交卷」留在原地，再点一次才交。
  评卷在 `finish()` 里一次性走 `quiz.judge()`，结果页给分、逐题摊开、再给一句按分数分的评语。
- **鼓励语只有一份**（`utils/cheer.js`）：考试与飞花令都从这里取。分档看分数
  （满分 / 90 / 80 / 60 / 40 / 及格线下），每档两句按 `seed` 轮换；
  连对看里程碑。判据只有「分数落哪一档」一条，改档位只改 `MARKS`。
- **大会首页是目录，不内嵌玩法**（`packages/game/index`）：只列三张入口卡
  （飞花令 / 题库 / 考试），点了才进各自的玩法页。
  上一版把飞花令的「挑一个字 + 看答案」就地摊在这一屏，用户 2026-10-03 裁决
  「列表页不应该出现飞花令直接玩的情况」—— 玩法都进独立页，目录页不摆任何一件。
- **搜索只在课内那 251 首里找**（`pages/search` → `corpus.search`）：篇名 / 作者 /
  朝代 / 出处 / 分组逐条比，一次只出 20 条，下拉再续。课外正文不进包，
  全书倒排索引随之删掉（`utils/text-search.js` 已不在），搜索页不再有
  「正文全文」这一档，也不自称「全站」
- **云端同步**：报文形状收在 `utils/wire.js`（见 § 二点五），本机离线队列攒着，
  联网后一次推。**没后端时不上报成功**，如实说「已攒 N 条」。
  2026-10-04 起它**登录就有**，不再分档（用户裁决见 § 四与
  [`wx-login-server.md`](wx-login-server.md)「同步不再分档」）。触发点四个自动一个手动：
  **登录成功那一刻**、启动后 3 秒、进首页、本地改动静默 5 秒后自己推一程；
  手动那条在「我的 → 同步」，记着绕过 60 秒最小间隔（`sync.now(true)`）——
  界面里只有这一处按钮，其余全自动
- **档位每小时对一次**：`app.js` 的 `onShow` 里比 `kb_tier_at_v1` 记的时间戳，
  距上次满一小时才走一次 `entitlement.sync()`（`store.tierDue()`，间隔 `TIER_GAP_MS`）。
  挂 onShow 不挂 onLaunch，是因为常驻后台的小程序不会再跑 onLaunch。
  这只是刷新，不是校验：拉失败不写记录，下一次进前台再试，
  已有的 `auth.tier` 不被清空；真正的校验由服务端在业务请求上做。
  支付成功后的即时重拉不走这个节流，届时要绕开 `remote.sessionRefresh()` 的 60 秒窗口
- **管理页与用户列表**：见 § 四
- **微信登录后端**：`/api/wx/login` 与 `/api/wx/refresh` 在本仓库的 `api/` 里，
  连同会话认 `Authorization: Bearer`、`syncTierGate` 放开、两条新行的服务端白名单。
  剩下的只是运维（配密钥、建 `wx_accounts` 表）—— 照
  [`wx-cloud-setup.md`](wx-cloud-setup.md) 一步步做。契约、报文、表结构在
  [`wx-login-server.md`](wx-login-server.md)。没配之前登录降级成「本机身份 + free 档」，见 § 五
- **第一个 owner 怎么来**：网页版那边走 `OWNER_EMAILS` 环境变量
  （`api/_lib/core.js` 的 `claimOwnerRole`），**小程序端刻意没有这条口** ——
  一个能在客户端点出来的「把自己设成 owner」就是权限漏洞
- **真·按人开关**：服务端可以在会话里下发 `caps: { <能力键>: false }` 把某人的某项能力
  单独关掉（`entitlement.switchedOff()` 读它），但**目前没有后端会发它** ——
  这条通道留着，等管理后台那侧接上
- **权限分层判据**：`entitlement.can()` 是唯一入口，界面不许自己拼「能不能用」
  （措辞也归 `entitlement.hint()`）。自检里有三组断言钉着它：
  §7.6 走完四道门槛、§7.7 扫 WXML 确认每个页面都真的照做了、
  §7.8 钉住用户列表页不许再有自助提权的口子

## 八、怎么验

```bash
node scripts/build-data.js   # 生成语料（读 scripts/corpus/）
node scripts/check.js        # 离线自检
node scripts/parity.js       # 与能力表逐项对照
```

自检覆盖：页面四件套齐全、require 可解析、语料完整性（课内 251 条正文）、
**包的边界**（只有课内那一部、包里不再有分片与清单、主包体积与课内正文预算、
读音表预算）、四套算法的间隔与封顶、排期内核、注音多音字消歧、
飞花令判词、六种题型、**门禁与三档（含「本机写 max 不生效」）**、
**逐页扫 WXML 确认门禁真的生效**、WXML 字段粗查与标签配平、事件处理函数存在性、
页面跳转目标存在性、**控件来源（原生控件必须在 / 自绘控件不许复活）**、
**观感口径（门禁卡收在一处 / 可点就有按下反馈 / 空状态给出路 / 主题只定一次 /
首页有骨架屏 / 自定义组件四件套齐全）**、同步冲突、包体积。

跑之前得先生成语料 —— 数据不入库，见 § 三。

**自检会「借」服务端契约来验自己**（`scripts/parity-web/` 与 `scripts/corpus/`）：
报文喂给那份 `core.js` 的 sanitize 函数、已读行 id 对照语料里的同出步表、
同步路径对照那份 `routes.js`。这几份都在仓库里，CI 与本机跑的是同一份。

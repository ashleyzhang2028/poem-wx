# 与网页版的逐项对照

> 这份文件只回答一件事：**网页版有的，小程序这边有没有**。
> 逐条列，不写「差不多了」这种话 —— 那正是漏项藏身的地方。
>
> 判据分四种：
>
> | 记号 | 意思 |
> |---|---|
> | ✅ | 两端都有 |
> | ⚠️ | 小程序端故意**换个做法**（平台不同，能力不丢） |
> | ⏸️ | 小程序端**没做**，理由写在 `docs/todo.md` 或本表备注里 |
> | ❌ | 本该有却没有 —— **这是缺口**，要补 |
>
> 这张表是手写的，但**结论由 `scripts/check.js` 守着**：
> 表里每一行都对应一条能力键或一个文件路径，任一边消失就报红。
> 页面入口、能力键、路由三处任缺其一，都算 ❌。

| 背诵范围 6 选 1 | ✅ | ✅ | 小程序端 8 项（多「本册」与「本年级」）：本册 / 本年级 / 本册及之前 / 小学随机 / …… / 全部随机；卡名与「当前学段」那一格见 Issue #26 |
| 阅读偏好（对齐 / 注音 / 字号） | ✅ | ✅ | 阅读页当场调；详情页那一行是**六个图标**（对齐 / 注音 / 字号各两枚），「设置」页集中调一次，字号从滑块换成 A－ / A＋ 两颗 |
| 今日加背 | ✅ | ✅ | free。上限 20、跨 0 点归零、加完当场进今日计划（挂在每日几首之外：设 5 首再加 1 首就是 6 首，按设置排的那 5 首不动）；入口在首页顶部那条搜索行、详情页与背诵弹层那一枚「加入今日背诵」、以及背诵设置页的管理面板（全选 / 移出选中 / 全部清空） |
| 掌握程度三档（记住 / 模糊 / 忘记） | ✅ | ✅ | 朱砂 / 琥珀 / 主题。**下一次复习一律落在哪天，不落在几点**：记住按算法的天数表推到那天 9 点；模糊与忘记不论评在几点，同样落到次日 9 点（昨天 15 点以后评的、一轮里已经算过今天的那一次，顺延到后天 9 点），提示只说日期。12 小时 / 30 分钟这样的短间隔照着结果类型硬加，中午评就推到半夜、傍晚评就推到次日凌晨 —— 人不在那个点上背诗，而到期又按天在日历上摊开（Issue #299） |

| 全部到期篇目（按天摊开、逐条可点） | ✅ | ✅ | 一行一首：诗题 + 作者朝代 + 掌握度 + 距到期。逾期超一周的另立一头（网页版 `-7` 天那条线同口径）。点一行就地开背诵弹层，不换页 |

| ~~记忆阶段分布~~ | ✅ | ⏸️ | **小程序端不做**：算法的档位名是它内部那把尺子（「4 天后」「3 号盒 · 8 天后」），摊成一张卡读到的是一串与用户无关的刻度。这个读数在「全部到期篇目」每一行上按掌握度给 |
| 「明日再背」/「月后再背」两份名单 | ✅ | ⏸️ | 见 `docs/todo.md` 第 16 条 |

| 自选背诵（教材之外加篇目） | ✅ | ⚠️ | pro 起。网页版是按 tier 给额度（free 10 / pro 100 / max 5000，且 pro 之下那两项是「清单」不是「按算法排期」）；小程序端 Free 无、Pro 1 个、Max 200 个，每集合 100 首，每个集合各排一份每日计划。入口三处：首页每个集合各一张卡、我的页、阅读页与列表 / 搜索结果行上那枚星。管理（新建 / 改名 / 加篇目 / 移出选中 / 清空 / 删集合）只在「我的 → 自选背诵」，首页不做就地改名。集合连每日首数一起跨设备（`collections:v1`）。**进度只记在篇目上**：同一首课内课外各出现一次，也只算一份掌握度，不按集合另存一套 —— 集合的读数用同一把尺子逐篇汇总，见 `docs/architecture.md`「掌握度」。见 `README.md`「自选背诵」一节 |
| 自选集合的进度（每集合一枚环 + 到期 + 掌握度分布） | ⏸️ | ✅ | 网页版没有这一项。小程序端的「背诵进度」页在本册四块之后逐集合摊开：环（已掌握 ÷ 已学）、篇数 / 已学 / 已掌握 / 平均掌握四个数、今日到期与逾期、七天到期、五档分布，与新排一样在「我的 → 自选背诵」每行给出掌握度细条。读数一律由 `scheduler.collectionProgress()` 汇总，与 `overview()` 同一份口径 |

## 三、大会与出题

| 能力 | 网页版 | 小程序 | 说明 |
|---|---|---|---|
| 出题方式 | 服务端组卷 | ⚠️ | 网页版每次出题问服务端要一份卷子；小程序端**本机现出**：从已进包的语料里按范围与题型随机抽，没有预置题库，也没有一张存在数据库里的卷子。同一条链路见下三行 |
| 飞花令（随机出令字 / 作答判对错） | ✅ | ✅ | max。一轮 90 秒，连对与轮次句数当场可读；一次提示只给两个字 |
| 令字池按命中数分常见 / 一般 / 难 | ✅ | ✅ | 同一套阈值 |
| 题库练习（逐题判定） | ✅ | ✅ | pro。选完立刻判、立刻给对错，连对累积成读数 |
| 题型：下句 / 上句 / 作者 / 朝代 / 篇名 | ✅ | ✅ | 就地取材，不接 AI。名字比网页版短，见 `design-system.md`「题型名」 |
| 考试（限时 20 分钟，全部答完再批） | ✅ | ✅ | max。答题途中不给对错，题号可跳回去改（`answers` 一份数组，选中项跟着 `index` 取），带着空题交卷先提醒一次；交卷时统一批并逐题摊开（对的也列），再按分数落到七档段位并给一句评语 |
| 段位与最好成绩 | ⏸️ | ✅ | 按正确率落到童生 / 秀才 / 举人 / 进士 / 探花 / 榜眼 / 状元七档，最好的一次留在本机，入口卡上带「最好 xx」 |
| 答题激励（分数评语 / 连对里程碑） | ✅ | ✅ | 两份共用 `utils/cheer.js`：考试按分数档给评语（低分也有话，不是只夸高分），飞花令连对到 3 / 5 / 10 / 20 / 30 句各给一句 |
| 答卷范围（全部 / 单部集子 / 小学·初中·高中） | ✅ | ⚠️ | 小程序端按「集子 + 全站课内」给范围，学段随机由排期层负责 |
| 正式考试 | ✅ | ⏸️ | 依赖后端组卷判分，见 `todo.md` 第 9 条 |
| 文学常识考试 | ✅ | ⏸️ | 同上 |
| 音效（背忘记 / 模糊 / 记住，答对 / 答错 / 过关 / 出分） | ✅ | ✅ | Web Audio 现场合成，零音频文件 |
| 音效开关 + 试听 | ✅ | ✅ | 声音设置页，试听是开关左边那枚空心胶囊 |
| 排行榜（分学段 / 年级 / 学期，按日周月年） | ⏸️ | ✅ | 小程序端独有：网页版没有这一层。见 `architecture.md` § 二点八 |
| 领奖台与勋章（状元 / 榜眼 / 探花） | ⏸️ | ✅ | 同上 |
| 榜单昵称打码（首末字 + 两个星号） | ⏸️ | ✅ | 服务端与端上同一口径，端上再兜一层，`check.js` 钉着 |
| 昵称敏感词过滤（写入拦 + 榜单兜底） | ⏸️ | ✅ | `api/_lib/nick-guard.js` 一份词表，`nicknameSet` 与 `boardMaskNick` 各过一遍 |
| 排行榜开关（两个榜默认开） | ⏸️ | ✅ | 管理后台不设拨杆，库里 `ranking:exam` / `ranking:fly` 没有那一行按开算。显式写 `0` 时列表挡住、提交照收 |

## 四、账号、同步与权限

| 能力 | 网页版 | 小程序 | 说明 |
|---|---|---|---|
| 邮箱注册 / 登录 / 验证 / 重设密码 | ✅ | ⏸️ | 小程序里不做邮箱密码，见 `todo.md` 第 4 条 |
| 微信登录（静默 `wx.login`） | ⏸️ | ⚠️ | 反向补的：小程序有，网页版没有；服务端要加两条路由 |

| 跨设备同步 | ✅ | ⚠️ | 网页版是 pro；小程序端归 free，且不用手动 —— 登录 / 启动 / 进首页 / 本地改动都自动推，「我的 → 同步」只留一条强制入口 |
| 进度导出（JSON） | ✅ | ⏸️ | 小程序端不做：进度与设置跟着微信账号同步，拷一份文件出来没有用处，见 `todo.md` 第 6 条 |

| 头像（用户名首字 / 上传图片） | ✅ | ⚠️ | 小程序走 `open-type="chooseAvatar"`，不自己压缩上传 |
| 用户协议 | ✅ | ✅ | 「我的 → 关于 → 用户协议」一页（`packages/settings/terms/`），文案按小程序实际写 |
| 隐私政策 | ✅ | ✅ | 「我的 → 关于 → 隐私政策」一页，与用户协议同在关于页的菜单里；文案按小程序实际写，不照抄模板 |

## 六、平台形态（这些不是缺口，是换掉）

| 项 | 网页版 | 小程序 | 为什么 |
|---|---|---|---|
| 分发 | PWA + Service Worker 离线 | 小程序包 + 分包预载 | 平台不同，离线策略必然不同 |
| 外壳 | 自绘顶栏 + 底栏 | 原生导航栏 + 原生 tabBar | 小程序的推荐呈现，免掉胶囊避让那一整套计算 |
| 控件 | 自绘 | 一律小程序自有控件 | 点击区 / 读屏 / 惯性由平台保证 |
| 部署 | Vercel（网页版自己的那台库） | 微信开发者工具上传体验版 | 见 `.cnb.yml` 的 `main` 流水线 |
| 虚拟支付 | 不支持（个人主体） | 不支持（同一条） | 三档都不收费，管理员按人分 |

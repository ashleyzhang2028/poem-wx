# 待做清单（现在不做，以后可能做）

> 这份文件是**唯一一处**记「小程序端还没做、以后可能做」的地方。
> 与 poem 网页版的 [`docs/todo.md`](https://cnb.cool/npu-gpu-cpu/poem/-/blob/main/docs/todo.md)
> 是同一套纪律，但不是同一张表 —— 那边记的是服务端与产品的待做，
> 这边只记**小程序端还没有的东西**。
>
> 逐项对照的现状在 [`docs/parity.md`](parity.md)。

## 纪律

1. **这里的每一条都是「不做」的现状，不是「即将上线」。**
   界面上不许把它写成「即将上线」，这份文件也不许写成排期承诺 ——
   没有日期、没有工期，全看「有人真要」。
2. **做完一件就搬走一件。** 真开工落地了，设计写进 `README.md` 或
   `docs/architecture.md`，这里只留一行「已搬走」。
3. **不做的要说清「不做的理由」。** 与「还没做」分开记 ——
   把「不做」写成「以后做」，就是给自己留一句假话。

## 二、明确**不做**的（免得被误读成「以后要做」）

| 事 | 实情 |
|---|---|
| 付费 / 支付通道 | **不做**。微信不允许个人主体做虚拟支付，而这里本来也不需要 —— free / pro / max 三档都由管理员按人分，界面上「付费」两个字一次都不出现 |
| AI 讲解 / 背诵纠音 | **不做**。唯一「调一次真花钱」的一类，从能力表里删掉了 |
| 整本导出（八部集子的正文） | **不做**。那是站点整理的内容资产，一次性拷走不行 —— 这是产品判断，不是「还没做」 |
| 儿童独立账号 | **不做**。未成年人实名 / 同意的合规成本高，儿童只是账号下的展示名 |
| 打开即强制登录 | **做不到**。`wx.login` 是静默的；要用户点头的接口必须由手势触发，没有 API 能在启动时弹授权框。所以写法只有一种：**进门容易、用起来要求登录** |

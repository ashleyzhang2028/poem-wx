# 正文分片怎么送到手机上：两条路，与它们的账

> 一句话：**分片跟主包一起走云托管容器下发，仍然免备案。**
> 代价是它要过一次容器、不能享受 CDN 边缘缓存 —— 而这个量级（1 万人也就几 GB/月）
> 容器完全扛得住。展开见下。

## 一、为什么不能像「下载文件」那样直接下

课外 5604 首的正文（分片，120 个文件）**不在小程序包里** —— 主包只有 2MB，
而分片原文 23MB。要让手机取到它们，只有两条路：

| | `wx.downloadFile` + 域名 | `wx.cloud.callContainer` |
|---|---|---|
| 走哪张名单 | **downloadFile 合法域名**（微信后台登记） | 不经过任何名单 |
| 收什么域 | **只收已备案的域**（https + 证书 + ICP） | —— |
| 域名 / 证书 / 备案 | **三样都要** | **三样一起免** |
| 谁能调 | 小程序 + 浏览器 | **只有小程序** |
| 边缘缓存 | 有（CDN） | 没有（从容器出） |

**卡点在备案**：`wx.downloadFile` 打的那个域必须先进 downloadFile 合法域名名单，
而那张名单只收已备案的域 —— 与 `wx.request` 同一条规矩。云托管的默认域填不进去
（微信提示「仅用作测试使用」）。

所以：
- **分片走公网 = 绕不开备案**（3–20 个工作日）。这是 `docs/todo.md` 第 13 条记的那道门。
- **分片走容器 = 免备案**。云调用走微信内网，域名 / 证书 / 备案三样一起免 ——
  与后端（登录 / 同步 / 管理）本来就是同一条口径。

## 二、这条链是怎么接起来的

```
小程序  corpus.ensureEntry(id)
          ↓ 课内 251 首在主包里，同步就有；其余走下面
        remote.shard(name)                    utils/remote.js
          ↓ wx.cloud.callContainer( path: "/api/shard/t017" )
        serve-api.js  →  shardApi.handle()    deploy-api-serve/shard-api.js
          ↓ 读 /app/shards/t017.json.gz
        200 + Content-Encoding: gzip（44KB）
          ↓
        corpus 缓存这一片 → 渲染 → 下次不再请求
```

### 为什么分片不跟「进度」走同一条 `PATHS`

`utils/remote.js` 里的 `PATHS` 是**业务接口**表，每个条目都会进 `push()` 那条
离线队列（outbox）。分片是只读的大块，混进去会把队列撑爆。所以它单独一条
`SHARD_PATH`，且**不写 outbox**：它自己那份缓存由 `corpus.saveShard()` 管
（上限 40 片，满了丢最早那份）。

### 为什么容器里那份要是 gzip

同一个文件在链路上出现两次，两次都是压缩后的：

| 环节 | 谁压 | 多大的量 |
|---|---|---|
| 构建上下文 → 镜像 | 流水线 `gzip -9`，上下文里只摊 `.gz` | 5.6MB（不是 25MB） |
| 容器 → 手机 | 直接发那份 `.gz`，带 `Content-Encoding: gzip` | 每片约 44KB |

台账详见 [`deploy/README.md`](../deploy/README.md) 的「成本」一节。

### 清单进包，正文走云 —— 两者不能混

`bucketOf(id)`（「这一条在哪一片」）靠的是**分片清单**。它在**主包里**
（`data/shards.json`，约 137KB，gzip 17KB），**不在** `data/texts/` ——
因为 `project.config.json` 的 `packOptions.ignore` 排掉的是**整个 `texts/` 目录**
（正文 24MB 进不去，这是对的），清单一落进去真机上就没了。

这条是「按需取正文」能不能成立的**前提**，不是细节：

| 缺了它 | 表现 |
|---|---|
| 清单在包里 ✅ | 点开课外诗 → 算出片名 `t0xx` → 走 `/api/shard/t0xx` 取那一片（44KB） |
| 清单被 ignore ❌ | `bucketOf()` 一律回空 → `ensureEntry()` 直接回 `null` → **连请求都不会发**，界面说「这一篇取不到正文」 |

所以：**清单（路由表）进包，正文（大块）走云**。这条边界由 `scripts/check.js` 钉着
（读 `corpus.js` 里那个 `MANIFEST` 常量，断言它不在 `packOptions.ignore` 名下）——
Node 里怎么跑都是绿的，只有真机会撞，所以判据只能是静态的。
`texts/idx.json`（全文倒排 2MB）是**另一回事**：它太大进不了包，
`text-search.js` 读不到时降级为「按篇名作者检索」，有兜底，故允许它留在 `texts/`。

## 三、分片默认**不进**镜像

镜像里有没有分片，由构建参数 `COPY_SHREDS` 决定：

| `COPY_SHREDS` | 镜像 | `/api/shard/*` |
|---|---|---|
| 不写（默认） | 不含分片（与从前一样，约 60MB） | `404 E_NO_SHARDS` |
| `=1` | 含分片（+5.6MB） | 正常 200 |

为什么默认不做：绝大多数调试构建（`e2e-mysql`、本地试跑）用不到分片，
带上只会让每次部署多传 5.6MB。要分片时在 `.cnb.yml` 的 `env:` 里加一行：

```yaml
env:
  COPY_SHREDS: "1"      # 值要写字面量，别写 ${VAR:-...}（CNB 只替换 $VAR）
```

**没开时的表现是刻意的**：小程序那边收到 `E_NO_SHARDS`，
界面上说的是「这个版本里没有课外正文」—— 不是「这一篇取不到正文」。
这两句话指向的下一步动作完全不同，所以一路上都不许把它们合并成一句
「加载失败」。

## 四、这条路的好处与不好的地方

### 好处

1. **免备案**。这是它存在的**唯一**理由 —— 域名、证书、ICP 三样一起免，
   不用等那 3–20 个工作日。
2. **不多养一套东西**。分片跟后端同一个镜像、同一个服务、同一套部署动作，
   没有第二处要配的域名与证书。
3. **只有小程序能拿到**。内容不走公网，不会被别的站直链、也不会被随便爬。
   对「站点整理的内容资产」这件事来说，这条算是白捡的。
4. **加了版本号零成本**。分片随镜像走，「哪个版本有哪一片」由镜像 tag 钉死，
   不像 CDN 那样要自己管缓存刷新。

### 不好的地方

1. **没有边缘缓存**。CDN 是「就近的机房把字节发给你」，容器是「就那一台（几台）
   发给你」。分片本来就只在**点开某一首诗**时才拉，不是首页首屏路径上的东西，
   所以这一条的体感影响不大 —— 但它是真实的。
2. **公网流量单价更贵**。云托管公网流量 **0.8 元/GB**，COS+CDN 是 **0.18 元/GB**
   （CDN 流量）。同一份量，容器那条贵约 4.4 倍 —— 绝对值仍然很小（见下）。
3. **容器是唯一缓存层**。冷启动后的第一次请求要现读磁盘（预压缩过就直接发，
   没预压缩要现压一次）；实例被缩容到 0 时，第一个请求还要等实例起来。
4. **实例缩容到 0 就「冻住」**。常驻才有即时的响应 —— 而常驻是要按
   CPU/内存小时计费的（见下）。反过来，**不常驻**就得接受「第一次点开等几秒」。
5. **不能给浏览器用**。云调用只有小程序能打。网页版拿不到分片 —— 本来就是
   两份部署，不落到任何一处，但这条边界要记着。
6. **图片/字体那条路还是没通**。这份路由只发 `data/texts/*`；字体子集
   （`utils/font.js` 那条）仍写着「等 CDN」，要用同一招得再摊一份（没做）。

## 五、成本

刊例价取自微信云托管官方文档
[「产品定价」](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/Billing/price.html)
（详见文末口径说明）。下面每一行都按**本项目的真实体积**算，不是估的。

### 5.1 分片本身的体积（真量出来的）

| | 进镜像那层 | 发到手机那片 |
|---|---|---|
| 原文 | 25.04 MB（122 个 json，含倒排索引 2.0MB） | 每片 186–210 KB |
| **gzip -9 之后** | **5.63 MB**（22.5%） | **每片约 44 KB**（中位 39KB） |
| 清单 + 倒排索引 | 18 KB + 466 KB | 同左 |

**每次部署要多传的**：5.6MB（不是 25MB —— 流水线只摊压缩后那份）。
**镜像体积**：+5.6MB。这两条都是一次性的，与用户数无关。

### 5.2 容器（真正花钱的地方）

分片本身**不另计费** —— 它只让容器的 CPU/内存一直有活干，而容器是按
「实例数不为 0」的那段时间计费的：

| 规格 | 刊例价 |
|---|---|
| 0.25 核 0.5G | **0.02975 元/小时** |
| 0.5 核 1G | 0.0595 元/小时 |
| 1 核 2G | 0.119 元/小时 |

按最小实例（0.25 核 0.5G）算两种运行方式：

| 运行方式 | 月用量 | 月费（刊例） |
|---|---|---|
| **常驻**（24 小时都有实例） | CPU 180 核*小时 + 内存 360 GB*小时 | **约 21.4 元** |
| **缩容到 0**（按官方示例的口径，8:00–24:00 才有实例） | CPU 120 + 内存 240 | **约 14.3 元** |

⚠️ **这一栏与分片无关** —— 后端（登录/同步）本来就要一个常驻实例。
分片加进来只多占一点磁盘，不多占 CPU/内存。换句话说：**上不上分片，
这笔钱都一样花**。

**免费额度**（首个环境，有效期 3 个月）：CPU 720 核*小时 + 内存 1440 GB*小时
+ 公网流量 5GB。按上表折算够跑 **120 天** —— 也就是说前三个月这套东西
（容器 + 分片 + 后端）一分钱不花。

### 5.3 流量 —— 你问的那笔

云调用**不像 CDN 那样分「下行/回源」**，只算一条：**公网流量 0.8 元/GB**。
（官方口径：只通过 `callContainer` 访问、不经公网域名的请求**不产生流量用量**；
这里的「公网流量」是**服务出网**那一侧算的。所以下面这张表是**上界** ——
真按内网走，分片这笔可能连这条都算不上。以控制台账单为准。）

每片 44KB，按「每个活跃用户每月取 N 片」估：

| 月活跃 | 每月请求数 | 流量 | 流量费（0.8 元/GB） |
|---|---|---|---|
| 100 人（每人 5 片） | 500 | 0.02 GB | **0.02 元** |
| 1000 人（每人 5 片） | 5 000 | 0.21 GB | **0.17 元** |
| 1 万人（每人 5 片） | 5 万 | 2.1 GB | **1.7 元** |
| 1 万人（每人 20 片） | 20 万 | 8.4 GB | **6.7 元** |

**带宽**不是单独计费项 —— 它被算进实例规格。最小实例（0.25 核 0.5G）的出口
带宽大约只够几 Mbps；一台实例撑 1 万人「偶尔点开一首课外诗」绰绰有余，
因为**请求是分散的**，不是每秒涌进来的。真要遇到「某个时刻几百人同时点」
（比如群里有人转发），平台会自动扩实例 —— 那时账单按实例数走，不按带宽走。

### 5.4 与方案 B（COS + CDN + 自有备案域）比

| | 方案 A：容器下发 | 方案 B：COS + CDN |
|---|---|---|
| 备案 | **不要** | **要**（3–20 工作日） |
| 域名 / 证书 | 不要 | 要（域名一年几十块） |
| 流量单价 | **0.8 元/GB** | 0.18 元/GB（CDN 流量） |
| 1 万人 / 2.1GB | **1.7 元** | 0.38 元 |
| 存储 | 0（在镜像里） | 0.118 元/GB/月 × 0.0056GB ≈ 0.001 元 |
| 额外要养的 | 无 | 一个域名 + 一套 CDN 配置 + 一份证书续期 |
| 边缘缓存 | 无 | 有 |
| 冷启动 | 实例缩容到 0 时第一下有等待 | 无 |

**一句话**：1 万人那档，两条路差 **一块多钱一个月**。
方案 A 买的是「**不用备案、不用多养一样东西**」，
付的是「贵 4 倍多的流量单价 + 没有边缘缓存」——这个量级上，前者的价值远超后者。

### 5.5 口径说明（别把这张表当账单用）

- 价格取的是**刊例价**，不叠折扣、资源包、优惠券 —— 可理解为理论最高价
- 免费额度只给**首个环境**、有效期 3 个月
- 「只通过 callContainer 访问不产生流量用量」（官方原文）这句话使 5.3 那张表
  成为**上界**；真按内网走，分片这笔可能更低
- 实际金额以「微信云托管控制台 → 费用中心 → 充值与账单」为准

## 六、这条路上踩过的坑（留给下一个改它的人）

| 现象 | 真因 |
|---|---|
| 构建报 `"/shard-api.js": not found` | 上下文里没有它 —— 漏了流水线 stage context 那一行 `cp deploy-api-serve/shard-api.js /tmp/ctx/shard-api.js` |
| `e2e-mysql` 报 `Cannot find module './shard-api.js'` | 同一条：那条 e2e 自己摊一遍上下文，漏摊了这一样 |
| 课外正文取不到，界面说「这一篇取不到正文」 | 镜像里没分片（`COPY_SHREDS` 没开）。**这时该看到的是「这个版本里没有课外正文」**，看到前一句说明界面把两种因合并了 |
| 容器日志里什么都看不出来 | 分片路由在 `apiHandler` **之前**，它 200 了就不进 poem 的日志 —— 要单独看 |
| 课外正文取不到，界面说「这一篇取不到正文」，**而日志里一个请求都没有** | 清单被 `packOptions.ignore` 排掉了（曾经它写在 `data/texts/manifest.json`）。`bucketOf()` 回空，客户端**根本不会发请求**。清单要在包里（`data/shards.json`）——见 § 二「清单进包」 |
| 自检 V49「接线在 require handler 之前」无故变红 | 块注释里写了 `/api/*` 之类的**带星号的路径**，`/*` 把注释后半段吃掉了。写成行注释，或在块注释里别写 `/xxx/*` |

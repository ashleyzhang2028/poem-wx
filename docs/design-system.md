# UI 设计规范

这一版是 Issue #12 之后**重做**的一版：上一版那套「宋代传统色 / 纸纹 / 印泥」
整份撤掉，按用户给的参考图重定。

规矩写在 `miniprogram/styles/tokens.wxss` 与 `app.wxss` 里，
`scripts/check.js` 的 **V13 一节**守着它们 —— 下面每一条都有对应的断言。

---

## 一、这一版为什么推倒重来

上一版不难看，单看每一块都说得过去。它的问题是**靠颜色和装饰区分「这是什么」**：

| | 上一版 | 这一版 |
|---|---|---|
| 分层 | 纸纹 + 底色差 + 卡片投影 | 只靠**留白**与一道极淡的描边 |
| 重点色 | 八种身份色（背诵墨绿 / 复习琥珀 / 忘记朱砂 / 大会青碧……） | **一处**：跟着主题走 |
| 表达重点 | 色卡 + 金边 + 印章，一屏好几处在喊 | **大数字**，一屏只有一组 |
| 圆角 | 四档（16 / 20 / 24 / 999） | 三档（14 / 20 / 24 / 999） |
| 字阶 | 十档（22 → 104rpx） | 六档 |

一句话：**先做减法，再谈风格。**

## 二、色

### 重点色只有一处

```css
--ink:    #1c1c1e;   /* 墨 · 正文与字（中性，不跟主题） */
--strong: var(--theme);          /* 强调 · 底色：按钮、选中块、进度环、印章 */
--strong-text: var(--theme);     /* 强调 · 字色：标题、大数字、底栏当前项 */
```

它原来不是「黑色这个颜色」，是「这里是重点」这件事本身。参考图里按钮、选中态、
头像底、底栏当前项，全都是一块干净的黑。

所以：**一屏里填黑的地方只该有一处。** 详情页是「记住」，设置页是选中的那一格。
首页因此没有大按钮：今天的篇目就在「计划」列表里，点哪行开哪行。

### 主题：那支墨可以让用户挑（Issue #26）

「既然是『重点』而不是『黑』，它就该让用户挑。」这一版是用户给的八色
（青绿 / 暮色 / 暖灰 / 青瓦 / 米褐 / 石绿 / 墨红 / 雾蓝），
外加他点名要留的**墨色** / **胭脂** / **雨过天青** / **黛青**（默认）。
选了之后，按钮、
选中态、卡片与列表标题、底栏当前项一起换 —— 换的是「重点长什么样」，
不换任何别的东西。

八色都是同一个明度带上的沉色，对页面白底 ΔE 47.9 ~ 77.8，最低的雾蓝
离判据线还有一倍。上一版那套中华传统色（朱红 / 明黄 / 天青 / 竹青 / 玄色 /
鸦青 / 天水碧）连同它们那张 ΔE 表一并撤掉 —— 清单换了，那些数就不再守任何东西。

「黛青」用的是 `rgba(2, 54, 51, 1)`，取自首页 banner 那幅画上的墨绿，
淡淡一档 `rgba(2, 54, 51, 0.05)`。它是默认那一项。

「墨色」用的是 `rgba(8, 8, 10, 1)`，比 `#1c1c1e` 再深一档。原因是下面那条
「压在主色上的字」，`#1c1c1e` 压石绿只有 2.66:1。

**色值一律 rgba**，不再有 hex：同一支色要按 1.0 / 0.05 两档出场，
写成 `rgba(46, 106, 103, 1)` 只是换个透明度的事，hex 得先转一道。

#### 每个色带一档 0.05 的淡淡版

`utils/theme.js` 的 `style()` 把每个色按两个透明度发到页面根节点上：
`--c-qinglv` = `rgba(46, 106, 103, 1)` 与 `--c-qinglv-soft` = `rgba(46, 106, 103, 0.05)`。
**胶囊这类「说了有这回事、但不必喊」的底**用淡的那一档；`variables()` 铺给所有色，
不挑当前主题 —— 页面上要摆色卡，每个色都得同时在场。

`--theme` / `--strong` / `--theme-deep` 指向当前那个色的 1.0，
`--strong-soft` 指向它的 0.05，所以在页面里写 `var(--strong-soft)` 就跟着主题走
（`tokens.wxss` 里默认落在黛青上）。

**做法**：真正被覆盖的是**页面根节点上的内联变量**（`style()` 的产物），
因为小程序里 `page{}` 上的变量 JS 改不了；`page{}` 里那几行是同一份值的兜底。
`theme.apply(page)` 在每个页面 `onShow` 里调一次 —— 26 个页面各一行，
`check.js` V27 守着，漏一个就红。

#### 色卡是**圆点**，每个圆点里只放它自己那一档色

改之前：十枚 96rpx 的圆角长方形（`--radius-ctl`）。
用户的原话是「每个颜色都是很大的圆角长方形，不美观，建议使用小一点的圆形」。

不美观之外还有一层：全站「能点的一块」都是同一个长相 —— 20rpx 圆角 + 填色。
色卡长成那样，读起来就是「一组可点的选项」（跟年级、学期那些格子一模一样），
而它其实是**一个颜色**。颜色本身是内容，形状不必再替它说「这是个控件」。

现在：56rpx 的**正圆**，色名在圆点下面，热区是 108rpx 见方的整格 ——
圆点小，但点得中。

圆点里放什么，用户改过一版：原先选中那一枚往圆心填色并打一枚 **✓**，
现在是**每个圆点默认铺自己那一档 0.05**，`hover` / `focus` / `on` 三种情形
（聚焦、悬停、选中，以及已选中的那个）回到 **1.0** 的本色。勾撤掉了 ——
勾是「选项」的记号，而这一圈色本身就是记号：淡的是「这有个色」，
实的是「就是这个色」。选中那个再加一圈 0.05 的外描边，说「已经落定」。

三种情形合成一条规则，写成一条选择器列表
（`.swatch-hover .swatch-dot, .swatch-dot:focus, .swatch.on .swatch-dot`），
判据在 `check.js` 里按这三处都在守着。

圆点用 4 列栅格（11 个色三行），不再五列 —— 色名要放得下，
两行五列地挤会把「雨过天青」折行。

「效果预览」那三块样例（两个按钮、两枚胶囊、一条列表行）默认**收起来**，
点一行摘要就地展开 —— 色卡已经占了半屏，再挂三块不可点的样例，
这一页就成了「外观博物馆」而不是设置。

#### 两支墨，不是一支

这是加主题时最容易做错的一步：`--ink` 原来同时管三件事
（正文的字、标题的字、重点的底）。主题一接上去，朱红那类暖色会把**全站正文
都染红** —— 而用户要的是「按钮、选中项、标题」变色，没要正文变色。

于是按「这支墨在说的是哪件事」分：

| 令牌 | 说的是 | 用在哪 | 跟主题吗 |
|---|---|---|---|
| `--ink` | 「这是字」 | 正文、诗词、输入的字 | **不跟**（中性墨） |
| `--strong` | 「这里是重点」的**底色** | 按钮底、选中块、进度环、印章、底栏圆底 | 跟 |
| `--strong-soft` | 同一支色的 **0.05** | 胶囊底、淡淡的一圈 | 跟 |
| `--strong-text` | 「这里是重点」的**字色** | 标题、大数字、底栏当前项 | 跟 |

所以**篇名与诗字永远是中性墨**（`.row-poem` / `.char-t` 显式写回 `--ink`）。
诗词名字上色，与「篇名宋体是内容需求」是同一条道理：它是书，不是书架。

#### 压在主题上的字，跟着主题定

`--on-ink` 不是写死的白字：按相对明度（`0.2126R + 0.7152G + 0.0722B`）
在黑与白里挑**离本色更远的那一支**，算出来不够 4.5:1 就换另一支。

这一版 11 个色里有 9 个落在白字上，**石绿**（黑字 4.56:1）与**雾蓝**
（黑字 4.68:1）落在黑字上 —— 它们的本色压白只有 4.39 / 4.27。
挑色时按「比 `#1c1c1e` 再深一档」把墨色定成 `rgba(8, 8, 10, 1)`，
也让深色主题上的白字站得更稳。`check.js` 里那条断言按这个判据真算：
算出来不是 4.5，或者配的不是更远的那一支，都会红。

#### 主题色要在白页面上看得见

主题色要铺在按钮底、选中块上，而页面底是 `#f5f5f7`。所以每个色还得过一条：
**它自己对页面白底的色差 ΔE ≥ 25**（CIE76，Lab 空间欧氏距离）。
低于这条，按钮底铺上去跟没铺分不出来 —— 这正是用户说的「太接近」。

| 色 | 对页面白底 ΔE | | 色 | 对页面白底 ΔE |
|---|---|---|---|---|
| 墨色 | 94.4 | | 青瓦 | 57.4 |
| 黛青 | 78.9 | | | |
| 胭脂 | 80.6 | | 石绿 | 54.7 |
| 墨红 | 77.8 | | 米褐 | 54.2 |
| 雨过天青 | 62.7 | | 雾蓝 | 47.9 |
| 暖灰 | 60.7 | | | |
| 青绿 | 59.3 | | | |
| 暮色 | 57.8 | | | |

`check.js` 里有一条按这个判据真算一遍：清单里的色有一个算不过就红，
色值与 ΔE 都对不上时报的是色名。上面这张表是算出来的，不是抄的。

#### 状态色不跟主题

绿=成功、红=危险、琥珀=待办照旧。用户说的「选中的选项都用天青」指
**主题那一类**（按钮 / 选中 / 标题），不是把「已读」「忘记」也染成天青 ——
那样又回到 Issue #12 之前「颜色各自表达身份」的老路了。

#### 三处「已经做过」的标记走主题（Issue #232）

「今日背诵」序号、「课外阅读」列表的已读胶囊、我的页的「清空背诵数据」，
都用 `--strong-soft` / `--strong-text`：

- 前两处是**同一件事的标注**（这一篇背过了 / 读过了）而不是成功或失败，
  底色只是「说了有这回事、但不必喊」的那一档 0.05，跟按钮选中态同一支色；
- 「清空背诵数据」是一行的标题，不是按钮，也不是报错。它跟旁边的
  「同步」「用户权限」一样只说明这一行是什么。

判据在 `check.js`：这两处规则的声明里必须是 `var(--strong-soft)` /
`var(--strong-text)`，且 `.read-dot` 只在 `app.wxss` 定义一次
（列表页与作者页共用）。

#### 其余「淡绿 / 淡青」胶囊底一并收进主题（Issue #232 续）

接着扫了一遍全站，还有五处挂着 `--green-soft` / `--green-light`，
谈的也全是「重点那一支色」而不是状态，一并改到 `--strong-soft` /
`--strong` / `--strong-text`：

| 处 | 类 | 它说的是 |
|---|---|---|
| 档位与权限 · 当前档位那一格 | `.chip.is-now` | 「你在这一档」 |
| 题库 / 考试 · 答对的选项格 | `.option.right` | 「这就是正解」（重点，不是「成功」） |
| 考试 · 逐题那个「对」字标记 | `.grade-mark.ok` | 「这题对了」 |
| 题库 · 「看全篇」那条链接 | `.verdict-link` | 一个可去的出口 |
| 详情页 · 译文标题按下时的底 | `.trans-hover` | 按下的反馈底 |

**真正是状态的仍在状态色上**：`.fh-msg.ok` / `.verdict-line.ok` 这类
只染字的反馈、「忘记 / 模糊」两颗评分格（`.chip.bad` / `.chip.fuzzy`）、
`.tag` 的 amber / red / blue / green 四档、`.btn.danger`、
以及 `.option.wrong` 与 `.grade-mark.no`。它们回答的是「这件事是什么状态」，
不是「这里是重点」，所以不跟主题 —— 与上一节同一条线。

判据在 `check.js`：这五处规则的声明里必须是主题那三个变量；
`--green` 只许出现在 `.tag.green` 与上面那几处「状态」里。

#### 权限对比表：三列同一套灰，你那一列才上色

表里每格一枚 `mask` 图标（`utils/icons.js` 的 `yes` / `no`），取色按三档：

| 格 | 色 | 说的是 |
|---|---|---|
| 当前用户这一列、有 | `--strong` | 「你有」 |
| 其余列、有 | `--ink-2` | 「这一档有」（对照，不抢眼） |
| 任一列、没有 | `--ink-4` | 「这一档没有」 |

行按「有几档开着」从多到少排：三档都有的在最上，两档的居中，只最上一档开着
的在最下 —— 差别大的项自然沉到表底，找「我这一档差在哪」往下翻就行。

#### 篇名的两枚胶囊：为什么这么排（Issue #279）

首页四张卡的篇目行，篇名后面挂两枚胶囊：

| 位置 | 说什么 | 类 | 取值 |
|---|---|---|---|
| 前 | **今天为什么背它** | `.tag.theme` / `.tag.ghost` | 新学 / 复习 / 补充 / 今日加背 |
| 后 | **它从哪来** | `.tag.course` / `.tag.own` | 课内 / 自选 |

前者是排期给的**状态**，随今天变；后者是篇目的**出身**，不随今天变。
两件事，所以两枚 —— 一枚不替另一枚说话。

- **不重复说**：出身那枚已经在篇目行上说了「自选」，自选集合的卡标题就只写集合名，
  不再缀「· 自选」。
- **互斥**：一首要么课内要么自选，判据是篇目所属的那部集子
  （`b === "poems"` 是课内，其余都是课外收进集合的），**没有第三态**。
  所以两枚胶囊永远只出一枚，位置也就永远对得上。
- **配色**：出身不是状态，所以不走琥珀 / 红 / 蓝 / 绿那四档状态色。
  课内用主题那一档淡底（`--strong-soft` / `--strong-text`），自选退回凹槽灰
  （`--sink` / `--ink-3`）—— 与「今日加背」那枚 `.tag.theme` 同支色系但排在其后，
  靠位置与文案分得开。
- **不出现空胶囊**：状态那枚在没话说时（课外篇目不在今日计划里）整枚不渲染，
  WXML 按 `item.reason` 有没有决定出不出现 —— 与身份行缺项不补孤零零一个 `·` 是同一条。

### 层次只用三档灰

```css
--bg:      #f5f5f7;   /* 页面底 */
--surface: #ffffff;   /* 卡片面 */
--sink:    #f2f2f4;   /* 凹槽：输入框、未选中格子、图标底 */
--line:    #ececef;   /* 卡片边 */
--line-2:  #f4f4f6;   /* 卡片内的行分隔 */
```

上一版有四个「浅色」（`--card` / `--card-2` / `--bg-soft` / `--bg-sink`），
彼此差 1~2% 明度 —— 手机屏上看不出来，只会让「我该用哪一个」变成每天要重猜一次的问题。

### 状态色只表达状态，不表达身份

```css
--green: #2e7d5b;  /* 成功、已读、完成、答对 */
--amber: #b26a00;  /* 提醒、待办、复习、逾期 */
--red:   #c0392b;  /* 危险、忘记、删除、答错 */
--blue:  #2f6f9f;  /* 信息、新学 */
```

上一版它们是「复习用琥珀、大会用青碧」这种**按页面分派**的身份色，一个颜色管一摊事。
现在它们只回答「这件事是什么状态」。

`check.js` 里有两条守着：字色令牌 `--ink` 必须是中性墨黑（三通道接近且够深），
以及**页面样式表里一个色值都不许写死**（全走令牌）。

上一版那八个身份色**本身可以用**（用户已明确）—— 它当初一起被禁，
是因为它们总以「写死在页面样式表里」的形态出现。现在禁的只有那个形态。

## 三、字

### 篇名用宋体，界面用系统黑体

这条是**内容需求**（诗词要像诗词），不是装饰，所以它从上一版留了下来。

```css
--font-poem:      "Kuibu Serif", "Songti SC", …, serif;        /* 题名 · 身份行 */
--font-poem-text: "Kuibu Serif Text", "Songti SC", …, serif;   /* 诗句正文 */
--font-ui:        -apple-system, "PingFang SC", …;
--font-num:       -apple-system, "SF Pro Display", …;   /* 数字 */
```

两条链排同一串系统名，差别只在首位那个外挂名。**题名、身份行与诗句正文
一律常规字重**（`font-weight: 400`）—— 详情页标题、身份行、正文都用常规，
重点由字号与留白给，不由字重给。外挂那份源字体只有半粗（SemiBold）一个源，
所以正文那条注册时带 `desc.weight = "normal"`，否则长段诗句会连字重一起
继承成半粗（自检 V12 钉着这一条）。

「先系统、后外挂」的两层策略没变，做法见 [`architecture.md`](architecture.md) § 六。

诗句正文的 `letter-spacing` 为 `0`：汉字本身已是全角方框，再加字距就是在
每个字的推进宽度上叠一层缝。36rpx 这一档加 `2rpx` 等于把整行拉宽 4%，
字距宽而字形不变，一列下来就是「瘦长」的观感。

注音那一路另有 `--py-gap`：每个字身盒两侧各留一格，这才是「字与字之间那道缝」。
它现在是 `1rpx`（原为 `2rpx`，减 20% 后取整）。注音字号 `--fs-pinyin` 是
`22rpx`（原为 `18rpx`，加 20% 取整），槽高 `--py-slot` 跟着抬到 `38rpx`。

### 字阶只有六档

```
--fs-caption 22  脚注、单位
--fs-hint    25  说明、次级信息、标签
--fs-body    29  正文、列表副题
--fs-title   32  列表标题、字段名、按钮
--fs-lead    38  页头、卡片主标题
--fs-hero    46  一屏只有一处的大标题
```

另有四个「一屏只出现一次」的：`--fs-stat`（统计大数字）、`--fs-score`（考试分数）、
`--fs-brand`、`--fs-mark`。

**页面样式表里出现裸 `font-size: 27rpx` 就是漏了令牌** —— V6.5 守着。

**统计大数字（`.stat-v`）是常规字重，不是粗体**（Issue #232）：
「今日 / 已背」「已学 / 已掌握 / 今日到期」这两排数字本来就大，再叠一层
`font-weight: 600` 是两处同时在喊；去掉之后大字号自己撑得住重点，
与页头标题拉开层次。判据在 `check.js`：`.stat-v` 那条规则里是
`font-weight: 400`。考试分数（`.score`）不走这条 —— 它一屏只出现一处。

**粗体只有一处**（Issue #232 / #277）：页面顶部的「今日背诵」四个字
（`.hero-title`，`font-weight: 700`）。其余一律不做加粗，重点由字号、
字体（宋体 / 黑体）与留白给 —— 字号差与宋体自己撑得住重点，再叠
`font-weight` 就成了「一屏好几处在喊」。卡内小标题（`.card-title`）、
页头与卡片主标题（`.head-title`）、详情页题名与身份行、统计大数字
（`.stat-v`）、进度环读数、选择态（`.seg` / `.chip` / `.opt-row`）、
「我的」那两行账号名，字重都只有一个出处：不加就是不加，不逐条写
`font-weight: 400`，也不借它当选中态的第二个信号（选中由底色 + 反白字说）。

### 行高三档

```
--lh-tight 1.3   标题
--lh-body  1.65  正文
--lh-loose 1.9   需要放开读的（空状态、说明）
```

诗词正文不在这三档里：它自己一支 `--lh-poem 1.5`（`--fs-poem` 的 36rpx 之下
即 54rpx 行盒）。诗句是整行成句的，用 `--lh-loose` 那样放开会把一首七绝
摊成一屏半；用 `--lh-body` 又挤。这一档是「读一首诗」的行距，
与 UI 文案的行距是两件事。

**句读分行与自动折行两种行距不同。** 一行之内放不下、由 WebView 自己折下来的
那一段，两行之间再加 `--poem-fold`（16rpx）；按句读分开的两行，仍是 `1.5em`。
做法是 `.poem-line` 的行盒按 `1.5em + --poem-fold` 给（管的是行内折行），
相邻两行之间再减回 `--poem-fold`（管的是行与行的距离）。注音那条路不参与 ——
装箱时按字身盒算过一行放几个字，轮不到 WebView 折行。

### 数字一律等宽

`--font-num` + `font-variant-numeric: tabular-nums`。
「24」「3」「58」三个数并排，用比例数字会左一个右一个；`0/5` 换成 `4/5` 时也会跳。

## 四、形与距

```css
--radius-sm    16rpx   行内小块：标签底、小图标底
--radius-ctl   999rpx  控件与按钮 —— 选项格 / 选项行 / 按钮（全站一种）
--radius       20rpx   卡片
--radius-block 24rpx   大块：输入框、统计块
--radius-pill  999rpx  胶囊：标签、分段、搜索框、头像
```

`--radius-lg` 不在表里，是被有意合并掉的。
**能点、能选中的东西一律 `--radius-ctl`** —— 形状取自搜索框里那颗搜索按钮
（Issue #266）：一颗圆的胶囊才是「能按的一块」，方角的矩形读起来像填表。
所以 `--radius-ctl` 与 `--radius-pill` 现在是同一个值，
控件那一档不再自成一格 —— 见下一节的「两条长相」。

投影：卡片一律不用（`--shadow: none`）。卡与卡之间只有 24rpx 的缝，
投影的模糊半径就有 6rpx，一条缝被两侧铺满就是一条两头深中间浅的灰带，
首页自上而下七八条。「哪张卡更重要」交给留白与字号差，不交给投影。

间距八档（8 / 16 / 24 / 32 / 48 / 64 + `--page-x` 28rpx）。
留白是这一版唯一用来分层的手段，所以稀疏的一侧留得比上一版大。

## 五、控件规范

### 搜索页那几个热门词整行居中

「李白 / 杜甫 / 苏轼 / 春 / 月 / 登高」是搜索框下面的候选，
它们是**同一组**，两行也好三行也好，整组居中（Issue #266）：
左对齐时第一行看着是「一行标签」，最后一行那一个落单的词会像跑偏。

`.hot-tags` 是 `flex-wrap` + `justify-content: center`；词与词之间靠
`.tag-btn` 的右外边距断，不用 `gap` —— 用了 `gap` 之后换行那一步
两侧的余量由 `justify-content` 分，末行的右外边距会多顶一份，
整组看着偏左。

### 「能点的那一块」只有三档高度

```
--h-btn      96rpx   主按钮：一屏最多一两个，是这一屏的正事
--h-btn-mini 60rpx   小按钮：一行里的小动作
--h-act      96rpx   动作块：「忘记 / 模糊 / 记住」这类平铺动作
--h-row      96rpx   列表行
--h-field    84rpx   输入框、搜索框
```

「点着舒服」的下限是 88rpx（≈46px，略宽于 iOS 的 44pt 目标）——
往上是浪费，不是体贴。**按钮高度不许各页写死**，V11 守着。

### 控件用系统的，只换一张脸

开关 / 单选 / 多选 / 滑动条 / 选择器 / 按钮全部走小程序自带控件：
行为、无障碍、键盘与读屏由平台保证。

原生控件的交互色只能通过组件属性给，取不到 WXSS 的 `var()`，
所以它注定要在 WXML 里写一次。Issue #26 之前那一次写的是字面量 `#1c1c1e`；
现在它**跟着主题走**，写法是绑到页面 data 里那份 `{{themeHex}}`
（`utils/theme.js` 的 `apply()` 给）—— 仍然是「一处」，只是那一处从常量
变成了绑定。`check.js` 里那条断言盯的也从字面量换成了 `{{themeHex}}`。

原生控件自己带固有尺寸，`--ui-scale` 够不着它，开关是唯一一处需要再收一道的：

| 控件 | 平台给的尺寸 | 怎么收 |
|---|---|---|
| `<switch>` | 51 × 31 px | 壳 `.sw`（`--w-switch` 88rpx / `--h-switch` 54rpx）+ 里面 `transform: scale(var(--switch-scale))`，两个令牌都乘 `--ui-scale` |
| `<slider>` | `block-size` 12–28 | 给属性，取 12（平台下限） |

壳不是为了好看：`<switch>` 铺开就是 51 × 31 px，缩了之后布局仍按原尺寸占位，
两边的字会被它挤走，所以先把它绝对定位进壳、尺寸只由壳说话。
壳也因此保住了 88rpx 的触控宽 —— 开关看着小了，点着还是原来那一块。

### 两条长相，不是三条

用户最后问的是这一句：

> 「所有按钮加大 radius，和这两处的按钮要不要都和课外阅读列表页那些集子的选项样式保持一致？」

**要。** 而且查下来当时不止「不一致」，是三套圆角：选项格 16rpx 的近直角、
按钮 999rpx 的胶囊、标签 999rpx 的胶囊。前两套都是「能点、能选中」的东西，
却是两种长相 —— 这就是「不统一」的出处，而且它不在一页里，跨页才看得见。

全站的可点块只有一条长相：**胶囊**。分界不在形状上，在「它是整块还是一段」：

| 长相 | 用在哪 | 圆角 | 高度 |
|---|---|---|---|
| **控件** | 选项格、选项行、按钮 | `--radius-ctl` 999rpx | 76 / 96rpx |
| **胶囊** | 标签、分段、搜索框 | `--radius-pill` 999rpx | 56 / 60rpx |

- **控件**：一格一个选项、一颗按钮。填色说中没选中。
- **胶囊**：一行里的一段、一个标记。细长，两端的圆就是它的形状本身。

两档高度不同、填色相同，所以同一屏里仍然一眼分得出「这是可点的」和
「这是标记」。2026-10-17 用户点名以搜索框里那颗搜索按钮为模范
（Issue #266）：「将其他页面的圆角矩形按钮全部按这个修改，
特别是登录按钮，背诵页面各个选项按钮」。落成的样子是
`--radius-ctl` 与 `--radius-pill` 取同一个值，`.btn`、`.chip`、
`.opt-row`、`.algo-row` 一起走它 —— 登录按钮、背诵设置的学段 / 年级 /
学期 / 背诵范围 / 每日首数、题库题型、试卷选项，不再有方角。

分段（`.seg-item`）本来就在胶囊档上：一段的圆角等于轨道的圆角才咬得上。

`.tag`（标签）与 `.section-label` **不跟这一条**：它们已经是胶囊，
改的只是「原来方的那几处」。**大块不改** —— 卡片 `--radius` 20rpx、
输入框与统计块 `--radius-block` 24rpx，它们是面，不是能按的一块。

**还有一个尺寸**：选项格的内边距，上下与左右分开两个令牌 ——

```css
--pad-opt-y  4rpx   选项格 · 上下
--pad-opt-x  24rpx  选项格 · 左右
```

落成令牌而不是写死在 `.chip` 里，有两个理由：它要跟 `--ui-scale` 一起收；
而且它不止管格子 —— `.opt-row`、`.tag` 的内边距都从这两条出，
一屏里标签与格子挨着时才像一套东西。它们**必须上下 / 左右分开**，
不能合成一个 `padding`：这两条边管的是两件事，纵向厚一点格子才「有肉」，
横向厚一点两字选项才不顶到边框。

### 内边距治不了「挤」——列数是另一回事

用户最后一句是：

> 「选项内文字左右 padding 和它自己的边界太近了，太挤了」

第一反应是把 `--pad-opt-x` 从 8rpx 加到 24rpx。**加完才发现没用**，
而且不是「加得还不够」——是**方向错了**。量一下就知道
（`scripts/shots/measure.js` 会把每一格的两侧余量打出来）：

| | 格宽 | 文字宽 | 两侧各余 |
|---|---|---|---|
| 修前 · 三列 · pad 8rpx | 100.5px | 85.3px | **4.8px** |
| 修后 · 两列 · pad 24rpx | 148.6px | 85.3px | **31.6px** |

关键在于**格子宽是均分定死的**：`(内容宽 − 缝) ÷ 列数`。
横向内边距是从这个定值里**抢**出来的 —— padding 越大，文字到格子边的距离
反而越小（三列里 pad 4→24，两侧余量 15.7→11.5rpx）。所以：

- **挤，多半是列数多了**，不是内边距小了。背诵范围（旧名取诗范围）七项里当时最长的是
  「小学+初中随机」（7 个字宽，Issue #26 已收成「小初随机」），
  三列里格宽只够它站住、剩不下空。改成**两列**（`.cols-2`）之后
  格宽 190→303rpx，两侧各留 66rpx；六项排两列是三行，只比原来的两行多一行。
  改短名字并没有推翻这条：现下最长的是「本册及之前」，两列仍比三列松快
  （两侧各 87rpx vs 32.5rpx）。
- 内边距这一档（24rpx）管的是**别的格子**：「一年级」「3 首」「题型」这些
  短文字，8rpx 时它们也贴着圆角。

这条由人看：去掉 `cols-2` 会让最长的选项名贴到圆角上，看一眼就知道。
自检不管它 —— 界面长什么样不在断言里（见 AGENTS.md）。

#### 背诵设置里没有阅读偏好（历史上的「一行 N 段」已撤）

**背诵设置页只管「背哪些、每天几首、怎么复习」** —— 学段 / 年级 / 学期 /
背诵范围 / 每日首数 / 复习算法，各自一张卡。

注音 / 对齐 / 字号**不在这页**。它们是**读一首诗时的临场偏好**，
要在诗句旁边当场调、当场看见效果，所以只待在两处：

- **详情页**（`pages/reader` 的 `.prefs`）：读这首诗时顺手调
- **设置页**（`packages/settings/general`）：集中调一次

用户原话：

> 「注音 ｜ 对齐 ｜ 字号」只应该出现在详情页和具体古诗背诵卡片里，
> 怎么显示在了背诵范围这里

这一页前后出过两版错：先是被塞成「一行七个段」（学期 · 年级 · 注音 · 对齐 ·
字号全挤一行），再是被收成「一行三段」（只留注音 / 对齐 / 字号）。**两版都把
阅读偏好搬到了它不该在的地方** —— 第二版只是把前一次的「越塞」收窄，方向仍错。
所以那一行连同它的排法（`.pref-row` / `.font-step` / `.fs-btn`）整块删除，
不再有「分段控件不撑满宽度」的例外。

背诵设置页里**没有**注音 / 对齐 / 字号（出现 `onPinyin` / `onAlign` /
`onFontDown` 就是摆错了页），这页也没有 `<slider>`。

**「集中在哪儿」这一半改过两轮。** 原来注音住在单开的一页「阅读设置」里，
而对齐与字号在「通用设置」—— 同为版式的三件事分在两页，改一个要跑两趟。
2026-10-04 用户问：「通用设置版式里有对齐和字号，怎么没有注音的设置？」
三件事先并到了一页，读的还是同一个 `settings.pinyin`。
2026-10-16 又叫「把主题和声音也全部整合到这个通用设置页面里去」——
于是那一页收成对齐 / 字号 / 注音 / 声音 / 主题五块，名字从「通用设置」改成「设置」。
「主题」「声音」两页随之撤掉：它们本来就是「一次调好」的偏好，分三处改要跑三趟。
注音仍走 `pinyin.setMode()`，音效仍走 `sfx.setEnabled()`，不各写一份 store。

**「年级是十二格还是六格」这一条后来改了口径。** 上一版的口径是「十二格同屏、
一个不收」，出处是「年级从十二格收到六格（取最近六年）- 谁让你这么瞎搞的，
这能收吗」。那一句禁的是**按最近六年砍掉高年级**，不是「十二格必须同屏」——
上一版读成了后者，于是没有「学段」那一格，用户在小学段里也能看见「高三」，
却看不出自己站在哪一段里。

这一版按 Issue #26 后半段（「背诵范围内……应该显示为 当前学段」）补上
**当前学段**三格：年级格只列这一段，**一个年级都没丢**（三段合起来正好十二个），
换学段就换一排、取诗范围也跟着换（选初中 → 「初中随机」）。所以判据从
「十二格同屏」改成两条：**12 个年级都还在**、**屏幕上只列当前学段那几格**。

#### 详情页的阅读偏好：一行装完（Issue #26 收尾）

用户在详情页上连着追了两轮：

> 「详情页一行显示 —— 左对齐 居中 不注音 生字 全文 A- A+」
> 「详情页你是没动，但是不是说了 「注音 ｜ 对齐 ｜ 字号」一行显示吗，你做到了吗？」

那一行是「**对齐 ｜ 注音 ｜ 字号 ｜ 加背**」，整行居中，三组之间各一道
极淡的竖线。**六个选项与加背开关全部用图标，没有字**（2026-10-16，Issue #247）：
图标只画 `.glyph` 一个元素（背景/描边各一处），一套形状在 `app.wxss` 里
定义一次，详情页与弹层共用。选中态是「颜色加深 + 项下一条 3rpx 短横」，
不再是填墨一块 —— 一枚 24rpx 的图标被实心色块包着会糊成一团。

| 图标 | 是什么 | 图形 |
|---|---|---|
| `ic-left` / `ic-center` | 左对齐 / 居中 | 三条横线，短的一根靠左或居中 |
| `ic-off` / `ic-rare` / `ic-all` | 不注音 / 生字 / 全文 | 划掉的圆 / 短符号压一条长线 / 斜排的注音点 |
| `ic-smaller` / `ic-larger` | 减小 / 加大字号 | 一枚 `−` / 一枚 `＋` |
| `ic-add` / `ic-added` | 加入 / 移出今日背诵 | 一枚 `＋` / 一个对勾；**没有边框** |

三处和别的地方不一样，都写明了理由：

| 事 | 这里 | 别处 | 为什么 |
|---|---|---|---|
| 段的外形 | `.pref-opt`，未选中就是**裸图标** | `.seg-item`（在浅灰轨道里） | 那一圈轨道底色在「三组挤一行」里是多余的一层 |
| 图标的容器 | `.glyph`（24rpx，与文字同一视觉重量） | `.seg-icon`（与字并排） | 这里没有字，图标自己就是那一项 |

**选中态不是填墨**：图标改用 `--strong-text` 加深，并加一条 3rpx 短横（`.pref-opt.ic.on::after`），
底透明 —— 一枚 24rpx 的图标被实心色块包着会糊成一团。底层仍是原生 `<radio>`（包在 `<label>` 里、
走 `.opt-radio` 视觉隐藏），加背开关是一个 `<view>` + `bindtap`。
「设置」页那根 `<slider>` 不动 —— 它是集中调字号的地方，独占一行。

### 详情页的身份行：朝代 · 作者 · 出处 · 学段

> 唐 骆宾王 课内诗词 新学 这些一定一行显示，注意样式的统一与协调

上一版这三件事分三行三种样式（朝代作者一行、出处一行、学段一枚胶囊），
现在收成**一条**：同一个字号 `--fs-caption`、同一个颜色 `--ink-2`
（学段用 `--ink-3` 再退一档，它是「背到哪了」而不是身份），
同一枚 `·` 断开。容器 `.poem-meta-row` 显式 `flex-wrap: nowrap` ——
折了「一行显示」这件事就破了。

四段里出处与学段会缺（课外篇目没有出处；学段总有，未学篇目停在「新学」）。
所以点由 WXML 按「有没有」自己决定出不出现 —— 写死两个点会在缺项时
留下孤零零一个「·」。

`--fs-caption` 在全站是「脚注、单位」那一档。这里用它而不用 `--fs-hint`，
是因为它是诗题下面的注脚，压一档才像「落在标题下的一行小字」，
与上面那个大标题拉开层次。

#### 标题底下还压着一行小字：题名异写 · 选本出处

身份行下面还有一行，只在有内容时出现（Issue #516 / #512）：

```
又名：秋登万山寄张五 · 选自《唐诗三百首》
```

两件事都**不进身份行**，各有各的理由：

- **「又名」**是题名的注 —— 它说的不是这首诗的身份，是「你可能在别处见过
  另一个名字」。与网页版 `reader-core.js` 的 `renderAliases()` 同一处、
  同一句话。
- **「选自《唐诗三百首》」**是**第二重出处**（#512）：身份行上的 `source`
  已经写了这首诗所出之书（《孟襄阳集》），`selection` 记的是「收它的那部
  选本」。两件事都真实，但并进身份行会把那一行撑破 —— 量过：
  `朝代·作者·出处·选本·学段` 在《唐诗》里 37 条超宽、《词》48 条，
  而身份行是 `nowrap` 的（四段时 0 条超宽）。所以另起一行。

`.poem-note` 写成 `display: flex; flex-wrap: nowrap` 而不是靠 `<text>` 的
行内特性：预览（`scripts/shots/render.js`）把每个 WXML 标签都编译成块级
`div`，写成行内的话截图与真机不一样，而截图正是看这一行的人唯一的尺子。
两段之间那一枚点由 `.poem-note-dot` 出两侧留白 —— WXML 里写「 · 」两端的
空白会被编译器吃掉，两段会粘成一句。

（`.pref-opt` 这个名字里带 `opt`，但 `check.js` 那条「不许自绘控件」的哨兵
盯的控件词里**没有 `opt`**：它太容易撞上别的东西，而这一行底层确实是原生
`<radio>`（藏在 `<label>` 里、走 `.opt-radio`）。真正守这件事的是
「一组 `.pref-seg` 里段数 = 原生 `<radio>` 数」那条 —— 丢一个 `<label>`
点整段就不选中，那条会红。）

宽度有三个读数，互相盯着：

```bash

node scripts/shots/prefs-width.js     # 量那一行在浏览器里到底多宽
```

| | rpx |
|---|---|
| 卡片内容宽 | 596 |
| 那一行（`prefs-width.js` 量出来的） | 见命令读数 |

2026-10-04 之前余量是 96，那 68 是被末尾那枚加号吃掉的（`44rpx` 的字 +

并且和 A- A+ 放在同一行」）。**余量这么薄，这一行已经满了**：再往里加任何

行宽用 `node scripts/shots/prefs-width.js` 量，真值就是它打出来的读数。
这条行宽不进自检 —— 界面尺寸不在断言里（见 AGENTS.md）；
量出来的数换了文案就该跟着变，写进自检只会让改一个词就红。

#### 量这件事时踩的两个坑（都记在 `prefs-width.js` 里）

1. **断言量的是它自己的假设，不是页面的事实。** 第一版把字号写成

   算式照样按 22 算、照样绿。现在字号从 `.pref-t` 自己那条 `font-size` 里读。
2. **先怀疑尺子，再怀疑排版。** 预览报过「那一行 595.5rpx、余 0，
   贴着边」—— 真相是预览把视觉隐藏的原生 `<radio>` 画成了 23px 的圆圈
   （真机上它是 1rpx，flex 排布里等于不存在）。补上 `render.js` 里
   那条镜像规则之后是 499。第二个跟头是**拿 `.prefs` 的盒子宽当行宽** ——
   它是 `flex:center`，被 `justify-content` 甩出来的空白不算进这一行，
   于是又量成 595.5。行宽是「两端之间的距离」，不是盒子有多宽。

### 「选一个」只有一套长相

这是 Issue #12 前后**反复栽过**的地方。之前同一屏里并存过**四种**说法：
原生圆点、一道左侧竖线、填色的底、填色的格子 —— 四种都在说
「这几个里选一个」。用户的原话是：

> 「取诗范围我看不出还包括单选框的必要性」
> 「不注音，生字和全文图标也是瞎画不对齐，选项也不统一」

现在收敛成**一套**。三种排布，**选中态完全一致：那一块填墨黑**。

| 排布 | 用在哪 | 类 |
|---|---|---|
| **分段控件**：合成一颗胶囊，选中的那段填墨黑。**一律撑满可用宽度** | 两三个互斥项（对齐 / 注音 / 难度 / 玩法） | `.seg` / `.seg-item` |
| **等宽格子**：一格一个方块，选中的填墨黑 | 等长的一堆（年级 / 学期 / 题型） | `.chip-group` / `.chip` |
| **选项行**：一样的格子、一样的缝，只差排法。横排（`.inline`，列数按最长的选项名挑 `cols-2` / `cols-4`，默认三列）或竖排（`.column`） | 背诵范围（七项，横排两列 —— 名字长，见上一节；旧名「取诗范围」） | `.opt-group` / `.opt-row` |
| **说明卡**：一整行，行里三行字（名字 + 年份 / 三条规则），选中的那行走主题色淡底 | 复习算法（四项，每项说自己怎么排期） | `.algo-group` / `.algo-row` |

四种**未选中的样子也一样**：白底 + 一道极淡的描边。
（上一版格子是「浅灰底 + 无描边」、选项行是「白底 + 描边」——
同一屏两种底，就是「选项不统一」的来源。灰底留给凹槽：输入框、图标底。）

**不该有圆点。** 圆点只在「没有别的选中标志」时才需要。
格子用填色说，分段用填色说，选项行却另起一个圆点说 —— 那就是第二种语言。
所以选项行里的原生控件现在是**视觉隐藏**的（`.opt-radio`），跟分段、格子一样。

**底层全是原生 `<radio>` / `<checkbox>`**（包在 `<label>` 里、视觉隐藏）：
点整段都选中、读屏读得到、键盘走得了。

#### 多选：一枚勾选框，且**只有选中才是重色**

「题型」这一类是**可多选**，而别处的范围 / 学期 / 年级是单选。
两者得看得出区别 —— 而这件事有**四版**，前三版都栽在**同一个地方**。

| | 做法 | 用户看到的 |
|---|---|---|
| 一版 | 墨黑胶囊 + 右上角一枚 14rpx 的小勾 | 「全填成墨黑胶囊，跟『选一个』的选中态长得一模一样，只看色块分不出哪个没勾」 |
| 二版 | 人人一颗双圈，内圈都填实 | 「选项怎么全部都是选中的重色？难道不是只有选中了才是重色吗？」 |
| 三版 | 白底 + 左侧一枚**空心**勾选框 | 「我不喜欢右侧方形选框，为什么不是未选中用灰色背景(和其他一样)，选中才是重色？」 |
| 现在 | **灰底** + 右侧一枚**空心**勾选框；选中才填主题色、才画勾 | —— |

前三版错在同一根上：**想用「填色」去说「能多选」**。
而填空是「选中」在全站的唯一说法，一旦用它表达别的意思，
未选中的格子也就成了重点 —— 这正是用户那句「难道不是只有选中了才是重色吗」。

用户第三版的判据给得很全，四条都照着落了：

| 他说的 | 落成什么 |
|---|---|
| 「未选中用灰色背景(**和其他一样**)」 | `--sink` —— 全站「这儿是个能按的槽」唯一的底（输入框、分段轨道、图标底都用它），不另造一层灰 |
| 「选中才是重色」 | 灰底写在 `.chip.multi:not(.on)` 上；**不许写进 `.chip.multi` 本体**（它排在 `.chip.on` 后面，会把选中那块主题色盖回成灰的） |
| 「右侧方形选框」 | 方框贴**右**内边距；名字左右对称让出同一块，仍在格子正中 |
| （三版把方框摆在左侧） | 左侧那版把名字推得不再居中，与上面那组单选格子的名字错开 |

现在：

| | 未选中 | 选中 |
|---|---|---|
| 单选（别处） | 白底 + 一道描边 | **主题色，实心** |
| 多选（`.chip.multi`） | **`--sink` 灰底** + 右侧一枚**空心**方框 | **主题色，实心**；方框填色并画上勾 |

所以单选与多选**未选中时**的差别只有两处：一格灰底、右边一枚方框 ——
两处都不是「填色」，所以「重色 = 选中」这条口径没被破。

勾选框是「可以几个都勾上」的通用长相（原生 checkbox 说的是同一件事），
而它**只在选中时才填色**。两枚伪元素画：`::after` 是那枚方框（边长 `--box`＝26rpx），
`::before` 是勾（两条边转 45°，`scale(0)` → `scale(1)`）。

两个细节是踩过才写下来的：

- **勾要抬一层**（`z-index: 1`）。两个伪元素挂同一格、又是同一层，
  按绘制顺序后画的 `::after` 会把 `::before` 整个盖住 ——
  白方框盖白勾，屏幕上就是一个空框。
- **居中要按旋转后的外接框退**。6×12 的勾转 45° 之后占的是
  `(6+12)×√2/2 ≈ 6.6` 见方，按 6×12 退会让勾贴在框的右上角、还被裁掉一角。

##### 题型名收成两个字

五种题型原来是四个字（接下句 / 接上句 / 认作者 / 填朝代 / 认篇名）。
它们是嵌在「题型 · 出自《…》」那一行读数里的 —— 四个字会把那一行顶到折行，
而且这一栏要回答的只是「这道题在问什么」，
「接下句」里那个动词是这一行给不出、也不必给的余量（下面是选项，选项自己会说话）。
2026-10-03 用户点名收短，落成：**下句 / 上句 / 作者 / 朝代 / 篇名**。

改的是 `utils/quiz.js` 的 `FORMS`（名字只有一个出处，界面不自已拼）。
五个名字都收成两个字。

##### 预览也会骗人：**这一处的一半是那把尺子**
页面写的是 `class="{{pickedForms.indexOf(item.key) >= 0 ? 'on' : ''}}"`，
而 `scripts/shots/wxml.js` 那层极简求值算不了 `indexOf` 这种成员调用，
于是每个格子都拿到 `undefined` → **一律画成勾上的**。
用户连着两轮看到的「怎么全部都是选中的重色」，一半是产品、一半是截图。
现在那一层补上了 `checkbox-group` 的语义（`multiPicker` / `findCheckedAttr`）：
组里那份清单就是「勾了哪几个」的出处，组内每格拿自己的 key 去比。
以后烘多选的截图，看到的才是真机上的样子。

多选那格的样子（`--sink` 灰底、方框在右侧、方框与勾共用一个 `--box`、
勾抬一层、名字两侧对称）由人看；只有「未选中那格与选中那格分得开」是
必须成立的结构事实。

> ⚠️ 不用原生 `<checkbox>` 的原因：它自带的高宽、描边、勾的粗细各机型都不同，
> 而这一屏里它要与单选格子并排对齐；伪元素则每一档缩放都跟着 `--ui-scale` 走。

### 破相是怎么来的（选项行在这里栽过两次）

1. **那道竖线**。选中态曾是 `inset 6rpx 0 0 var(--ink)` —— 一条贴左的竖线。
   inset 阴影**不参与圆角裁切的外沿**，而这一行有 `border-radius`：
   圆角把竖线的上端切掉一个斜口，下端也被切 ——
   屏幕上就是一根上不接顶、下不接底、左上还有豁口的黑条。
   现在不画竖线了：整块填色本身就说明了「这一行」。
2. **选中与未选中的左右起点不一样**。行曾加过 `margin: 0 var(--sp-1)`，
   而同一张卡里的格子没有 —— 于是「学期/年级」和「取诗范围」的左边缝差 8rpx，
   竖着扫下来就看得出错位。现在两者都归零。

### 图标：同一份网格

`不注音 / 生字 / 全文` 这三枚，用户说「瞎画不对齐」。上一版确实各画各的 ——
圆的溢出比方的多，光学中心不在一条线上，并排看着就是「不对齐」。

现在定一份网格，所有图标都长在它上面：

| 规矩 | 值 |
|---|---|
| 画布 | 24 × 24rpx，图形内缩 2rpx（留出光学边距） |
| 线宽 | 2.5rpx，只有这一种；圆角端点 |
| 混用 | 描边类与实心类不混；一个图标要么全描边、要么全实心 |
| 配色 | `currentColor` —— 段选中时整段变白，图标跟着白，不用改三处 |

三枚「注音」共用一个母题（**一个字 + 它头上的拼音**），差别落在「有几个」上：

- **不注音** —— 一个「字 + 拼音」被圆圈加斜杠划掉
- **生字** —— 只有**一个**，右边空着一大块
- **全文** —— **三个**一路排到底，一点都不空

第一版我给「全文」画了三道横线 —— 那正是 `.ic-left` 的样子，
同一屏里并排出现就是「瞎画」的观感来源。所以母题换掉了。
「全站」（地球）也一样：只画圆加一道横线会读成「⊖（禁止）」，
必须把**经线**也画出来才像球。

### 尺寸只有一个旋钮

用户要的是「使用他们默认的但是**小一号**的全局配置」。
这句话真正的关键不是抄哪个库的类名，而是**所有尺寸必须能从一处调小**。

`styles/tokens.wxss` 定了 `--ui-scale`，字阶 / 间距 / 圆角 / 高度
**全部由它算出来**：想让全站小一号，改这一个数（例如 `.9`），整条体系一起收 ——
不用动任何页面。`check.js` V19 守着「这几组令牌必须乘 `--ui-scale`，
且页面不许重新定义共享令牌」。

默认是 `1`：这一版的尺寸是按 750 设计稿、在小屏上验证过的，
再统一缩一次会先撞到触控下限（88rpx ≈ 46px，再缩就不够指头点）。
所以这个旋钮是给「小屏 / 大字号系统」这类场景用的，不是默认值。

### 几毫米的规矩

| 事 | 补在哪 | 为什么不能各页自己补 |
|---|---|---|
| 选项与文字的间距 | `app.wxss` 给 `<radio>` / `<checkbox>` 自己上 `margin-right` | 原生控件不带外边距 —— 紧贴是浏览器的排法，不是控件的排法 |
| 按钮文字垂直居中 | `.btn` 用 `flex + align-items:center` | 原生 button 的默认行高由平台按字号算，和页面给的 `height` 对不上就偏 |
| 并列按钮一样高 | `.actions` 显式 `align-items:center` | flex 默认 `stretch` 遇上固定 `height` 会退化成基线对齐 |
| **要定尺寸的原生 button（头像那枚）** | 尺寸只定在**外层的壳**上（`.avatar-wrap`，`position:relative` + `overflow:hidden`），壳里那两样（button 与头像本体）一律 `position:absolute` 贴满它、尺寸写**字面量** | 原生 button 有两条自作主张的默认，2026-10-04 各踩了一次：① 自带 `display:block` 与 `width:100%`，真机上盖过页面样式表给的 `width` —— 写 `width:112rpx` 不生效，被撑成一行宽，叠上 `border-radius:50%` 就是一枚扁椭圆；② 它里面**解析不了 `height:100%`** —— 把尺寸挪到壳上之后，宽度那条链活着、高度那条断在 button 上，里面的 `<image>` 于是按**自己那张图的固有比例**排高度（横构图排成一根横条），又是一枚扁椭圆，`aspectFill` 再取中段，看着就是「只显示了左侧一点」。绝对定位 + 字面量把两条默认一起绕开。V50 守着 |
### 底栏：自绘，因为原生只认图片

用户原话：「导航栏几何按钮明明文字上面有图标的，现在好像没有，例如 我的」。

原生 `tabBar` 的图标只能是**图片文件**（`iconPath` / `selectedIconPath`），
所以底栏整条自绘：`app.json` 里 `"tabBar": { "custom": true }`，
组件在 `custom-tab-bar/`。

形状照参考图：一枚图标在上、一行小字在下；**选中的那一项图标嵌进一块
主题色淡底**（`--strong-soft`），图标与文字取主题色（`--strong-text`）。

图标是 SVG，源文件在 `miniprogram/icons/`，`scripts/build-icons.js` 把它们
压成 **base64** data URI 写进 `miniprogram/utils/icons.js`（构建产物，`check.js` 不查在不在）。
**一条图片资源都不引**：data URI 不进包外，也就不必多套倍图。
五枚里四枚来自 `icons/`，搜索那一枚是照着同一份网格补画的（用户没给）。

图标**不上 `<image>`，走 `mask`**：`.tab-ico-mask` 拿 data URI 当 `mask-image`，
`background-color: currentColor` 取色。`currentColor` 在 `<image src>` 里拿不到
（data URI 是一张独立的图，页面继承色不会进去），在 mask 上却是现成的：
`.tab` 给 `color: #9ca3af`、`.tab.on` 给 `color: var(--strong-text)`，
一枚图两态，不必两张图切 `visibility`。

`mask-image` 这份 data URI 必须是 **base64**：`%3Csvg%3E` 那种 URL 编码的
小程序不认，真机上整片空白（Issue #262 —— 之前在浏览器预览里是好的，
预览把 `src` 当普通 `<img>` 画，所以一直没发现）。

「大会」那一项不是 tab 页，是 `navigateTo` 进大会分包 —— 底栏停在原页，
回来看那一栏还亮着。所以 `custom-tab-bar` 的每一项多带一个 `noSwitch`：
`switchTab` 与 `navigateTo` 在同一个 `onTap` 里分流。

**去 tab 页一律走 `switchTab`，出口只有一个**（`utils/tab-page.js`）。
微信这条规矩很坑：`navigateTo` 跳 tab 页是**静默失败** —— 不报错、不跳转、
`fail` 也不回调。于是「点登录去『我的』」写出来就是
`wx.navigateTo({ url: "/pages/mine/mine?login=1" })`，看着天经地义，
实际是死链（Issue #195，全站曾有 16 处这么写）。

`tab-page.js` 只两件事：`go(url)` 切 tab、`mine()` 去「我的」。
不需要 `login()` 这种包装 —— 「我的」页第一张卡就是登录入口，
切过去就够了，不必再替用户点一下。

底栏那三项要登录的（课外 / 搜索 / 大会）在未登录时**都切「我的」**，
不 render 一张 `lock-card`：门禁页摆在 tab 位上，用户点一次就多一层要退。
「大会」与其他两项的区别只在登录之后 —— 它 `navigateTo` 进分包，不是 tab 页。

自绘的**代价**要说清：高亮不再由平台管 —— 每个 tab 页 `onShow` 里要调一次
`tabbar.sync(this, n)`，否则切过去还亮着上一栏。这一步 V19 按事实守着
（每页各调一次、序号各不相同、每页都留了 `.has-tabbar` 垫片）。

#### 圆底不能填主题色本体

第一版是「选中 = 填墨黑圆底 + 白图标」，换主题后圆底跟着变 `--strong`。
那枚图标走 `mask` + `background-color: currentColor`，而它压在圆底上 ——
圆底与图标同色，图标整个消失（Issue #262）。

现在底下那层是 `--strong-soft`（主题色 5% 的淡底），同一条 `currentColor`
拿来当图标色也读得出来：主题色与它自己的淡底之间隔着 20 倍的白，
不会糊成一块。**深色主题上「选中」靠的是淡底 + 文字加粗，不靠填色** ——
淡底在白栏上只有 1.1:1，所以选中的记号主要由字重与颜色承担。

### 头像：只有微信一个来源，且只落本机

用户 Issue #111 的原话：

> 当用户登录后，直接使用小程序微信账号的头像吧，不要再提供用户自己上传头像的
> 功能了，也许能节省对象存储或者静态资源存储

落成一条**没有优先级可言的**规则：

```
微信头像（chooseAvatar 给你的那一张）  →  昵称首字印
```

**这一节原来不是这样。** 原来有三个来源、一条优先级
（`avatarLocal`（自己传的）→ `avatarUrl`（微信那张）→ 首字印），
因为 Issue #12 那一轮要的是「她自己能在设置里换头像」。
Issue #111 把「用户自己上传」整条路收掉了 —— 于是来源只剩一个，
那两个字段、那条优先级、以及「从自己那张退回微信那张」那个动作
**一起退场**（少一个来源就少一整层分支，不是「留着以后可能有用」）。

#### 为什么不能「登录后自动拿到微信头像」

这是这一整节里唯一需要解释的技术事实：

1. **平台没有任何一条「静默拿微信头像」的 API。**
   自 2022 年起 `wx.getUserProfile` 只返回匿名「微信用户 + 灰头像」，
   调用它等于糊一张假图到用户脸上。唯一合规的路是 `open-type="chooseAvatar"`
   —— 用户点一下，弹出来的第一项就是**当前微信头像**。
   所以「登录后直接用微信头像」落成的样子是：
   **头像圆点一下 = 微信那张**，而不是「不点也能自动拿到」。
2. **它给回来的是一枚临时文件路径**（`wxfile://…`）。那是**这台机器上的**东西：
   换台手机打不开，服务端的 `sanitizeImgUrl` 也只收 `https://` 与 `/api/avatar/`。
   要让它跨设备，就必须先把它**上传到某处** —— 而那正是「养一份对象存储」。

#### 所以头像只落本机、不上传

```
选头像（chooseAvatar）
  → store.profile().avatarLocal = 那枚临时路径
  → 只写 wx.setStorageSync，**不进同步报文、不上传**
```

- 换台手机：头像**不在**（这是刻意的，不是 bug）——
  真要它在，就得养一份对象存储，而 Issue #111 要的正是别养。
- 没选过：显示昵称首字印，**不拿灰头像冒充**。
- **首字印不画在原生 button 里**（Issue #194）：`open-type="chooseAvatar"` 那个 button
  只包住 `<image>`，首字印是与它并列的一层，走自己的宽高字面量与圆角。
  真机上原生 button 里的盒模型跟页面样式表对不上（`height:100%` 解析不出来），
  灰底会排成「只看得见左侧一点」的扁椭圆。判据见 V50。
- 副题只说「我是谁」（`已登录 · 微信账号`），不再解释这张头像哪来的 ——
  只有一个来源，说来源等于说一句用户不需要懂的话。

**入口仍只有一处：头像那个圆自己。** 用户 2026-10-04 的那句话依然成立
（「换头像那一行也是多余…直接点击上面的头像就可以编辑或者更换头像不行吗？」），
只是那个圆现在给的就是微信那张。
「用微信头像」这个动作**已撤** —— 它是「从自己传的那张退回微信那张」，
没有「自己传的那张」，它点了不会有任何变化。

#### 登录后多问一次：要不要用微信的（Issue #194）

「登录后自动有头像」做不到（上面第 1 条），但用户看不懂技术理由，
于是登录后第一次进「我的」页时，身份卡下面多一条**一次性的引导**
（`.grant-lead`）：一句话说明「点头像挑微信头像、点名字那一格确认微信昵称」，
旁边一枚「先不用」。

- 判据是「没选过头像、昵称还是默认值」—— 两样都填过就不再问。
- 三件事任意一件都会把它收掉：选了头像（`onAvatarChoose`）、
  自己改了昵称（`onNickname`）、点了「先不用」。
  三条路都写同一个 `identityAsked` 标记，所以不会反复弹。
- 用户没同意就什么都不做：头像继续是首字印、昵称继续是默认值 ——
  「保留现状」指的就是这个，不是把灰头像糊上去。

V22 守着：`avatarSrc()` 只认本机那一张、`avatarUrl` 字段整个退场、
登录不写头像、页面一律走 `store.avatarSrc()`、不再出现 `getUserProfile`。
V39 守着撤干净的这几处，并**反着守一条**：选完头像不许 `markDirty`、
不许有 `wx.uploadFile` / `/api/avatar` —— 一旦有人把上传通道加回来，
就又要为它养一份对象存储。

## 六、为什么没有引 ColorUI 这类组件库

用户两次问过这件事：

> 「看看是否使用某一种小程序 UI 组件，例如 ColorUI，或者有没有更好的可以使用」
> 「要不还是使用第三方小程序 UI 组件吧，使用他们默认的但是小一号的全局配置，例如 colorUI，各组件样式统一」

**结论：不引组件库，但把它真正有价值的那两件事自己做掉了。**

### 为什么不引

| 说它不行的地方 | 实情 |
|---|---|
| 它解决不了你的问题 | 你说的是「选项不统一 / 图标不对齐 / 选中态看不出」。这些是**这一套控件的长相**问题，不是「缺控件」。ColorUI 给的是「一个 cu-btn 长什么样」，换成它以后同类问题照旧 —— 你还是得为「取诗范围该用哪档」做一遍决定 |
| 它自己的控件不是原生的 | ColorUI 的按钮、卡片多是 `<view>` 拼的，会把原生 `<button>` / `<radio>` 的行为（无障碍、键盘、读屏、`open-type`）绕开。本项目从第一版就守着「控件一律用系统的」 |
| 两套命名会打架 | 它的 `.cu-*` 体系会和这里 `.card` / `.btn` / `.seg` 的语义撞车，最后是「哪一套优先」的日常判断 —— 这种事一次解决不完 |
| 体积 | 主包余量只剩几百 KB（正文分片与索引都走云端）。整个组件库进来要先切掉一大半用不到的，剩下的维护成本归你 |
| 维护 | 它的更新节奏与小程序基础库不同步。一旦某个组件在新基础库下表现变了，你得自己进库改 —— 那时它就是**你自己的代码**，只是你没有它的设计文档 |

### 为什么「有更好的」也未必更好

换任何一个库，都要重做一遍**已经做对的事**：
篇名宋体（内容需求，与配色无关）、能力不可用时不渲染、触控高度下限 88rpx、
预览工具与 700 多项自检。这些是**这个项目的规矩**，组件库不提供，
换了库还得自己搬一次。

### 真正该学的两点，已经落地

用户那句「**默认的但是小一号的全局配置**」里，藏着组件库唯一真正值钱的东西：

1. **一套能整体缩放的尺寸体系** —— ColorUI 靠一颗根字号；
   这里靠 `--ui-scale`（见第五节「尺寸只有一个旋钮」）。**改一个数，全站小一号。**
2. **组件只有一份实现** —— 分段 / 格子 / 选项行、卡片、按钮、标签，
   都只在 `app.wxss` 定一次，页面取类名。
   `check.js` V13 / V19 守着「同一件事不许写第二遍」。

换句话说：**要的是「统一」，不是「第三方」。**
统一是靠「只有一个出处 + 一条断言」守出来的，不是靠引一个包。

### 背诵进度页：四块读数，四种形状（Issue #252）

这一页原来是「一枚环 + 三个大数字 + 未来七天一列」，与网页版 `/progress` 差得远。
现在补齐到**四块**，每块换一种长相 —— 因为四块读的是四件不同的事：

| 块 | 它在回答 | 形状 | 不这么做的理由 |
|---|---|---|---|
| 概要 | 我背得怎么样 | 环 + 四个大数字 | 大数字一屏只该有一组（照旧） |
| 到期日历 | 哪天有活儿、哪天空 | 七格柱状，柱高按**当天峰值**归一 | 七格同日历一样横向排，一眼扫出轻重；换成列表就没有「形状」可看了 |
| 全部到期篇目 | 到底是哪几首 | 按天摊开的一行一首 | 这是**名单**，不是读数；点一行就地开背诵弹层 |
| 掌握度分布 | 背到什么成色 | 五档横条 | 分档是连续的（0→100%），条长天然表达「多与少」 |

四条约束：

- **四个数字，不是三个。** 第四格是**平均掌握**，不是网页版的「尚未学过」：
  未学的数从「已学 / 总篇目」里读得出来，而「平均掌握」是这一页唯一
  能说「背到什么成色」的那个读数。
- **柱高按当天峰值归一，条长按本档峰值归一**，都留一个 `5%` 的地板 ——
  有一首与没有一首要分得开，而「只有一首」不该是一根看不见的线。
- **零那一档压一档透明度**（`.bar-row.zero`），不换色。用灰说「没有」，
  用主题色说「有多少」。
- **条与柱子走 `--strong`，逾期走 `--amber`**。前者是重点色，后者是状态色，
  与全站那条线一致（见第二节）。

`check.js` 守的是**结构事实**：四块读数都在、都走 `S.overview` / `S.dueList`、
点得开背诵弹层、条的形状与配色走令牌。柱子多高、条多长、字号多大，由人看。

## 八、这一版没动的两条

推倒重来时，有两件事是**项目真正立得住**的，保留了：

1. **篇名一律宋体** —— 内容需求，与配色无关。
2. **能力不可用时不显示** —— 注音 / 全文检索 / 答题音效 / 同步进度。
   **能力压根没有**时整块不渲染，连位置都不占 ——
   一个点不动的按钮、一张写着「待开通」的卡，比没有更糟。
   判定一律走 `readiness()`，它返回 `visible` / `usable` / `state` 三个值。

   > 把正文读出来是这条规矩最早的例子：它后来整个不做了（个人主体拿不到
   > 平台那支插件的授权），代码与界面都撤干净 ——
   > 留一张写着「待开通」的卡比没有更糟。见 `docs/todo.md` 第 1 条。

## 九、文案：能短就短，别在选项下面讲课

用户 2026-10-02 的两句话：

> 「所有选项，所有按钮，尽量使用精简语言」
> 「更不要在各个选项，设置，卡片下面显示各种婆婆妈妈的解释性提示」

这条规矩和色、字、形一样硬，因为它**最容易被顺手破掉** ——
写一行小字解释「为什么这样」，每一句单看都是在如实交代，
合起来是把界面读成一篇说明书，而用户要的是「看得懂就点」。

**三条落地判据**（`check.js` V18 守着，每条都做过反证）：

| 判据 | 线 |
|---|---|
| 卡片 / 选项 / 按钮下面的说明文字 | 超过 **24** 字就报红（读数类 18 字） |
| 按钮文案 | 不超过 **12** 个可见字 |
| 页头那行 `head-sub` | 能不写就不写；要写只写**读数**，不抄这一页有什么 |

**读数 ≠ 解释。** 「这个范围里有 12 首」「共 10 题 · 限时 20 分钟」
「已掌握 3 / 已学 12」是事实，留着；「本册 = 本学期」是标签的同义改写，删掉；
「篇名作者搜的是索引字段；正文全文走倒排索引，先定位相关分片再精确定位」
是原理说明，它属于 `architecture.md`，不属于界面。

**空状态与出错说明是例外**：没有它，「没有」和「没加载出来」分不清。
但也要短 —— 「还没有背诵记录」，不是「您目前尚未产生任何背诵记录，
请回到首页开始您的第一次背诵之旅」。

### 别跟用户说「数据存在哪」（Issue #49，2026-10-04）

用户的原话：

> 「为什么叫 **本机数据**，没有人关心或者需要知道这个数据在本机还是云端，
> 你显示这个对用户来说完全不可理解。排查所有类似的问题，这是微信小程序场景。」

他说的是文案，不是某一页。`本机 / 云端 / 服务端 / 后端 / 离线` 这一组词
是**实现词汇** —— 它们描述数据放在哪，而用户的问题是「我背得怎么样、
换手机还在不在」。要求用户先懂这套架构，才看得懂自己那一屏，是把成本转嫁给他。

| 原来 | 现在 | 为什么 |
|---|---|---|
| 本机数据 | **背诵进度** | 这一格说的是「我背得怎么样」，存哪儿是系统的内务 |
| 云端同步 | **同步进度** | 「换手机还在不在」才是用户要的那件事 |
| 清空本机数据 | **清空背诵数据** | 清的是内容，不是存储位置 |
| 本机记录 | **背诵记录** | 同上 |
| 已登录（本机身份） | **已登录** | 「本机身份」是内部状态的两档，用户不必懂 |
| 后端未就绪 · 已攒 N 条 | **换手机进度不跟随 · 点一下重试** | 说事实（会丢），并给一条出路（点一下） |
| ~~本机设置的头像~~ | ~~自己设的~~ | 已撤（Issue #111）：头像只有一个来源，不再需要区分「谁定的」 |

**唯一的例外是隐私政策。** 「不登录时一切只在这台手机上，登录后只把背诵记录同步到
服务器」这一类要原样留着 —— 那不是实现词汇，是用户**有权知道**的事实，
而且是他判断「要不要登录」的依据。现在它在独立一页里（「我的 → 隐私政策」），
不再挤在弹窗里。

这条由人守：「本机 / 云端 / 服务端 / 后端 / 离线」只出现在注释、文档与
`utils/` 的实现里 —— 那是给我们自己看的，不进用户看得见的句子。
自检不扫文案（见 AGENTS.md）；早期那种「五个词撞见就红」的全站扫描已撤。

#### 顺带揪出来的一个真 bug

改这条时发现「我的」页那一行的读数**从来没对过**：
`sync.state()` 读的是 `store.settings().lastSyncAt`，而 `settings()` **只投影
`DEFAULTS` 里有的键** —— `lastSyncAt` 不在里面。于是它写进去了、`read()` 也读得到，
`settings().lastSyncAt` 却**恒为 undefined**：同步成功多少次，那一行都说「还没同步过」。

没有任何报错，因为两个函数各自都对。预览那边也一直在打配合的假：
`pages.json` 的 `syncedAt` 就是往这个键写的，而那屏拍出来照样是「还没同步过」，
谁也没觉得不对（图在、字对、状态是错的）。

修法：`lastSyncAt` 进 `DEFAULTS`。判据不查「字符串在不在」，而是**真跑一遍存取** ——
存进去、投影出来，读不到就红。

## 十、改界面时怎么「看见」

```bash
# 1. 先把语料编译出来（数据不入库）
node scripts/build-data.js

# 2. 出预览页
node scripts/shots/render.js

# 3. 逐屏截图到 scripts/shots/out/shots/
node scripts/shots/shoot.js            # 全部 26 屏
node scripts/shots/shoot.js reader     # 只截名字里含 reader 的

# 4. 自检
node scripts/check.js
```

**它不是真机**：布局、配色、文案、显隐口径是真的；原生控件外观、字体回退、
安全区是近似的。改完先在这儿看一遍，再去开发者工具过。

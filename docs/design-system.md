# UI 设计规范

这一版是 Issue #12 之后**重做**的一版：上一版那套「宋代传统色 / 纸纹 / 印泥」
整份撤掉，按用户给的参考图重定。

规矩写在 `miniprogram/styles/tokens.wxss` 与 `app.wxss` 里，
`scripts/check.js` 的 **V13 一节**守着它们 —— 下面每一条都有对应的断言。

---

## 一、这一版为什么推倒重来

上一版不难看，单看每一块都说得过去。它的问题是**靠颜色和装饰区分「这是什么」**：

| | 上一版 | 这一版 |
|---|---|---|
| 分层 | 纸纹 + 底色差 + 卡片投影 | 只靠**留白**与一道极淡的描边 |
| 主色 | 八种身份色（背诵墨绿 / 复习琥珀 / 忘记朱砂 / 大会青碧……） | **一种**：墨黑 |
| 表达重点 | 主色卡 + 金边 + 印章，一屏好几处在喊 | **大数字**，一屏只有一组 |
| 圆角 | 四档（16 / 20 / 24 / 999） | 三档（14 / 20 / 24 / 999） |
| 字阶 | 十档（22 → 104rpx） | 六档 |

一句话：**先做减法，再谈风格。**

## 二、色

### 主色只有一处

```css
--ink: #1c1c1e;   /* 墨 · 主色与正文 */
```

它不是「黑色这个颜色」，是「这里是重点」这件事本身。参考图里按钮、选中态、
头像底、底栏当前项，全都是一块干净的黑。

所以：**一屏里填黑的地方只该有一处。** 首页是「开始背」，详情页是「记住」，
设置页是选中的那一格。

### 层次只用三档灰

```css
--bg:      #f5f5f7;   /* 页面底 */
--surface: #ffffff;   /* 卡片面 */
--sink:    #f2f2f4;   /* 凹槽：输入框、未选中格子、图标底 */
--line:    #ececef;   /* 卡片边 */
--line-2:  #f4f4f6;   /* 卡片内的行分隔 */
```

上一版有四个「浅色」（`--card` / `--card-2` / `--bg-soft` / `--bg-sink`），
彼此差 1~2% 明度 —— 手机屏上看不出来，只会让「我该用哪一个」变成每天要重猜一次的问题。

### 状态色只表达状态，不表达身份

```css
--green: #2e7d5b;  /* 成功、已读、完成、答对 */
--amber: #b26a00;  /* 提醒、待办、复习、逾期 */
--red:   #c0392b;  /* 危险、忘记、删除、答错 */
--blue:  #2f6f9f;  /* 信息、新学 */
```

上一版它们是「复习用琥珀、大会用青碧」这种**按页面分派**的身份色，一个颜色管一摊事。
现在它们只回答「这件事是什么状态」。

`check.js` 里有两条守着：主色必须是中性墨黑（三通道接近且够深），
以及**上一版那八个身份色不许回到页面样式表里**。

## 三、字

### 篇名用宋体，界面用系统黑体

这条是**内容需求**（诗词要像诗词），不是装饰，所以它从上一版留了下来。

```css
--font-poem: "Kuibu Serif", "Songti SC", …, serif;
--font-ui:   -apple-system, "PingFang SC", …;
--font-num:  -apple-system, "SF Pro Display", …;   /* 数字 */
```

「先系统、后外挂」的两层策略没变，做法见 README 的「篇名宋体」一节。

### 字阶只有六档

```
--fs-caption 22  脚注、单位
--fs-hint    25  说明、次级信息、标签
--fs-body    29  正文、列表副题
--fs-title   32  列表标题、字段名、按钮
--fs-lead    38  页头、卡片主标题
--fs-hero    46  一屏只有一处的大标题
```

另有四个「一屏只出现一次」的：`--fs-stat`（统计大数字）、`--fs-score`（考试分数）、
`--fs-brand`、`--fs-mark`。

**页面样式表里出现裸 `font-size: 27rpx` 就是漏了令牌** —— V6.5 守着。

### 行高三档

```
--lh-tight 1.3   标题
--lh-body  1.65  正文
--lh-loose 1.9   需要放开读的（空状态、说明）
```

### 数字一律等宽

`--font-num` + `font-variant-numeric: tabular-nums`。
「24」「3」「58」三个数并排，用比例数字会左一个右一个；`0/5` 换成 `4/5` 时也会跳。

## 四、形与距

```css
--radius-sm    14rpx   行内小块：标签、小按钮
--radius       20rpx   卡片 —— 全站一种
--radius-block 24rpx   大块：主按钮、输入框
--radius-pill  999rpx  胶囊：按钮、标签、分段、头像
```

投影只有两层，且都很淡。**「一屏里最该先看的那张卡亮一点」这件事，这一版交给留白做。**

间距八档（8 / 16 / 24 / 32 / 48 / 64 + `--page-x` 28rpx）。
留白是这一版唯一用来分层的手段，所以稀疏的一侧留得比上一版大。

## 五、控件规范

### 「能点的那一块」只有三档高度

```
--h-btn      96rpx   主按钮：一屏最多一两个，是这一屏的正事
--h-btn-mini 60rpx   小按钮：一行里的小动作
--h-act      96rpx   动作块：「忘记 / 模糊 / 记住」这类平铺动作
--h-row      96rpx   列表行
--h-field    84rpx   输入框、搜索框
```

「点着舒服」的下限是 88rpx（≈46px，略宽于 iOS 的 44pt 目标）——
往上是浪费，不是体贴。**按钮高度不许各页写死**，V11 守着。

### 控件用系统的，只换一张脸

开关 / 单选 / 多选 / 滑动条 / 选择器 / 按钮全部走小程序自带控件：
行为、无障碍、键盘与读屏由平台保证。

原生控件的交互色只能通过组件属性给，取不到 WXSS 的 `var()`，
所以它注定要在 WXML 里写死一次 —— 那就钉在一处：`#1c1c1e`（即 `--ink`）。

「选一个」有三种长相，各有各的场合：

| 场合 | 长相 | 为什么 |
|---|---|---|
| 两三个互斥选项（对齐 / 注音 / 在哪儿搜） | **分段控件**：合成一颗胶囊，选中的那段填墨黑 | 一排圆圈两个选项就占半屏；选中态只有「圈里多一个点」，扫不出来 |
| 等长的一堆选项（年级 / 学期 / 每日首数 / 题型） | **格子**：一格一个胶囊，填色说选中；多选那格右上角多一个方框 | 圆点吃掉横向空间，还只跟第一行文字对齐、第二行缩进 |
| 令字格（飞花令挑令字） | 格子自己的底色 + 描边 + 字变色 | 缩到 0.56 的圆点看不出能点，还压在笔画上 |

**底层全是原生 `<radio>` / `<checkbox>`**（包在 `<label>` 里、视觉隐藏）：
点整段都选中、读屏读得到、键盘走得了。

### 几毫米的规矩

| 事 | 补在哪 | 为什么不能各页自己补 |
|---|---|---|
| 选项与文字的间距 | `app.wxss` 给 `<radio>` / `<checkbox>` 自己上 `margin-right` | 原生控件不带外边距 —— 紧贴是浏览器的排法，不是控件的排法 |
| 按钮文字垂直居中 | `.btn` 用 `flex + align-items:center` | 原生 button 的默认行高由平台按字号算，和页面给的 `height` 对不上就偏 |
| 并列按钮一样高 | `.actions` 显式 `align-items:center` | flex 默认 `stretch` 遇上固定 `height` 会退化成基线对齐 |
| 同级文字的字号颜色 | `field-label` / `card-title` / `hint` 只在 `app.wxss` 定一次 | 两个类干同一件事、字号差 3rpx，同页出现就露馅 |

## 六、组件清单（`app.wxss`）

| 类 | 用途 |
|---|---|
| `.card` / `.card-title(.bar)` | 卡片与卡内小标题 |
| `.btn` / `.btn.primary` / `.btn.ghost` / `.btn.mini` / `.actions` | 三档按钮 + 并列行 |
| `.stats` / `.stat` / `.stat-v` / `.stat-k` | **统计大数字**（参考图里最抓眼的那组） |
| `.row` / `.row-title` / `.row-sub` / `.row-icon` / `.row-go` | 列表行（带行首图标底） |
| `.tag`（`.amber` / `.red` / `.blue` / `.green`） | 状态胶囊 |
| `.seg` / `.seg-group` / `.seg-item` | 分段控件 |
| `.chip-group` / `.chip`（`.multi`） | 等长选项格子 |
| `.search` / `.field` | 输入 |
| `.kv` | 键值行 |
| `.meter` / `.ring` | 进度：一横一竖 |
| `.empty` / `.empty-mark` | 空状态（必带印章与出路） |
| `.lock-card`（组件） | 未登录那一道门（全站唯一一份） |
| `.section-label` | 分隔一组卡片的小标签 |

**统计大数字只有一套实现。** `check.js` V13 守着 ——
页面里再定义一个 `.num-v` 那样的「又一个统计数字」就报红。

## 七、这一版没动的两条

推倒重来时，有两件事是**项目真正立得住**的，保留了：

1. **篇名一律宋体** —— 内容需求，与配色无关。
2. **能力不可用时不显示** —— 注音 / 全文检索 / 答题音效 / 云端同步。
   **能力压根没有**时整块不渲染，连位置都不占 ——
   一个点不动的按钮、一张写着「待开通」的卡，比没有更糟。
   判定一律走 `readiness()`，它返回 `visible` / `usable` / `state` 三个值。

   > 朗读是这条规矩最早的例子，现在连那两档都不留了：TTS 通道个人主体
   > 申请不下来，用户裁决不做，界面里**一处朗读元素都没有**。
   > 见 README「朗读：不做，界面上也没有」。

## 八、文案：能短就短，别在选项下面讲课

用户 2026-10-02 的两句话：

> 「所有选项，所有按钮，尽量使用精简语言」
> 「更不要在各个选项，设置，卡片下面显示各种婆婆妈妈的解释性提示」

这条规矩和色、字、形一样硬，因为它**最容易被顺手破掉** ——
写一行小字解释「为什么这样」，每一句单看都是在如实交代，
合起来是把界面读成一篇说明书，而用户要的是「看得懂就点」。

**三条落地判据**（`check.js` V18 守着，每条都做过反证）：

| 判据 | 线 |
|---|---|
| 卡片 / 选项 / 按钮下面的说明文字 | 超过 **24** 字就报红（读数类 18 字） |
| 按钮文案 | 不超过 **12** 个可见字 |
| 页头那行 `head-sub` | 能不写就不写；要写只写**读数**，不抄这一页有什么 |

**读数 ≠ 解释。** 「这个范围里有 12 首」「共 10 题 · 限时 20 分钟」
「已掌握 3 / 已学 12」是事实，留着；「本册 = 本学期」是标签的同义改写，删掉；
「篇名作者搜的是索引字段；正文全文走倒排索引，先定位相关分片再精确定位」
是原理说明，它属于 README，不属于界面。

**空状态与出错说明是例外**：没有它，「没有」和「没加载出来」分不清。
但也要短 —— 「还没有背诵记录」，不是「您目前尚未产生任何背诵记录，
请回到首页开始您的第一次背诵之旅」。

## 九、改界面时怎么「看见」

```bash
# 1. 先把语料编译出来（数据不入库）
git clone --depth 1 https://cnb.cool/npu-gpu-cpu/poem.git /tmp/poem
POEM_WEB_DIR=/tmp/poem node scripts/build-data.js

# 2. 出预览页
node scripts/shots/render.js

# 3. 逐屏截图到 scripts/shots/out/shots/
node scripts/shots/shoot.js            # 全部 26 屏
node scripts/shots/shoot.js reader     # 只截名字里含 reader 的

# 4. 自检
node scripts/check.js
```

**它不是真机**：布局、配色、文案、显隐口径是真的；原生控件外观、字体回退、
安全区是近似的。改完先在这儿看一遍，再去开发者工具过。

# 虚拟支付配置步骤（Pro / Max 购买）

前提：小程序主体为个人、服务类目含「工具」、已认证备案，且已在 MP 后台开通虚拟支付。
个人主体全终端月支付限额 10 万元；Android 费率 1%（T+3），iOS 12%（约 45–60 天）。

## 1. MP 后台：虚拟支付 → 基本配置

记下三项：AppID、OfferID、**现网 AppKey**（密钥，不入库、不进截图）。
要用 iOS 支付：先配置小程序简称，再开通苹果 IAP。

## 2. MP 后台：虚拟支付 → 道具管理

建好并**发布**四个道具，ID 与价格逐字对上服务端价目表（默认值）：

| 道具 ID | 价格 |
|---|---|
| `pro_month` | ¥12 |
| `pro_year` | ¥98 |
| `max_month` | ¥25 |
| `max_year` | ¥198 |

价格与 MP 后台不一致时，微信会拒绝该笔支付。

## 3. 云托管：环境变量

「服务设置 → 环境变量」新增三项，保存后**重新部署**：

```
WX_PAY_OFFER_ID=<OfferID>
WX_PAY_APPKEY=<现网 AppKey>
WX_PAY_PUSH_TOKEN=<自拟的随机串，如 openssl rand -hex 16>
```

缺任一项，下单回 `503 E_PAY_NOT_CONFIGURED`，其余功能不受影响。

## 4. 数据库：建 `pay_orders` 表

执行 `deploy/sql/mysql-schema.sql` 中 `pay_orders` 那一段（见 [`wx-cloud-setup.md`](wx-cloud-setup.md) § 四，先切库再执行）。

## 5. MP 后台：发货推送配置

- 路径：`/api/pay/notify`（GET 用于校验，POST 接收推送）
- Token：与 `WX_PAY_PUSH_TOKEN` 完全一致
- 消息格式：**JSON**（服务端不解析 XML）
- 接收方式：优先选后台提供的「云托管」接收并指向本服务；否则填服务的公网访问地址。

## 6. 更新镜像与小程序

改动涉及 `api/**` 与 `deploy/**`，须合并后让流水线重出镜像并在云托管发布；
小程序端发体验版（[`wx-cloud-setup.md`](wx-cloud-setup.md) § 八点五）。

## 7. 上架前验证

1. 管理员登录 →「我的 → 后台管理 → 支付与价格」，确认四个档位的生效道具与价格正确。
2. 用普通微信账号在「我的 → 用户权限 → 开通 Pro / Max」下一笔小额真单。
3. 支付后立即升档；「支付记录」里出现该单，状态为已支付。
4. 后台「购买记录」里同一笔带 uid、openid、业务单号、支付单号。
5. MP 后台「交易订单」金额与之一致；再试一次重复支付（续订），到期日应在原到期日后顺延。
6. 该单在 MP 后台退款后，账号对应时长被回收。

## 促销与改价

先在 MP 后台新建一个道具（如 `pro_month_promo`），再到「支付与价格」页添加同样的 ID、档位、周期、价格，
并在对应档位选它为生效。恢复原价：把生效道具选回原道具。

## 未验证项

真机拉起支付、真实发货推送、`query_order` 的状态码（按 2 / 3 / 4 视为已付）、
退款推送字段名，均需用测试单核对。

# 虚拟支付配置步骤（Pro / Max 购买）

> **上线前必做：`WX_PAY_ENV` 必须是 `0`（或删掉这个变量），并重新部署。**
> `WX_PAY_ENV=1` 是沙箱：用户不付钱，服务端照常发货，等于免费开通 Pro / Max。
> 部署后打开定价页，顶部没有「当前是沙箱环境」提示才算改成功。

前提：小程序主体为个人、服务类目含「工具」、已认证备案，且已在 MP 后台开通虚拟支付。
个人主体全终端月支付限额 10 万元；Android 费率 1%（T+3），iOS 12%（约 45–60 天）。

## 1. MP 后台：虚拟支付 → 基本配置

记下三项：AppID、OfferID、**现网 AppKey**（密钥，不入库、不进截图）。
要用 iOS 支付：先配置小程序简称，再开通苹果 IAP。

## 2. MP 后台：虚拟支付 → 道具管理

建好并**发布**四个道具，ID 与价格逐字对上服务端价目表（默认值）：

| 道具 ID | 价格 |
|---|---|
| `pro_month` | ¥12 |
| `pro_year` | ¥98 |
| `max_month` | ¥25 |
| `max_year` | ¥198 |

价格与 MP 后台不一致时，微信会拒绝该笔支付。

## 3. 云托管：环境变量

「服务设置 → 环境变量」新增三项，保存后**重新部署**：

```
WX_PAY_OFFER_ID=<OfferID>
WX_PAY_APPKEY=<现网 AppKey>
WX_PAY_SANDBOX_APPKEY=<沙箱 AppKey>
WX_PAY_ENV=0
WX_PAY_PUSH_TOKEN=<自拟的随机串，如 openssl rand -hex 16>
```

**`WX_PAY_ENV=1` 仅用于沙箱测试（见 § 7）；上线必须改回 `0` 或删掉该变量。**
缺任一项，下单回 `503 E_PAY_NOT_CONFIGURED`，其余功能不受影响。

## 4. 数据库：建 `pay_orders` 表

执行 `deploy/sql/mysql-schema.sql` 中 `pay_orders` 那一段（见 [`wx-cloud-setup.md`](wx-cloud-setup.md) § 四，先切库再执行）。

## 5. MP 后台：发货推送配置

- 路径：`/api/pay/notify`（GET 用于校验，POST 接收推送）
- Token：与 `WX_PAY_PUSH_TOKEN` 完全一致
- 消息格式：**JSON**（服务端不解析 XML）
- 接收方式：优先选后台提供的「云托管」接收并指向本服务；否则填服务的公网访问地址。

## 6. 更新镜像与小程序

改动涉及 `api/**` 与 `deploy/**`，须合并后让流水线重出镜像并在云托管发布；
小程序端发体验版（[`wx-cloud-setup.md`](wx-cloud-setup.md) § 八点五）。

## 7. 沙箱测试

沙箱用沙箱 AppKey 与 `env=1`，不真实扣款，**测完必须改回 `WX_PAY_ENV=0`**。开发者工具里拉不起虚拟支付，须用手机上的体验版。

### 准备

1. 云托管环境变量设 `WX_PAY_ENV=1`，并配好 `WX_PAY_SANDBOX_APPKEY`，重新部署。
2. 小程序发布体验版，用自己的微信打开。
3. 定价页顶部出现「当前是沙箱环境」提示，说明服务端确实跑在沙箱。没有这条提示不要继续。

### 用例

| # | 操作 | 预期 |
|---|---|---|
| 1 | 登录后在定价页买 Pro 包月 | 立即升 Pro；「我的」页出现 Pro 徽标与到期日；顶部出现欢迎卡 |
| 2 | 「我的 → 用户权限 → 支付记录」 | 有该单，状态已支付，带支付单号 |
| 3 | 管理员打开「后台管理 → 支付与价格」 | 购买记录里同一笔带 uid、openid、业务单号、支付单号、道具 ID |
| 4 | 再买一次 Pro 包月 | 到期日在原到期日后顺延，不是从今天重算 |
| 5 | 买 Max 包月 | 立即升 Max，徽标变金色 |
| 6 | 已是 Max，尝试买 Pro | 按钮置灰「已是 Max」；服务端回 `E_PAY_DOWNGRADE` |
| 7 | 拉起支付后点取消 | 弹「没有完成支付」；记录里该单保持待支付，账号档位不变 |
| 8 | 付款成功后立刻关掉小程序，再打开「支付记录」 | 自动补发货，状态变已支付（验证查单兜底） |
| 9 | 用没有绑定微信的账号下单 | 回 `E_PAY_OPENID`，不能下单 |

### 看日志

云托管服务日志中应出现：

- 下单：`pay.order` 对应的 `api.ok`
- 发货推送：`pay.notify` 对应的 `api.ok`；没有这条说明推送没到，发货靠查单补上
- 出现 `pay.notify_mismatch` 或 `pay.query_fee_mismatch`：金额或道具与订单不符，对应订单不会发货，须核对 MP 后台道具价格

### 通过标准

用例 1 – 9 全部符合预期。沙箱通过不代表现网通过，须继续做 § 8。

## 8. 现网小额验证

1. **`WX_PAY_ENV` 改回 `0`（或删掉），并确认 `WX_PAY_APPKEY` 是现网 AppKey，重新部署；定价页的沙箱提示消失。不做这一步不要上线。**
2. MP 后台「道具管理」新建测试道具（如 `pro_month_test`，设后台允许的最低价），在「支付与价格」页添加，并把「Pro 包月」的生效道具临时切到它。
3. 手机体验版用自己的微信真实支付一笔，核对 § 7 用例 1 – 3 与 MP 后台「交易订单」金额一致。
4. 再支付一笔，核对续订顺延。
5. 在 MP 后台「交易订单」对这些单退款（Android 由开发者主动退款，180 天内手续费退还）。
6. 退款后账号对应时长被回收；该单在后台购买记录里状态为已退款。
7. 把「Pro 包月」生效道具切回 `pro_month`。

## 促销与改价

先在 MP 后台新建一个道具（如 `pro_month_promo`），再到「支付与价格」页添加同样的 ID、档位、周期、价格，
并在对应档位选它为生效。恢复原价：把生效道具选回原道具。

## 未验证项

真机拉起支付、沙箱与现网下的发货推送、`query_order` 的状态码（按 2 / 3 / 4 视为已付）、
退款推送字段名，均需用测试单核对。

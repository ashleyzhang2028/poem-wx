# 跬步 · 古诗词背诵微信小程序

[poem](https://cnb.cool/npu-gpu-cpu/poem) 网页版的微信小程序移植。
覆盖小学一年级到高中三年级统编版古诗文，另设课外集子
（古文观止 / 乐府 / 唐诗 / 词 / 曲 / 昭明文选 / 成语故事 / 文学名著 / 历代名家 / 历代帝王……）。
篇目数以 `node scripts/build-data.js` 的输出为准。

**未登录能看首页目录，点不动；登录后按 free / pro / max 三档放开，
而进度与设置从登录那一刻起就跟着账号走 —— 换台手机登同一个微信，一切认回来。**
断网也能背：本机永远是可用的那一份，同步只是把本机已有的往上搬。

## 快速开始

```bash
# 编译语料 + 四条自检（语料在 scripts/corpus/，构建产物与自检结论都不入库）
npm test

# 用微信开发者工具打开 miniprogram/ 目录
```

这一条命令只需要 node（≥18），`package.json` 里那些 devDependency 与它无关，
**不必 `npm install`**。

**语料是构建产物，不在 git 里**（`.gitignore` 挡着 `miniprogram/data/`）。
`npm test` 自己会先编一遍，**不必再单独敲 `npm run build:data`**；
只有「开发者工具里要看数据、又不想等自检跑完」时才单跑 `npm run build:data`。

`npm test` 是 `scripts/build-and-check.js`：先编译语料，再依次跑
`check.js` / `parity.js` / `e2e-wx-sync.js` / `e2e-mysql.js`，**头一条不绿就停在那儿**，
不拿上一轮的产物继续往下走。`.cnb.yml` 里自检与发布两条流水线都只调这个脚本 ——
自检链要加一步，只改它一处。

装到手机上的体验版由流水线在打包前自己跑（见 `.cnb.yml`），**用户端不需要任何构建**。

### 语料与后端契约都在本仓库

| 在哪 | 是什么 |
|---|---|
| `scripts/corpus/` | 语料（统编版与课外集子的数据文件；取自哪一版见 `scripts/corpus/VERSION.json`） |
| `scripts/parity-web/` | 服务端契约的只读副本（能力表、路由表、报文清洗、存储层形状），自检拿它当基准 |
| `api/` | 后端运行时契约（登录 / 同步 / 管理那几条路由），镜像与 `e2e-mysql` 都摊它 |
| `miniprogram/utils/server.js` | 云调用两栏 —— **构建产物，不入库**：构建期从密钥仓库注入，用户开箱即用 |

**没有第二个仓库要跟。** 换一版语料就是把 `scripts/corpus/` 整份换掉、
把 `VERSION.json` 的 `upstreamRef` / `syncedAt` 改过来，然后重跑上面三步。

### 云调用两栏怎么进包

值是部署方的密钥，**存在密钥仓库**（`poem-wechat-mini-program-secrets` 的
`wechat-ci.yml`）：

```
CLOUD_ENV      云开发环境 ID（形如 poem-d9g1bqeq978682c58）
CLOUD_SERVICE  云托管服务名
```

构建期由流水线把这两个变量交给 `build-data.js`，它据此生成
`miniprogram/utils/server.js` —— 跟语料一样是**构建产物**，已 gitignore。
用户装上去就通，不必自己填。本机没注入时就两格为空，界面照实说
「这个包还没配同步服务器」。

```bash
CLOUD_ENV=… CLOUD_SERVICE=… npm run build:data   # 本机要验证这条路时这样跑
```

管理名录是别人的账号标识，**不进代码库**。要导入就设环境变量：

```bash
POEM_ROSTER='[{"id":"...","label":"belem","tier":"max"}]' node scripts/build-data.js
```

不设也能跑 —— 管理页如实显示「名录未导入」，只列出本机授权，不凭空编人。
CI（`.cnb.yml`）里没配这个变量，所以构建出来的是空名册，自检有断言守着这一点。

`appid` 已换成正式号（`wx200a0c667fc67fcb`），上传体验版跟着 `main` 流水线走；
`upload.js` 会把它与密钥仓库里的 `WX_APPID` 逐字比对，不一致直接拒绝上传。

⚠️ **那一步是 `allow_failure: true`** —— 上传失败时**流水线照样是绿的**，得自己翻
那一步的日志找 `✗✗✗`。碰见平台回 `20003 … appIdToAppuin failed`（Issue #133）：
那**不是** IP 白名单的问题，是**上传密钥不是这个 appid 名下的** ——
逐条排查见 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) § 八点五。

## 现在到什么程度了（别看成「可以提审了」）

功能是齐的，**卡在后端**。老实分三档：

| | 状态 |
|---|---|
| **能跑** | 四套算法、注音、题库、飞花令、全文检索、进度总览 —— 全部离线可用，断网也能背（页面清单见 `miniprogram/app.json`） |
| **要配置** | 微信登录与跨设备同步。代码在 `api/` 里，部署与建表照 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) 一步步做 —— **用户端不用配**：云调用两栏在构建期由密钥仓库注入进包 |
| **不做** | 语音朗读：同声传译插件要企业/个体户主体，自家 TTS 要付费 + 后端签名。用户裁决不做，界面里一个朗读元素都没有 |

所以「一切就好了吗」的答案是**没有**，但**没有的是外部依赖，不是代码**：
没配后端时登录降级为本机身份、档位按免费、进度只在本机，
**功能一个不少，也不会假装成功**。

提审前必须先做的三件事：

1. ~~换掉 `appid`~~（已换，见上）
2. ~~接上后端~~（云调用两栏由构建期从密钥仓库注入 `miniprogram/utils/server.js`，
   值写在 `wechat-ci.yml` 的 `CLOUD_ENV` / `CLOUD_SERVICE` 里 —— 用户开箱能用）
3. **真机走一遍**。上面所有验证都是离线跑的；安全区、原生控件外观、字体回退、
   分片下载超时各有一摊事，开发者工具的真机预览才是准的

传到体验版跟着 `main` 那条流水线（`.cnb.yml`），**只上传不提审** ——
「要不要上线」不该由流水线决定。

## GitHub 上的只读镜像

[`ashleyzhang2028/poem-wx`](https://github.com/ashleyzhang2028/poem-wx) 是本仓库
`main` 的一份**只读镜像**，每次推 `main` 由流水线最后一步同步过去。给它是为了
在 GitHub 上看代码方便（CNB 这份是私有的）。

**只同步 `main`，不同步分支** —— 本仓库有 80 多个分支，大半是合完就没用的
`auto/*`。想让某个分支也上去，先合回 `main`。

⚠️ **别在 GitHub 那份上直接提交。** 它是单向的，下一次同步会覆盖掉你的提交。
要改代码在这边改。

同步那步用到一对密钥，走**密钥仓库**（`poem-wechat-mini-program-secrets` 的
`wechat-ci.yml`），不进代码：

```
GH_PAT    fine-grained PAT，对 poem-wx 有 Contents: Read and write
GH_REPO   ashleyzhang2028/poem-wx
```

那两份密钥仓库的配置里，`allow_slugs` 要覆盖本仓库、`allow_events` 要含 `push`，
不然流水线读不到它们（同现有那几个键的规矩）。

同步失败会让整条流水线**红** —— 它排在最后，前面几步成不成都不影响
「GitHub 上有没有这一版」这件事本身。

## 要联网的四条路，和「要不要备案」

只有四条路要出网（`utils/remote.js` 的 `PATHS`）：微信登录、进度同步、
TTS 合成、管理接口。**没有后端也能跑** —— 语料、算法、记音、进度全在本机，
断网照背，丢的恰好是这四样，届时界面如实说「后端未就绪」而不是假装成功。

服务端有哪些接口，逐条列在 `api/_lib/routes.js` 的 ROUTES 表 —— 那张表就是路由。
部署好的容器上 `GET /api/count` 回同一张清单（形如 `ok /wx/login /sync/pull …`），
拿它对齐「线上那一版是哪个版本的后端」。

接后端有两条路，**分别只在要不要备案**：

| | 怎么走 | 要域名 / 备案 | 谁能调 |
|---|---|---|---|
| **云调用（推荐）** | `wx.cloud.callContainer` | **都不要** | 只有小程序 |
| request 合法域名 | `wx.request` + 域名 | 要域，且**域名必须已备案**（3–20 个工作日） | 小程序 + 网页版 |

**第二条路的门槛不在配置，在备案。** `wx.request` 只能打在微信后台登记过的域上
（没登记的真机一律 `url not in domain list`），而那张名单**只收已备案的域名** ——
https + 有效证书、ICP 备案、不带端口不写 IP，三条都满足才填得进去。
云托管的默认域填不进去（微信提示「云托管域名仅用作测试使用」）。
想上线又不想等备案，就走云调用：它走微信内网，不经过那张名单。

云调用的代价只有一条：**只有小程序能调**（浏览器拿不到调用方身份）。
本项目两端本来就是两份部署，这条不落到任何一处。

两条路在客户端只差一层分派，`PATHS` / 报文 / 重试全共用。
怎么填见 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) § 6，
两条路的说明见 [docs/architecture.md § 五点五](docs/architecture.md#五点五出网两条路一张名单和一个免掉它的办法)。

## 谁能用

| 档位 | 能力 | 怎么拿到 |
|---|---|---|
| 未登录 | 只能看首页书目（一年级上下册），点不动 | 谁都能进 |
| **Free** | 每日背诵 / 今日加背 / 课外阅读 / 注音辅助 / 艾宾浩斯 / 进度总览 / 全站搜索 / 同步进度 / 语音朗读 / 进度导出 / 莱特纳盒 | 微信登录后就有 |
| **Pro** | 再加 SM-2 / 题库 / 自选清单 / 管理页 | 管理员发放 |
| **Max** | 再加 FSRS / 飞花令 / 考试 | 管理员发放 |

对比以登录为前提：**未登录一条能力也拿不到**，所以表里只有这三档 ——
「登录就有」不是一个档位，它只是 Free 那一档到手的条件，界面上不写这句话。

三档**都不收费**，由管理员在管理页里按人分（微信不允许个人主体做虚拟支付，
但这里本来也不需要支付）。

一句得说清的取舍：小程序**做不到**「打开即强制登录」——`wx.login` 是静默的，
要用户点头的接口又必须由手势触发，没有 API 能在启动时弹授权框。
所以写法只有一种：进门容易、用起来要求登录。

## 权限

| 能力 | 门槛 |
|---|---|
| 首页浏览 | 不需登录。默认列出一（本册）诗词，**看得见、点不动** |
| 其余全部能力 | 登录就有（Free 档）。含每日背诵 / 今日加背 / 课外阅读 / 注音辅助 / 艾宾浩斯 / 进度总览 / 全站搜索 / 同步进度 / 语音朗读 / 进度导出 / 莱特纳盒 |

对比表逐条在「我的 → 用户权限 → 权限对比」。

## 功能

- **门禁**：未登录只能浏览首页目录，点任意一首给一句人话 + 登录入口，不静默跳转
- **每日背诵**：按选择的年级学期与范围排出今天要背的几首，分「复习」与「新学」。
  计划卡下面还有一张折叠的「本年级本学期全部诗词」，默认收起，点开列全，
  点任一首进背诵弹层；范围选的是随机那几档时，标题随范围走
  （「小学阶段全部诗词」这种），列表给那一段的全部篇目
- **今日加背**：今天想多背一首就自己加（上限 20，跨过 0 点自动归零）。
  入口在首页那张「今日加背」搜索卡、详情页与背诵弹层里的「加入今日背诵」，
  清理由背诵设置页那张面板（全选 / 移出选中的 / 全部清空）。
  加进去的当场排进今日计划、小签标「今日加背」——
  它与排期器自己凑数补的那几首（可能标「补充」）分得开。
  **加背挂在每日几首之外**：设了 5 首再加 1 首，今天就是 6 首，原来那 5 首一个不动
- **四套复习算法**：艾宾浩斯遗忘曲线 / 莱特纳盒 / SM-2 / FSRS，设置页可切，**换算法不清进度**
- **背诵设置**：先选**当前学段**（小学 / 初中 / 高中），年级格只列这一段
  （一至高三十二个年级一个不丢，换学段就换一排，取诗范围跟着换）；
  范围 7 选 1：本册 / 本册及之前 / 小学随机 / 初中随机 / 小初随机 / 高中随机 /
  全部随机（这张卡原来叫「取诗范围」）。
  入口两处：「我的 → 背诵概况」里那三行各自跳到对应的那一张卡，
  以及「我的 → 设置 → 背诵设置」
- **课外阅读**：各集子按「课内 / 诗文典籍 / 人物 / 文史常识」四类分组，
  每类下的集子排成两列，点一格直接进该集子的列表
- **全站搜索**：搜篇名 / 作者 / 正文，不让人选「搜哪儿、怎么搜」——
  先按篇名作者找，没结果自动落到正文全文
- **作者索引**：从搜索页进，按朝代先后把全站作者铺成一页
  （按朝代分段，段内按拼音），点一位读他的全部作品；
  **下一篇只在这一位作者里走**，走到头退回他的列表。
  与网页版 `/authors/` 同一条产品口径 —— 那两件事的来龙去脉见下面「作者索引」一节
- **背诵进度**：已学 / 已掌握 / 今日到期，未来七天排期，记忆阶段分布。入口在「我的 → 背诵概况」最后一行
- **古诗词大会**：飞花令（随机出一个字，自己写一句接，对错自动翻题）、题库（逐题判定）、考试（限时 20 分钟，全部答完再批）。入口在底栏中间那枚「大会」
- **答题音效**：答对 / 答错 / 过关 / 出分四种，Web Audio 现场合成，零音频文件；
  可在「声音设置」里关掉，旁边有「试听一声」当场验这台设备出不出声
- **按体裁判版式**：七绝律诗一句一行（作者排的）；《琵琶行》的序、《左传》的长篇
  对白按句读折开，且按段落断开 —— 长诗不再是四十几行连成的一堵墙
- **注音**：三种模式（不注音 / 生字 / 全文）。读音表离线进包，多音字按词组消歧 ——
  「白发」读 fà、「作为」读 wéi、「不是」读 bú、「一行」读 yì
- **通用设置**：对齐方式、注音、字号。**只在详情页与通用设置页**出现 ——
  背诵设置页不再有这一行（它只管背哪些、每天几首、怎么复习）。
  注音原先单开一页「阅读设置」，2026-10-04 并回来了：三件事是同一组版式偏好，
  分两页改一处要跑两趟。那页现在只留答题音效，名字也跟着改成「声音」
- **主题色**：九种中华传统色（朱红 / 明黄 / 天青 / 雨过天青 / 胭脂 / 竹青 /
  玄色 / 鸦青 / 天水碧）+ 一格「墨」回到默认。后两个（雨过天青 / 天水碧）
  是替换了原先的月白 / 藕荷 —— 那两个对页面白底几乎看不见。选了之后
  按钮、选中态、卡片与列表标题、
  底栏当前项一起换 —— 页底、卡片、状态色（成功 / 危险 / 待办）不动，
  正文与诗词也仍是中性墨。做法与两条边界见
  [`docs/design-system.md`](docs/design-system.md) 的「主题色」一节
- **正文全文检索**：不只搜篇名作者，正文里的句子也搜得着，带出命中那一句
- **题库**：五种题型（下句 / 上句 / 作者 / 朝代 / 篇名），可按需勾选；
  考试与题库共用同一套出题与判分内核
- **同步进度**：登录就有（2026-10-04 起不再分档）。跟着账号走的是六样：
  背诵进度、已读标记、今日加背、自选清单、**全部设置**（年级 / 册次 / 范围 /
  每日首数 / 算法 / 主题色 / 注音 / 字号 / 对齐 / 自动翻篇 / 朗读偏好）、昵称。
  合并是「新者胜」（两端都按 `updatedAt` 比）。
  「跟设备走」的两项例外：答题音效取决于这台机器的扬声器；
  **头像**只有微信一个来源且不上传（Issue #111），换台手机就是没有 ——
  这是刻意的，为它养一份对象存储不划算。
  登录那一刻就同步一次，不必等下一次启动；没后端时离线队列攒着，不假装成功
- **头像**：**只有一个来源 —— 微信那张**。点头像走 `chooseAvatar`，它弹出来的
  第一项就是当前微信头像；选完**只落本机、不上传**（不为它养一份对象存储）。
  换台手机头像就是没有 —— 这是刻意的，也是 Issue #111 明确要的。
  平台没有任何「静默拿微信头像」的 API，所以「登录后自动用微信头像」
  落成的样子是「点一下就给你微信那张」，不是「不点也能拿到」
- **管理页**：给微信登录用户分层（free / pro / max）与改角色（owner / admin / user），
  归档对齐网页版的权限表；改档只走服务端，没有「改本机档位」那条路
- **用户权限**：free / pro / max 三档，与网页版同一张能力表；页面上是「我的权限」
  与「权限对比」两张卡，对照表逐行就是能力表本身、逐格按门槛算，当前档位列标「现在」。
  表照网页版 `/plans/` 排：列头 Free / Pro / Max 三档等分，整表铺在页面上、卡片里不滚
- **导出备份**：整份数据复制成 JSON，换手机时导回去

## 与网页版对照（摘要）

逐条在 [`docs/parity.md`](docs/parity.md)，这里只给结论。**记号只有四种**：
✅ 两端都有 / ⚠️ 换个做法（平台不同，能力不丢）/ ⏸️ 小程序端没做 / ❌ 是缺口。

| 一类 | 结论 | 差在哪 |
|---|---|---|
| 内容与阅读 | ✅ | 语料 / 译文 / 集子 / 索引卡 / 注音 / 全文检索，一条不少。差「注音勘误审核」与「打印页」 |
| 背诵与复习 | ✅ | 四套算法 / 六种范围 / 掌握度 / 进度总览 / 今日加背。差「自选清单」 |
| 大会与出题 | ✅ | 飞花令、题库、考试、音效都在。差「正式考试」与「文学常识考试」（依赖后端组卷） |
| 账号与同步 | ⚠️ | 身份换成微信，其余对齐。差「邮箱密码登录」（平台不同，不该做）与「家庭子用户」 |
| 报告与反馈 | ⏸️ | 网页版的报告台账与跟帖都要后端，小程序端先给「复制联系邮箱」这一条出口 |
| 平台形态 | ⚠️ | 外壳 / 控件 / 离线 / 部署全按小程序最佳实践换掉，不是缺口 |

**一处刻意的反向补充**：微信登录是小程序有、网页版没有的一层 ——
服务端那两条路由在本仓库 `api/` 里，
契约见 [`docs/wx-login-server.md`](docs/wx-login-server.md)。

这张表由 `node scripts/parity.js` 守着：网页版 `js/entitlement.js` 里
每一个能力键，都必须在小程序端落成「已实现的能力 / 页面」或
「`docs/todo.md` 里的某一条」。**漏一项就红。**

## 朗读：不做，界面上也没有

TTS 通道个人主体申请不下来（同声传译插件要企业 / 个体户主体；自家 TTS 要后端签名
并按量计费）。用户 2026-10-02 的裁决是**不做**。

于是界面里**一处朗读元素都没有**：详情页没有朗读那格、没有播放工具栏、设置里没有朗读卡、
「我的」页没有入口。上一版留了一张写着「待开通 / 朗读通道待接入」的卡 ——
那等于每次进详情页都杵着一块死内容，比没有更糟。

`utils/speech.js` 里三条通道的代码还在（不是删了，是不接），
`docs/todo.md` 第 1 条记着为什么不做。**「不做」和「还没做」分开记**：
写成「以后做」，下一个人会误读。

自检守着这条：全页面扫源码，任何一处冒出朗读元素或「待开通」这五个字就红。

## 能力不可用时不显示

**这是这个项目的一条硬规矩。**

注音、正文全文检索、答题音效、云端同步，都按这套走：

| 能力 | 什么时候不显示 |
|---|---|
| 注音 | 读音表没生成 |
| 正文全文检索 | 倒排索引没生成 |
| 答题音效 | 运行环境没有音频接口 |
| 同步进度 | 通道没开（如实写「换手机进度不跟随」）|

判定这件事的函数一律叫 `readiness()`，同步返回三个值：

- `visible` —— 界面里该不该出现这个元素
- `usable` —— 能用，还是只是占着位置
- `state` —— `ready` / `awaiting` / `denied` / `unsupported` / `missing`

**能力压根没有**时连位置都不占 —— 一个点不动的按钮比没有更糟。

## 作者索引

用户对网页版 `/authors/` 的原话（Issue #480），这一页就是照它做的：

> 按时间朝代顺序，将中国所有作品的作者列在一页，上面是朝代索引列表，
> 点击朝代可以下面的具体朝代，朝代下面是各个作者，例如唐代 李白，
> 点击李白，显示李白所有作品列表，再点击列表，进入详情页，
> **详情页的上一页下一页都是该作者的作品**。返回就回到李白列表。

两层，都在**一个分包页**里（`packages/authors/index`），不新开页面：

| | 是什么 |
|---|---|
| ①**名册** | 朝代表 + 一段一段的作者，段内按拼音排 |
| ②**一位作者的作品** | 复用列表页那一套（分组标题 + 行 + 已读标记 + 未读筛选） |

口子开在**搜索页**（不是课外阅读）—— 与网页版同一处，那边第二轮改的就是这个。

### 名册是「扫一眼有谁」，不是「读一行的详情」

一段里**只有**「名字 + 收了几条」两件事，排成一行行的格子。
一人一行、右边挂箭头与小字那种排法，一部《唐诗》就是上百行，
读者得点着滚动条把一整朝滤一遍。

排版按**内容**走，不按列数：名字长短差得远（「苏武」2 字、
「孔子及弟子、朱熹」8 字），等宽栅格会把长的挤成两行、短的留一大片空。
所以是 `auto-fill` + `minmax`，一行塞几颗由名字长短自己定。

### 名册现算，不进包

十部集子的索引本来就在包里（各集子的列表页要用），名册只是把它们按作者
重摆一遍。比多背一份静态的「作者 → 条目」表划算，也不会跟语料错开版本。
（名册条目数少于选集合计：结集与课内已背过的那几条不进名册。）

两张归并表在 `utils/author-index.js`，与网页版 `data/author-index.js`
**同口径**（`check.js` V40 拿两端逐段比）：

- `ERAS` —— 把二百多种朝代写法（`宋 / 北宋 / 南宋`、`南朝·宋 / 南朝宋`……）
  收进一条时间轴。段名取归并后的（「宋」），不是原写法
- `ALIAS` —— 异名归一（`曹子建` → `曹植`、`班孟坚` → `班固`），
  否则《文选》里一个人的作品会拆到两处。共 **50 条**，`check.js` V40
  拿两端逐条比（差集双向都查，不是数条数 —— 一条改错、一条漏掉时
  总数可能正好一样）。第二轮补进三条：`孔子及其弟子 → 孔子及弟子`
  （《论语》那一批的两种写法）、`吕不韦等 → 吕不韦`、`刘安等 → 刘安`
  （先秦子书托名的「等」写不出人来，归到书上那位主人）
- `ATTRIB` —— **合编课文**的归属：`classic-gw-10`《古人谈读书》正文两段两家
  （前三句《论语》、「余尝谓读书有三到」是朱熹），显示与详情页一个字不改，
  名册里挂**朱熹**。`check.js` V40 也拿两端逐条比（**这一条是补来的**：
  #480 第三轮网页版加了它，这边只搬了 ERAS / ALIAS，名册上这一条归属就不同）

两处**故意与网页版不同**，都写在代码注释里：

1. **判重只认课内。** 网页版按作品 id（`WorksIndex.widOf()`）判「这一篇是不是
   已经在别处收过」；小程序端没有那张表，也不该为它多背 8KB ——
   做法是一篇在课内背过，它在《唐诗》里那条壳就不进名册
   （这正是网页版 `repOf()` 的裁定：课内优先）。代价是课外两部选集之间的
   重复现不出来，而那种重复在语料里本来就少
2. **结集不进名册。** 《礼记》的《大学之道》、《论语》的《子路曾皙冉有公西华侍坐》
   四条，作者一格填的是**书名**。挂上去就是「《礼记》写了《大学之道》」——
   那是编。它们在各集子的列表页照旧读得到，一个字不丢
3. **差的是哪几位。** 第二轮补录之后两边差了六位（网页版 495、这边 540）：
   崔护、刘歆、庄周、项羽、王十朋、杨基。都是同一类 —— 他名下的作品只在
   **课外两部选集**里各有一条（例如王十朋《读〈岳阳楼记〉》在《古诗》与
   《古文观止》各一条），网页版按作品 id 并成一篇、这边各收一条，
   于是这边反而多出作品、人也多冒出来几位。名单钉在 V41 里，
   哪天冒出一位不在名单上的，就是该回来对一次

### 下一篇只在这一位作者里走

用户那句话里最具体的一条，落在**评完分自动往下跳**那一处（小程序端的
「下一页」只有这一处）。从作者索引进详情页时 URL 带一个 `?from=李白`，
reader 认它：下一首在这位作者名下找，走到头退回**他的作品列表**。

⚠️ 这段有三个坑，都在注释里标着：

1. 只走**收作品的十部**。曾经这里扫了全站十七部 —— 于是李白的下一篇
   跳进了《成语故事》的「李白」词条（名册不收词条，下一篇凭什么收）
2. 作者名要**归一**：名册写「曹植」，《文选》里写「曹子建」，不归一就漏
3. 顺序要与②层列出来的一模一样（集子 → 组 → id），否则「列表里看到的顺序」
   与「下一篇跳到的顺序」对不上，用户当成 bug

这一条跨三个文件，静态扫描看不出来，所以 V41 是**真跑阅读页**验的：
连翻五首，每一首的 `author` 都得是李白、`bookId` 都得在那十部里。

## 语料随仓库走，口径由自检钉住

语料在 `scripts/corpus/`（取自哪一版见 `VERSION.json`），
**没有第二个仓库要跟**。但「不偷偷跟」这条纪律留着 —— 它真正的意思不是
「别自动拉上游」，而是**「盘上这份语料到底是不是那一份」要有答案**。

所以把口径写下来，写进 `scripts/check.js` 的 V40：

| 判据 | 查什么 |
|---|---|
| 篇数 | 各集子逐部 + 课外合计 + 带正文的条数（这张表**会过期**，数取自 `build-data.js` 输出） |
| 号段 | `gushi 1–126` / `songci 1–331` / `tangshi 1–469` 不许出现**新**空洞 |
| 归位 | 曹植《七步诗》只此一条、在《古诗「非唐代」》、朝代三国·魏；《唐诗》里非唐的只有记着的那一条（杨万里《闲居初夏午睡起·其一》，通用名篇那一段收的） |
| 朝代 | 收作品的十部集子里没有空朝代；《昭明文选》同一位作者只落一朝 |
| 时间轴 | 两端 `author-index.js` 的 `ERAS` 表逐段一致（拿 `scripts/corpus/` 那份比） |
| 异名 | 两端 `ALIAS` 表逐条一致（**这一条是补来的**：第一版只比 ERAS，语料里补的十条异名这边一声不响地落后了十条，名册上于是「桓温」与「桓元子」各挂一半作品） |
| 合编归属 | 两端 `ATTRIB` 表逐条一致（**同样是补来的**：`ALIAS` 落后是同一个教训 —— #480 第三轮给《古人谈读书》加了归属裁定，这边只搬了 ERAS / ALIAS，没搬 ATTRIB） |
| 出处两重 | 选本条目必须同时有 `source`（所出之书）与 `selection`（收它的选本）；《唐诗》《词》《曲》《文选》四部的条数逐部对（**这一条抓出过真漏**：`build-data.js` 原先根本没搬 `selection`） |
| 题名异写 | `aliases` 搬全了（11 条），点名的那几条一条不少（**与出处同一类漏**：构建脚本漏搬一个字段，界面上少一句话，谁也不会发现） |

换一版语料（把 `scripts/corpus/` 整份换掉）就是一次**要人来做**的动作：
换完把 `VERSION.json` 的 `upstreamRef` / `syncedAt` 改过来，跑一遍自检，
绿了才算换过。红了的意思是「回来对一次」—— 对完把 V40 那张表改掉。
篇数表会过期是**故意的**：一份永远不用改的表，也就永远证明不了什么。

这也解释了为什么号段判据是「不许有**新**空洞」而不是「连号」——
语料里本来就有洞，而且有理由（`gs-02/03/04` 是《诗经》里与课内重了的、
`sc-127` 并进了别的号、`ts-306/307` 是搬家留下的空位、`ts-427–442` 那一段是
几批补录接号时成段让出来的）。已知的空洞列在 `KNOWN_HOLES` 里；
哪天真补上了，判据会催着把它删掉，免得那张表越攒越大。

### 主包体积的账

索引落盘时摘掉了每个文件里重复或恒空的字段（集子 id / 集子名 / `hasT` / 空字段），
`utils/corpus.js` 的 `ofBook()` 读回时补齐 —— 外面看到的形状不变。
自检守着「盘上那份是紧凑的」与「补回来之后归属正确」两条。
体积、上限与逐项预算见 [`docs/architecture.md`](docs/architecture.md) § 三。

## 数据放在哪

正文**不全进包，但课内那部分进包**。全部正文远超主包上限（2 MB），一部《昭明文选》就超了；
课内那批只有两百来 KB。所以分三层：

- **包内**：各集子索引 + **课内正文与译文**，主包合计约 1.3 MB（以 `build-data.js` 输出为准）
- **云端**：其余正文切成约 200 KB 一片的分片（片数与体积见 `build-data.js` 输出），
  **跟主包一起走云托管容器下发**（`/api/shard/<name>`，gzip 后每片约 44 KB），按需取
- **本机**：背诵进度、设置、已读标记

课内正文进包是刻意的：首页「每日背诵」与详情页都靠它，这点体积换掉一次云端往返，
省下的是每天真正被打开的那两个页面的等待。边界由自检验着 —— 课内进包、课外走分片，
同一份正文不许两边各存一份。

⚠️ **「云端」那一层默认随镜像走，要瘦镜像才用一面旗关掉。** `project.config.json` 里
`packOptions.ignore` 把 `data/texts` 挡在包外（这一条不变），而容器里有没有分片，
看构建参数 `COPY_SHREDS`：

| 这面旗 | 课内正文 | 课外正文 |
|---|---|---|
| 默认（不写） | 可用（在主包里，断网也能背） | 可用（从容器取下） |
| `=0` | 同上 | 点开会说「这个版本里没有课外正文」（调试镜像那一档） |

**分片为什么走容器而不是 CDN**：`wx.downloadFile` 打的那个域必须进 downloadFile
合法域名名单，而那张名单**只收已备案的域** —— 云调用走微信内网、不过那张名单，
于是域名 / 证书 / 备案三样一起免。代价、账目与取舍见
[`docs/shard-delivery.md`](docs/shard-delivery.md)；要开这面旗见
[`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) § 一点五。
**「构建出来 27MB」不等于「包里有 27MB」**：进包的是索引 + 课内正文，分片被 ignore 掉了。

上面那三层说的是**内容**。**账号那一份**（账号 / 进度 / 设置 / 昵称）另有一层，
它跑在微信云托管的容器里、走**云调用**（免域名免备案），
库是腾讯云 MySQL —— 存储层是一个接口（`getX / putX` 那组），换实现不动小程序一行。

> **「数据在哪、后端依赖怎么解、CI 为什么会被上游绊住」三件事单独一份：**
> [`docs/data-backend.md`](docs/data-backend.md)。
> 一句话版：小程序端**一行都不认识数据库**，它只认识 `PATHS` 与报文；
> 数据库是**容器里那个存储层的一个实现** —— `store.js` 那组 `getX / putX` 是契约，
> 线上实现是腾讯云 MySQL（`deploy/store-mysql.js`）。

详细推演见 [`docs/architecture.md`](docs/architecture.md)。

## 后端怎么部署

后端在**本仓库根的 `api/`** 里，部署描述在 `deploy/` 与 `deploy-api-serve/`。
镜像由 CNB 流水线在 `/tmp/ctx` 摊出上下文后构建，云托管按**镜像**部署。

```bash
git checkout main && git pull   # 推 main 就出镜像
```

然后照 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) 一步步做：建服务（填镜像
`ghcr.io/ashleyzhang2028/poem-wx/wx-api:<本仓库短 sha>`，端口 8080）→
配环境变量 → 跑一遍 `deploy/sql/mysql-schema.sql` 建表 → 验。云调用两栏的值
写在 `miniprogram/utils/server.js`（构建期由密钥仓库注入），不走界面。

⚠️ **镜像地址填 GHCR 那份，不要填 CNB 制品库那份**（Issue #71）：CNB 的 Docker
制品库可见性跟着代码仓库走，本仓库 Private → 制品私有 → 云托管「从地址拉镜像」
那一栏拉不动（它只收公开镜像），要么配拉取凭据、要么把整个仓库改 public。
所以流水线一次推两份：GHCR 那份是**公开包**，云托管直接拉，**不用配凭据**。
CNB 那份留着当回滚路（私有，要凭据才拉得动）。两份是同一棵树。

⚠️ **推 GHCR 那两个密钥里，`GHCR_TOKEN` 必须是 classic PAT**（密钥仓库
`wechat-ci.yml` 的 `GHCR_USER` / `GHCR_TOKEN`）。GitHub 原话是 *GitHub Packages
only supports authentication using a personal access token (classic)* —— 所以
**fine-grained token 的 Permissions 里没有 Packages 那一栏，不是藏得深，是不存在**。
`write:packages` 是 classic 的 scope，走这个链接建：
<https://github.com/settings/tokens/new?scopes=write:packages>。
（同文件里的 `GH_PAT` 是另一码事 —— 同步代码用的，fine-grained 的
`Contents: Read and write` 就够。两个别互相顶替。）

⚠️ **部署方式选「镜像」，不选「代码仓库」**：本仓库根上没有这份镜像的构建上下文
（`api/` 与三个服务壳文件是流水线在 `/tmp/ctx` 摊出来的）。流水线为什么这么构建，
见 [`deploy/README.md`](deploy/README.md)。

### 哪些改动要在云托管更新 Docker 镜像

镜像里装的只有后端：`api/`（路由与内核）、`deploy-api-serve/`（服务壳与分片路由）、
`deploy/store-mysql.js`（MySQL 存储层）、`deploy/Dockerfile`，外加一份正文分片。
**小程序端一行都不在镜像里。**

要更新镜像的：

- `api/` —— 后端本体，改了必须换镜像
- `deploy/` —— Dockerfile、`store-mysql.js`、`sql/`
- `deploy-api-serve/` —— `serve-api.js` 与 `shard-api.js`
- `main` 那条流水线自己（`.cnb.yml`）

不要更新镜像的：

- `miniprogram/` —— 随体验版走，与容器无关
- `scripts/`（含 `scripts/corpus/`）—— 构建期用；改语料只影响新体验版，不影响容器
- `docs/`、`README.md`、`AGENTS.md`

**「要更新镜像的」那张名单就是判据本身**：`main` 的发布流水线挂着 `ifModify`，
只列了 `api/**`、`deploy/**`、`deploy-api-serve/**` 与 `.cnb.yml` ——
推 `main` 时这四样一个都没动，那一步**连跑都不跑**（流水线页上是「未执行」，
不是失败）。名单与 `ifModify` 对不上时，自检会红（`scripts/check.js`）。

推 `main` 时流水线把镜像推到两个 tag：`<短 sha>`（每次提交都变）与 `latest`。
**云托管不会自动跟着走** —— 改完上面那几样之后，去服务的「部署」里选新 tag 重新部署，
线上才真的换过来。

### 手动发一版：分支详情页上那个「发布」按钮

推 `main` 之外还有一个入口 —— **`main` 分支详情页上的「发布」按钮**，
它在 `.cnb/web_trigger.yml` 里，点了就跑 `web_trigger_release`
（链与推 `main` 那份逐字相同，只是不挂 `ifModify`：手动要的正是
「不管这次改了什么，都按当前代码重出一遍」）。

```
main 分支详情页 → 「发布」→ 走一次 镜像 → GHCR → 体验版 → 同步 GitHub
```

（自检挂在 `"**"` 的 `push` 那条上，与这次发布并行跑；发布链本身不自检。）

跑的是**该分支最新一次提交**，密钥与 `push` 那条同源（同一个密钥仓库）。
哪一步失败仍按各自的规矩红或绿：只有「上传体验版」是 `allow_failure`。

`.cnb.yml` 里那两个入口的脚本是**同一份**，`check.js` 逐行比着 ——
改发布链只改一处，另一处不同就红。

### 重跑一次发布，然后在哪儿看那条横幅

「上传体验版」是 `allow_failure: true` —— **它失败时流水线照样是绿的**，
判据是那一步日志里的横幅：`✓✓✓ 体验版已上传 <sha> ✓✓✓` 才算传上去了，
`✗✗✗` 开头的才是真交代了原因、并带着脚本里翻译好的处置办法。

不推新提交也要重跑时，在**那次发布的构建详情页**（`…/-/build/…`，从仓库首页的
流水线/构建记录点进去）点「重新运行」/「重试」。选哪种：

- 想沿用同一次 checkout 与同一条密钥 → 只重跑「上传体验版」这一步或整个 job；
- 想干净重来 → 重跑整条流水线（换过 `WX_PRIVATE_KEY_B64` 之后就该这么跑）。

日志在同一页 → 本次构建的任务列表 → 展开 **「上传体验版」** → 看这块面板的输出。
**不要看整条流水线的颜色**：这步红了整条也是绿的，只看那一步的横幅。

横幅里的 `<sha>` 必须与本次发布的提交对上（`…/-/commit/<sha>`）；空的话说明打的是
tag `latest` 那类非 commit 触发，别拿它当「这一次传上去了」的凭据。

镜像那两步失败会把流水线打红，与这块横幅是两回事。

  外加一张「明确不做」的表（免得把「不做」误读成「以后要做」）

下面是摘要，细节以那两份文件为准：

- **朗读不做**：TTS 通道个人主体申请不下来，界面里一处朗读元素都没有（见
  [`docs/todo.md`](docs/todo.md) 第 1 条，以及上面「朗读：不做，界面上也没有」一节）
- **付费档不能小程序内下单**：微信不允许个人主体做虚拟支付，
  `pro` / `max` 只能由管理员在管理页里按人分
- **存储层跑在腾讯云 MySQL**：`store.js` 那组 `getX / putX` 是契约，
  线上实现是本仓库的 `deploy/store-mysql.js` + `deploy/sql/mysql-schema.sql`
  **（小程序前端一行不动）**。
  **这不影响小程序审核** —— 审核不看你的数据库跑在哪，
  真正会踩线的只有「`wx.request` 打未备案域名」，而云调用不经过那张名单。
  换库要动什么、条件 upsert 那条不变式在哪，见 [`docs/data-backend.md`](docs/data-backend.md) § 三
- **后端要配一遍**：接口契约写死在 `utils/remote.js`，**报文形状收在 `utils/wire.js`**。
  服务端代码已就绪（微信登录两条路由 + 会话认 Bearer + 白名单，都在本仓库根的
  `api/` 里），同步与管理那几条也在那儿。云调用两栏在构建期注入进包
  （`miniprogram/utils/server.js`，`baseUrl` 同理）。没配之前一律降级，不做任何「假装成功」
- **`node scripts/e2e-wx-sync.js` 是这一块的真判据**：它把小程序端 utils 与本仓库
  后端接起来真跑一遍（登录 → 同步 → 设置/进度真落库 → 换台手机认回来）。
  上面那些静态自检验得了「报文形状对不对」，验不了「两边合起来通不通」——
  而这一轮的坑（**登录通但同步一律 401**、字段被服务端裁掉、换机认不回来）
  全都是合起来才显形的
- **跨端同步要服务端配合一次核对**：小程序发的报文已经按服务端的
  `sanitize*` 逐字段对齐并写进自检（自检会直接 require 契约副本
  `scripts/parity-web/core.js` 来验），但**「同一个人在两端的 uid 是同一个」
  这件事只有服务端能保证** —— 见文档末节
- **客户端档位不是安全边界**：改本机存储就能提档，真扣配额必须在服务端做

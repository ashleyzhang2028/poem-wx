# 跬步 · 古诗词背诵微信小程序

[poem](https://cnb.cool/npu-gpu-cpu/poem) 网页版的微信小程序移植。
覆盖小学一年级到高中三年级统编版古诗文 251 首，另设十七部课外集子
（古文观止 / 乐府 / 唐诗 / 词 / 曲 / 昭明文选 / 成语故事 / 文学名著 / 历代名家 / 历代帝王……），
共 5599 条篇目。

**未登录能看首页目录，点不动；登录后按 free / pro / max 三档放开，
而进度、设置、头像从登录那一刻起就跟着账号走 —— 换台手机登同一个微信，一切认回来。**
断网也能背：本机永远是可用的那一份，同步只是把本机已有的往上搬。

## 快速开始

```bash
# 1. 从 poem 仓库取语料并编译（数据不入库，必须先跑这一步）
git clone --depth 1 https://cnb.cool/npu-gpu-cpu/poem.git /tmp/poem
POEM_WEB_DIR=/tmp/poem node scripts/build-data.js

# 2. 离线自检（1349 项）+ 与网页版对照（28 项）
node scripts/check.js
node scripts/parity.js

# 3. 用微信开发者工具打开 miniprogram/ 目录
```

管理名录是别人的账号标识，**不进代码库**。要导入就设环境变量：

```bash
POEM_ROSTER='[{"id":"...","label":"belem","tier":"max"}]' node scripts/build-data.js
```

不设也能跑 —— 管理页如实显示「名录未导入」，只列出本机授权，不凭空编人。
CI（`.cnb.yml`）里没配这个变量，所以构建出来的是空名册，自检有断言守着这一点。

`appid` 已换成正式号（`wx200a0c667fc67fcb`），上传体验版跟着 `main` 流水线走；
`upload.js` 会把它与密钥仓库里的 `WX_APPID` 逐字比对，不一致直接拒绝上传。

## 现在到什么程度了（别看成「可以提审了」）

功能是齐的，**卡在后端**。老实分三档：

| | 状态 |
|---|---|
| **能跑** | 16 个页面、四套算法、注音、题库、飞花令、全文检索、进度总览 —— 全部离线可用，断网也能背 |
| **要配置** | 微信登录与跨设备同步。**代码已经齐了**（服务端在 [`poem#532`](https://cnb.cool/npu-gpu-cpu/poem/-/pulls/532)），剩下的全是运维动作 —— 照着 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) 一步步做 |
| **不做** | 语音朗读：同声传译插件要企业/个体户主体，自家 TTS 要付费 + 后端签名。用户裁决不做，界面里一个朗读元素都没有 |

所以「一切就好了吗」的答案是**没有**，但**没有的是外部依赖，不是代码**：
没配后端时登录降级为本机身份、档位按免费、进度只在本机，
**功能一个不少，也不会假装成功**。

提审前必须先做的三件事：

1. ~~换掉 `appid`~~（已换，见上）
2. **配 `baseUrl`**，并把域名加进微信公众平台的「request 合法域名」——
   开发者工具里勾了「不校验合法域名」能绕过，**真机绕不过**，这条最容易在提审后才发现
3. **真机走一遍**。上面所有验证都是离线跑的；安全区、原生控件外观、字体回退、
   分片下载超时各有一摊事，开发者工具的真机预览才是准的

传到体验版跟着 `main` 那条流水线（`.cnb.yml`），**只上传不提审** ——
「要不要上线」不该由流水线决定。

## GitHub 上的只读镜像

[`ashleyzhang2028/poem-wx`](https://github.com/ashleyzhang2028/poem-wx) 是本仓库
`main` 的一份**只读镜像**，每次推 `main` 由流水线最后一步同步过去。给它是为了
在 GitHub 上看代码方便（CNB 这份是私有的）。

**只同步 `main`，不同步分支** —— 本仓库有 80 多个分支，大半是合完就没用的
`auto/*`。想让某个分支也上去，先合回 `main`。

⚠️ **别在 GitHub 那份上直接提交。** 它是单向的，下一次同步会覆盖掉你的提交。
要改代码在这边改。

同步那步用到一对密钥，走**密钥仓库**（`poem-wechat-mini-program-secrets` 的
`wechat-ci.yml`），不进代码：

```
GH_PAT    fine-grained PAT，对 poem-wx 有 Contents: Read and write
GH_REPO   ashleyzhang2028/poem-wx
```

那两份密钥仓库的配置里，`allow_slugs` 要覆盖本仓库、`allow_events` 要含 `push`，
不然流水线读不到它们（同现有那几个键的规矩）。

同步失败会让整条流水线**红** —— 它排在最后，前面几步成不成都不影响
「GitHub 上有没有这一版」这件事本身。

## 要联网的四条路，和「request 合法域名」

小程序里 `wx.request` 只能打在**微信后台登记过的域名**上，没登记的域真机上一律
`url not in domain list` —— 这是平台名单制，不是配置失误，它换来的是「小程序的代码
由微信替开发者下发」这件事本身的安全。名单分 request / socket / uploadFile /
downloadFile / 业务域名几张，**互不通用**；本项目只用到 request 这一张。

本项目只有四条路要出网（`utils/remote.js` 的 `PATHS`）：微信登录、进度同步、
TTS 合成、管理接口。**没有域名也能跑** —— 语料、算法、记音、进度全在本机，
断网照背，丢的恰好是这四样，届时界面如实说「后端未就绪」而不是假装成功。

配一个能填进名单的域名要三条：**https + 有效证书**、**已 ICP 备案**、
**不带端口不写 IP**。本项目用云托管给的默认域（腾讯的、已备案），
照 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) 第 6、7 步加进去就行。

填完之后客户端只改一处：设置页里 `configure({ baseUrl })` 填同一个域名。
完整说明见
[docs/architecture.md § 五点五](docs/architecture.md#五点五request-合法域名小程序唯一绕不开的一张网)。

## 谁能用

| 档位 | 能力 | 怎么拿到 |
|---|---|---|
| 未登录 | 只能看首页书目（一年级上下册），点不动 | 谁都能进 |
| **免费** | 每日背诵 / 今日加背 / 课外阅读 / 注音辅助 / 艾宾浩斯 / 进度总览 / 全站搜索 | 微信登录即得 |
| **登录即开** | 同步进度 / 进度导出 / 莱特纳盒 | 微信登录即得 |
| **专业** | SM-2 / 题库 / 自选清单 / 管理页 | 管理员发放 |
| **全能** | FSRS / 飞花令 / 考试 | 管理员发放 |

三档**都不收费**，由管理员在管理页里按人分（微信不允许个人主体做虚拟支付，
但这里本来也不需要支付）。

一句得说清的取舍：小程序**做不到**「打开即强制登录」——`wx.login` 是静默的，
要用户点头的接口又必须由手势触发，没有 API 能在启动时弹授权框。
所以写法只有一种：进门容易、用起来要求登录。

## 功能

- **门禁**：未登录只能浏览首页目录，点任意一首给一句人话 + 登录入口，不静默跳转
- **每日背诵**：按选择的年级学期与范围排出今天要背的几首，分「复习」与「新学」
- **今日加背**：今天想多背一首就自己加（上限 20，跨过 0 点自动归零）。
  入口在首页那张「今日加背」搜索卡、详情页与背诵弹层里的「加入今日背诵」，
  清理由背诵设置页那张面板（全选 / 移出选中的 / 全部清空）。
  加进去的当场排进今日计划，小签标「今日加背」——
  它与排期器自己凑数补的那几首（可能标「补充」）分得开
- **四套复习算法**：艾宾浩斯遗忘曲线 / 莱特纳盒 / SM-2 / FSRS，设置页可切，**换算法不清进度**
- **背诵设置**：先选**当前学段**（小学 / 初中 / 高中），年级格只列这一段
  （一至高三十二个年级一个不丢，换学段就换一排，取诗范围跟着换）；
  范围 7 选 1：本册 / 本册及之前 / 小学随机 / 初中随机 / 小初随机 / 高中随机 /
  全部随机（这张卡原来叫「取诗范围」）
- **课外阅读**：十七部集子（页面上不再报「十七部」这个数），按「课内 / 诗文典籍 / 人物 / 文史常识」四张卡分组进入
- **全站搜索**：搜篇名 / 作者 / 正文，不让人选「搜哪儿、怎么搜」——
  先按篇名作者找，没结果自动落到正文全文
- **作者索引**：从搜索页进，按朝代先后把 **540 位作者** 铺成一页
  （15 个朝代段，段内按拼音），点一位读他的全部作品；
  **下一篇只在这一位作者里走**，走到头退回他的列表。
  与网页版 `/authors/` 同一条产品口径 —— 那两件事的来龙去脉见下面「作者索引」一节
- **背诵进度**：已学 / 已掌握 / 今日到期，未来七天排期，记忆阶段分布
- **古诗词大会**：飞花令（随机出一个字，自己写一句接，对错自动翻题）、题库（逐题判定）、考试（限时 20 分钟，全部答完再批）
- **答题音效**：答对 / 答错 / 过关 / 出分四种，Web Audio 现场合成，零音频文件；
  可在「声音设置」里关掉，旁边有「试听一声」当场验这台设备出不出声
- **按体裁判版式**：七绝律诗一句一行（作者排的）；《琵琶行》的序、《左传》的长篇
  对白按句读折开，且按段落断开 —— 长诗不再是四十几行连成的一堵墙
- **注音**：三种模式（不注音 / 生字 / 全文）。读音表离线进包，多音字按词组消歧 ——
  「白发」读 fà、「作为」读 wéi、「不是」读 bú、「一行」读 yì
- **通用设置**：对齐方式、注音、字号。**只在详情页与通用设置页**出现 ——
  背诵设置页不再有这一行（它只管背哪些、每天几首、怎么复习）。
  注音原先单开一页「阅读设置」，2026-10-04 并回来了：三件事是同一组版式偏好，
  分两页改一处要跑两趟。那页现在只留答题音效，名字也跟着改成「声音」
- **主题色**：九种中华传统色（朱红 / 明黄 / 天青 / 雨过天青 / 胭脂 / 竹青 /
  玄色 / 鸦青 / 天水碧）+ 一格「墨」回到默认。后两个（雨过天青 / 天水碧）
  是替换了原先的月白 / 藕荷 —— 那两个对页面白底几乎看不见。选了之后
  按钮、选中态、卡片与列表标题、
  底栏当前项一起换 —— 页底、卡片、状态色（成功 / 危险 / 待办）不动，
  正文与诗词也仍是中性墨。做法与两条边界见
  [`docs/design-system.md`](docs/design-system.md) 的「主题色」一节
- **正文全文检索**：不只搜篇名作者，正文里的句子也搜得着，带出命中那一句
- **题库**：五种题型（下句 / 上句 / 作者 / 朝代 / 篇名），可按需勾选；
  考试与题库共用同一套出题与判分内核
- **同步进度**：**登录即得**（2026-10-04 起不再分档）。跟着账号走的是七样：
  背诵进度、已读标记、今日加背、自选清单、**全部设置**（年级 / 册次 / 范围 /
  每日首数 / 算法 / 主题色 / 注音 / 字号 / 对齐 / 自动翻篇 / 朗读偏好）、
  **头像**、昵称。合并是「新者胜」（两端都按 `updatedAt` 比）。
  只有「跟设备走」的那一项例外 —— 答题音效取决于这台机器的扬声器，不搬。
  登录那一刻就同步一次，不必等下一次启动；没后端时离线队列攒着，不假装成功
- **管理页**：给微信登录用户分层（free / pro / max）与改角色（owner / admin / user），
  归档对齐网页版的权限表；改档只走服务端，没有「改本机档位」那条路
- **用户与权限**：free / pro / max 三档，与 poem 同一张表
- **导出备份**：整份数据复制成 JSON，换手机时导回去

## 与网页版对照（摘要）

逐条在 [`docs/parity.md`](docs/parity.md)，这里只给结论。**记号只有四种**：
✅ 两端都有 / ⚠️ 换个做法（平台不同，能力不丢）/ ⏸️ 小程序端没做 / ❌ 是缺口。

| 一类 | 结论 | 差在哪 |
|---|---|---|
| 内容与阅读 | ✅ | 语料 / 译文 / 十七部集子 / 索引卡 / 注音 / 全文检索，一条不少。差「注音勘误审核」与「打印页」 |
| 背诵与复习 | ✅ | 四套算法 / 六种范围 / 掌握度 / 进度总览 / 今日加背。差「自选清单」 |
| 大会与出题 | ✅ | 飞花令、题库、考试、音效都在。差「正式考试」与「文学常识考试」（依赖后端组卷） |
| 账号与同步 | ⚠️ | 身份换成微信，其余对齐。差「邮箱密码登录」（平台不同，不该做）与「家庭子用户」 |
| 报告与反馈 | ⏸️ | 网页版的报告台账与跟帖都要后端，小程序端先给「复制联系邮箱」这一条出口 |
| 平台形态 | ⚠️ | 外壳 / 控件 / 离线 / 部署全按小程序最佳实践换掉，不是缺口 |

**一处刻意的反向补充**：微信登录是小程序有、网页版没有的一层 ——
服务端那两条路由在 [`poem#532`](https://cnb.cool/npu-gpu-cpu/poem/-/pulls/532)，
契约见 [`docs/wx-login-server.md`](docs/wx-login-server.md)。

这张表由 `node scripts/parity.js` 守着：网页版 `js/entitlement.js` 里
每一个能力键，都必须在小程序端落成「已实现的能力 / 页面」或
「`docs/todo.md` 里的某一条」。**漏一项就红。**

## 朗读：不做，界面上也没有

TTS 通道个人主体申请不下来（同声传译插件要企业 / 个体户主体；自家 TTS 要后端签名
并按量计费）。用户 2026-10-02 的裁决是**不做**。

于是界面里**一处朗读元素都没有**：详情页没有朗读那格、没有播放工具栏、设置里没有朗读卡、
「我的」页没有入口。上一版留了一张写着「待开通 / 朗读通道待接入」的卡 ——
那等于每次进详情页都杵着一块死内容，比没有更糟。

`utils/speech.js` 里三条通道的代码还在（不是删了，是不接），
`docs/todo.md` 第 1 条记着为什么不做。**「不做」和「还没做」分开记**：
写成「以后做」，下一个人会误读。

自检守着这条：全页面扫源码，任何一处冒出朗读元素或「待开通」这五个字就红。

## 能力不可用时不显示

**这是这个项目的一条硬规矩。**

注音、正文全文检索、答题音效、云端同步，都按这套走：

| 能力 | 什么时候不显示 |
|---|---|
| 注音 | 读音表没生成 |
| 正文全文检索 | 倒排索引没生成 |
| 答题音效 | 运行环境没有音频接口 |
| 同步进度 | 通道没开（如实写「换手机进度不跟随」）|

判定这件事的函数一律叫 `readiness()`，同步返回三个值：

- `visible` —— 界面里该不该出现这个元素
- `usable` —— 能用，还是只是占着位置
- `state` —— `ready` / `awaiting` / `denied` / `unsupported` / `missing`

**能力压根没有**时连位置都不占 —— 一个点不动的按钮比没有更糟。

### 先做减法，再谈风格

上一版单看每一块都不难看，问题是它**靠颜色和装饰区分「这是什么」**：

| | 上一版 | 这一版 |
|---|---|---|
| 分层 | 纸纹 + 底色差 + 卡片投影 | 只靠**留白**与一道极淡的描边（**卡片不带投影**） |
| 主色 | 八种身份色（背诵墨绿 / 复习琥珀 / 忘记朱砂 / 大会青碧……） | **一种**：墨黑 `#1c1c1e` |
| 表达重点 | 主色卡 + 金边 + 印章，一屏好几处在喊 | **大数字**，一屏只有一组 |
| 圆角 | 四档 | 三档 |
| 字阶 | 十档（22 → 104rpx） | 六档 |

一句话：**一屏里填黑的地方只该有一处。** 首页是「开始背」，详情页是「记住」，
设置页是选中的那一格。

底色是中性浅灰 `#f5f5f7`，卡片是白，凹槽是 `#f2f2f4`。
状态色（绿 / 琥珀 / 朱砂 / 青）只表达状态，不表达身份 ——
上一版它们是「复习用琥珀、大会用青碧」这种按页面分派的一套。

**参考图里最抓眼的那处做成了共用件**：`.stats` / `.stat` 三个大数字并排、
中间一道细竖线。首页（今日 / 已背 / 还剩）、我的（已学 / 已掌握 / 已读）、
进度页（已学 / 已掌握 / 今日到期）三处都走它 —— 各写一遍，字号和颜色一定会漂。

**外壳不照搬网页版**：顶栏用原生导航栏（白底、墨字），免掉一整套状态栏与胶囊避让的计算。
底栏**自绘**而不是原生 tabBar —— 原生 tabBar 的图标只能是图片文件
（`iconPath`），本项目一条图片资源都不引、图标一律 CSS 画，所以
`app.json` 里开了 `"custom": true`，组件在 `custom-tab-bar/`。
形状照参考图：图标在上、文字在下，选中的那一项嵌进一块墨黑圆底。

### 篇名宋体：先系统，后外挂

一整套中文宋体 woff2 有 3MB，主包只剩不到 400KB，**塞不下**。所以分两层：

1. `--font-poem` 按平台排一串系统字名（iOS 的 Songti SC、Windows 的 SimSun、
   Android 的思源宋体 / Noto Serif CJK……）。缺一个，那台机上就**静默退回黑体**。
2. 整串都没命中时，`utils/font.js` 用 `wx.loadFontFace` 拉一份**篇名子集**：
   全站 5599 篇的篇名 + 作者名去重只有 3074 字，切出来 1.2MB，走 CDN
   （与正文分片同一条路）。生成脚本 `npm run font:subset`。

**没配 CDN 就一笔不发起** —— 与「能力没就绪就别留假状态」同一条口径，见
[docs/architecture.md § 六](docs/architecture.md#字体与高度这一轮的两条硬口径)。

**控件一律用小程序自有的**：开关是 `<switch>`、单选是 `<radio>`、多选是 `<checkbox>`、
滑动是 `<slider>`、挑一个用 `<picker>`、按钮是 `<button>`。
自绘控件长得再像，也拿不到平台给的点击区、读屏与惯性，所以一个都不留。
只有列表行与正文卡片仍是 `<view bindtap>`（它们是导航不是控件），触碰反馈借原生
`hover-class`。样式表只统一尺寸字体，配色靠 `color="#1c1c1e"` 这类组件属性给 ——
原生控件的外观改不到内部，这点必须写在属性上。管理页的改档改角色更进一步，
直接用系统的 `showActionSheet`。

### 控件与文字的几毫米

Issue 里那句话问得对：**「这些难道不是小程序原生控件就设置得好好的吗？」**
—— 不是。原生控件给的是**行为**（点击区、读屏、惯性、键盘），
**不给排版**：`<radio>` 就是一块 23px 的方框，它不自带外边距，
紧贴右边那行字是浏览器的排法，不是控件的排法。同理，原生 `<button>`
的文字不保证居中 —— 它的行高由平台按字号算，和页面给的 `height` 对不上就偏。

所以这几件事**必须在样式表里补，且只补一处**：

| 事 | 补在哪 | 为什么不能各页自己补 |
|---|---|---|
| 选项与文字的间距 | `app.wxss` 给**还在用裸控件**的那几处（`.pref-item`）在控件自己身上写 `margin-right` | 之前靠 `.opt-main` 的 `padding-left` 兜，只兜住「两行文字」那一种，单行的那几页就贴在一起了 |
| 按钮文字垂直居中 | `.btn` 改成 `flex + align-items:center` | 网页版那套「height 88rpx / line-height 84rpx」的凑法在小程序里会偏，且字重、字号、系统字体任一变，偏的方向还不一样 |
| 分段控件的宽度 | `.seg-group` 一律 `flex: 1` | 上一版只有加了 `.fill` 的才撑满 —— 列表页那条「全部 / 未读」缩成一小撮，搜索页的「全站 / 课内」撑满整行，同一屏两种宽窄 |
| 同级文字的字号颜色 | `field-label` / `card-title` / `hint` 这些类只在 `app.wxss` 定一次 | 之前搜索页有两个类（`.opt-label` / `.section-label`）干同一件事，字号差 3rpx、颜色一个深一个浅，同页出现就露馅 |

自检里守着它们的几条：控件间距 / 没有第二份间距 / 按钮 flex 居中 /
没有用 line-height 凑居中 / 同级文字只定一次 / 三种「选一个」是同一块填色 /
选项行不许再画竖线 / 样式表括号配平。

### 版式：一句一行，但不是每一句都一行

> 五言七言绝句律诗可以一句一行，琵琶行还有其他这种怎么能一句一行呢？

能，但**得分开算**。这两件事看着是一件事，其实不是：

| 体裁 | 语料长什么样 | 该怎么排 | 为什么 |
|---|---|---|---|
| 七绝律诗（《咏鹅》《江南》） | 一行一句，末字带标点 | **一行一句，别动它** | 这就是作者排的版。`杨柳青青江水平，` 折成两行是反的 |
| 长诗（《琵琶行》的序） | 一行承 27 句，就是整段诗序 | **按句读折开**，折出来的行停在句读上 | 整行一个块排出来是一堵墙，居中更是没法看 |
| 古文（《郑伯克段于鄢》） | 一行承十几句 | 同上 | 语料本来照原文的句读排，折开即是还原 |
| 词（《宴山亭》） | 一行一段 | 同上，**并且按阙分段** | 分词上下阙是两件事，糊成一片读不出结构 |

所以版式在**语料层**算一次（`corpus.layout()`），正文与注音两条路都走它：

```
corpus.layout(text) → {
  paras: 段落 → 行 → 句     // 注音（逐字）要看到句
  rows:  拍平的行            // 正文要看到行，一行一个块才排得出版式
}
```

三个坑，都在自检里守着：

1. **折出来的行要停在句读上**。收行点漏判一个标点，两行会并回去 ——
   拼回去照样等于原文，靠「拼得回原文」那条不变式**抓不到**。
   所以另有一条查「有没有孤字成行」。
2. **短句不折**。《江南》的 `杨柳青青江水平，` 是七绝的一行，不折。判据是
   「这一行每一句都短」—— 七绝每句七个字，一律不折；散文里长短句混着，折。
3. **语料行末那一句常常没有标点**（`……月承幌而通晖`，15000 多处）。
   它不能自己占一行，否则屏幕上就是一行孤零零的一两个字 —— 并回上一行。

自检里六条守着这一节，跑的是**全站 5599 篇**：折叠不丢字、段落与行同源、
折出来的行不许孤字成行、短句不被折、长句真的被折、阅读页只走 `layout()`。

### 「选一个」只有一套长相

> 注音、生字注音目前的单选按钮的形式非常丑陋，有图标的表达形式吗？
> 取诗范围我看不出还包括单选框的必要性 …… 选项也不统一。

说清了「丑」在哪 —— **不在圆点**（它是原生控件，行为、读屏、点击区都对），
在于**同一个界面上出现过四种「选一个」的说法**：原生圆点、一道左侧竖线、
填色的底、填色的格子。四种都在说「这几个里选一个」，谁也说不清谁。

现在收敛成**一套**。三种排布，**选中态完全一致：那一块填墨黑**。

| 排布 | 用在哪 |
|---|---|
| **分段控件**：合成一颗胶囊，选中的那段填墨黑。一律撑满宽度 | 两三个互斥项（对齐 / 注音 / 在哪儿搜 / 玩法） |
| **等宽格子**：一格一个方块，选中的填墨黑 | 等长的一堆（学期 / 年级 / 每日首数 / 题型） |
| **竖排选项行**：一行一个，选中的填墨黑 | 名字较长、要一行一个（取诗范围 / 复习算法） |

三者**未选中的样子也一样**：白底 + 一道极淡的描边。
（上一版格子是浅灰底、选项行是白底 —— 同一屏两种底，就是「不统一」的来源。）

**圆点在这里是多余的第二遍。** 它只在「没有别的选中标志」时才需要。
所以选项行里的原生控件现在是视觉隐藏的（`.opt-radio`），跟分段、格子一样。
底层**仍是原生 `<radio>` / `<checkbox>`**（包在 `<label>` 里、视觉隐藏）：
点整段都选中、读屏读得到、键盘走得了 —— 换的只是一张脸。

**顺手修掉了「取诗范围」选中行的破相。** 那一行原来是
「浅灰底 + `inset 6rpx 0 0` 一道竖线」：inset 阴影不参与圆角裁切的外沿，
而这一行有 `border-radius` —— 圆角把竖线的上端切掉一个斜口、下端也切掉，
屏幕上就是一根上不接顶、下不接底、左上还有豁口的黑条。
现在不画竖线了，整块填色本身就说明了「这一行」。

### 图标：同一份网格

> 不注音，生字和全文图标也是**瞎画不对齐**。

上一版确实各画各的：圆的溢出比方的大、光学中心不在一条线上，并排就是「不对齐」。
现在定一份网格 —— 画布 24×24rpx、图形内缩 2rpx、线宽只有 2.5rpx、
描边类与实心类不混、配色走 `currentColor`（段选中时图标自动跟着白）。

三枚「注音」共用一个母题（**一个字 + 它头上的拼音**），差别落在「有几个」上：

- **不注音** —— 一个「字 + 拼音」被圆圈加斜杠划掉
- **生字** —— 只有**一个**，右边空着一大块
- **全文** —— **三个**一路排到底，一点都不空

第一版我给「全文」画了三道横线 —— 那正是 `.ic-left` 的样子，并排出现就是
「瞎画」的来源。所以母题换掉了。「全站」（地球）也一样：只画圆加一道横线
会读成「⊖（禁止）」，得把**经线**也画出来才像球。

### 六句话六件事，和「让人少选一件事」

> 今日背什么 改成 背诵范围
> 如下按此顺序一行内显示（整体居中）：左对齐 居中 不注音 生字 全文 A- A+
> 十七部集子 改成 课外阅读
> 搜索页的 范围 方式选项卡片删除 搜索框内已经有提示，不要再增加用户选择成本
> 模拟考试改名为考试 所有题目答完后再给分给对错 (宽度你应该只显示一半)
> 5 个题型（可多选）全填成墨黑胶囊，跟「选一个」的选中态长得一模一样，
> 只看色块分不出哪个没勾

六句话，六件事，落在四个地方。它们的共同点是**都在减**：减掉一句话、
减掉一个要用户选的东西、减掉一层看不见的线索。

**注音 · 对齐 · 字号从背诵设置页整块撤掉。** 这三件事前后出过两版错：先是被
连同年级、学期一起塞成「一行七个段」，再是被收成「一行三段」。两版都把**阅读偏好**
搬到了它不该在的地方 —— 用户要的是「选背哪些」，不是「诗怎么显示」：

> 「注音 ｜ 对齐 ｜ 字号」只应该出现在详情页和具体古诗背诵卡片里，
> 怎么显示在了背诵范围这里

它们本来的去处就够：**详情页**（读这首诗时顺手调）+ **通用设置页**（集中调一次）。
背诵设置页现在只管五件事 —— 学段 / 年级 / 学期 / 背诵范围 / 每日首数 / 复习算法。

**这一屏后来又按同一段话的后半句动了一次**（「背诵范围内……应该显示为 当前学段」、
「取诗范围修改为 背诵范围」）：

- **卡片改名**：「取诗范围」→「背诵范围」。改名之后页头让位 —— 一屏里不再
  两句同样的话（页头改成一句管整屏的短话，与「怎么读」同一长相）。
- **补上「当前学段」那一格**：小学 / 初中 / 高中三格，年级格只列这一段。
  这一格是**补**，不是砍：上一版把「年级从十二格收到六格」那句读成了
  「十二格必须同屏」，于是没有学段那一格 —— 用户在小学段里也能看见「高三」，
  却看不出自己站在哪一段里。现在三段合起来正好是那十二个年级，一个不丢，
  换段就是换一排；取诗范围也跟着换（选「初中」就落回「初中随机」）。
  `check.js` 同时守两件事：**12 个年级都还在**（被砍就红）、
  **屏幕上只列当前学段那几格**（退回十二格同屏也红）。

**「每日首数」那张卡留着**，四档是 3 / 5 / 10 / 20。上一版把它整块撤了，
理由是「全站默认就是 5 首」—— 那是把「不选时拿几首」当成了「用户不需要选」。

**搜索页不再让人选「搜哪儿、怎么搜」。** 两块选项卡片整块撤掉，改由系统定：
先按篇名作者找，一篇都没对上才落到正文全文；范围一律搜全站。
搜索框里那句「搜篇名 / 作者 / 正文」已经说清了能搜什么，
再让用户先猜「我想找的这句在标题里还是在正文里」，是把系统的活儿推给人。
留下的只有「命中几篇 · 在哪儿捞到的」那一行读数 —— 它不要求用户做任何事。

**考试：改成「考试」，也改成「先答完再批」。** 答题途中页面拿不到对错：
选项只有「没选 / 选了」两态，可以回头改；交卷时才按整份答卷批，
逐题摊开（**对的也列** —— 「我哪几道是对的」和「我哪几道错了」一样是信息）。
时间到与主动交卷走同一条路，所以「没答完」是被如实交代的：空白格判为答错。
选项也从通栏一条收成两列 —— 两三个字的选项占一整行，九成的宽度是空的。

**多选的格子换一套形状。** 上一版是「跟单选一模一样的墨黑胶囊 + 右上角
一枚 14rpx 的小勾」，而那枚勾只在选中时才出现、压在墨黑上只有 2rpx 的线 ——
于是「没勾的」和「勾了的」色块一样黑，「能多选」这件事只在选中之后才存在。
现在把线索从「一枚小勾」换成**形状本身**：多选的格子是一圈**双圈**
（胶囊里再套一颗胶囊），选中时内圈也填墨。于是

| | 未选中 | 选中 |
|---|---|---|
| 单选（别处） | 白底 + 一道描边 | **墨黑，实心** |
| 多选 | 白底 + **两道**描边 | 墨黑 + **两道描边**（内圈也填墨） |

**只看色块就分得开**：实心 vs 空心，与勾在不在无关。

### 详情页一行身份行，与「专业，精简」

> 唐 骆宾王 课内诗词 新学 这些一定一行显示，注意样式的统一与协调
> 背得怎么样是什么不专业的词汇？我需要所有页面的标题，选项，设置，
> 内容都专业，精简，不需要背得怎么样 这种口语化的啰嗦的词汇
> 白话译文改成译文
> 其他类似问题一并修复

**一、身份行收成一行。** 朝代 / 作者 / 出处 / 学段，上一版是三行三种样式：
朝代作者一行、出处一行、学段一枚胶囊。它们说的是同一件事（「这是哪首、
谁的、什么来路、背到哪了」），现在读成一句话 —— 同一个字号、同一个颜色、
同一枚「·」断开。`check.js` V26 守着三件事：这一行不许折（`flex-wrap: nowrap`）、
四段同字号同色、四段都在同一个容器里（退回去就红）。

**二、全站文案去掉口语化的垫话。** 用户点的是「背得怎么样」这张卡，
而它其实在给掌握程度打分 —— 改成**掌握度**。「白话译文」改成**译文**
（「白话」是相对文言的说法，标题上不必交代）。同样处置的还有一串页头：
「三样玩法 → 玩法」「限时一卷 → 考试设置」「走到哪了 → 背诵概览」
「我这一档 → 我的权限」「出一组题 → 练习设置」「挑一个令字 → 选择令字」，
以及设置三页的「怎么背 / 怎么读 / 怎么排好看 → 背诵 / 阅读 / 版式」。

背诵结果的提示语也一起收了：原来是「有点模糊，12 小时后再复习一次」
「没关系，30 分钟后再复习一次」「记住了！下次复习：…」——
每条前面都挂着一句情绪垫话，而用户真正要看的是那个时刻。现在只留读数：
「12 小时后再复习」「30 分钟后再复习」「下次复习：10 月 5 日」。

这一类词的问题是**它们是顺手写上去的**，一次一个，回看时看不出来。
所以 V26 里那张 `BANNED` 表是**否定断言**：14 个词，扫遍页面、分包、
工具层的**给人看的字符串**（注释先摘掉 —— 讲清楚这些词为什么被删掉，
正是给下一个人看的），撞见任何一个就红。

### 背一首诗是一张弹层，不是一次跳页

> 首页的今日古诗背诵，当用户点击古诗，他不是从页面底部弹出详情页去背诵吗？
> 请参考 /poem 代码库。这种弹出卡片式方便用户背完随即进入下一首，
> 而不需要页面之间的切换。

网页版（`/poem`）本来就是这么做的：`js/app.js` 的 `openPoem()` 把
`#modal` 摆开（`css/style.css` 里 `.modal` 是 `position:fixed; inset:0;
align-items:flex-end`，`.modal-box` 只圆上面两角、从底部滑上来），
`handleResult()` 评完分就 `closeModal()` + `renderToday()` ——
**一件跳页都没有**。

小程序这边原来走的是 `navigateTo` 详情页，背完再 `redirectTo` 下一首：
每首一次整页重建，用户看见的是一屏空白接着一屏空白。现在首页点篇目、
点「开始背」都从底部弹同一张卡上来：

| | 网页版 | 这里 |
|---|---|---|
| 打开 | `openPoem(p, planItem)` → `#modal` | `recite-sheet` 组件的 `open(queue, id)` |
| 评分 | 三格 · 关弹层 · 就地重排列表 | 三格 · 顺势进下一首 · 回调首页重排 |
| 走完 | 回列表 | 队列到头，弹层自己收掉 |

**队列由首页给**（`queue="{{plan}}"`）：下一首是什么，只有排过计划的那个人知道
（复习轮次、今日加背都排在那一列里）。组件不自己排计划，只照着往下走。
门禁也仍由首页把着 —— 组件不发网络、不查门禁，那两样是页面的事，
组件替页面做决定，页面就没法统一口径。

**阅读面因此有了两个住处**，所以它被收进了 `app.wxss` 的「阅读面」一节：
标题区 / 身份行 / 偏好行 / 正文 / 注音 / 译文，一处定义、两处使用。
这不是顺手抽个公共类 —— 抽走的每一段都带着原来那份理由（为什么身份行是一行、
为什么偏好行不许折、为什么注音那条路行距要收），搬过来时一条都没丢。
各自只留各自的壳：详情页是 `.poem-card` 的内边距与背诵卡，
弹层是底部滑上来的动画、把手、钉在卡底的评分区。

`check.js` V28 守着五件事：首页点篇目不许再 `navigateTo` 详情页、
弹层靠底且只在顶部两角是圆角、压得过自绘底栏、阅读面只此一份（两处都不许再写）、
三档评分与「顺次进下一首」都在组件里。每一条都做过反证。

> **详情页那一页仍然在**：列表页、搜索页、飞花令还要跳它 ——
> 那是「查一首诗」，与首页「今天这一趟」是两件事。

### 尺寸只有一个旋钮

> 使用他们默认的但是**小一号**的全局配置，例如 colorUI。

这句话真正的关键不是抄哪个库的类名，而是**所有尺寸必须能从一处调小**。
`styles/tokens.wxss` 定了 `--ui-scale`，字阶 / 间距 / 圆角 / 高度全部由它算出来 ——
改这一个数（例如 `.9`），整条体系一起收，不用动任何页面。

默认是 `1`：现在的尺寸是按 750 设计稿、在小屏上验证过的，再统一缩一次
会先撞到触控下限（88rpx ≈ 46px）。所以这个旋钮是给「小屏 / 大字号系统」用的。

**为什么不引 ColorUI 这类组件库**，逐条写在
[docs/design-system.md § 六](docs/design-system.md)：
它解决不了「选项不统一」这类**长相**问题、它的控件不是原生的、
两套命名会打架、主包塞不下、维护要自己扛。
而且**要的是「统一」，不是「第三方」** —— 统一是靠「只有一个出处 + 一条断言」
守出来的，不是靠引一个包。

自检里守着这一节的有：三种排布必须是同一块填色、选项行不许再有竖线与圆点、
`--ui-scale` 必须在且被这几组令牌用上、页面不许重新定义共享令牌、
样式表括号必须配平。每一条都做过反证（把事实改坏，确认它会红）。

### 观感上的几处口径

界面不追新奇，只把「想表达什么」和「看起来像什么」对上：

- **一屏一件事**。首屏那张卡只回答「今天背什么」：一行日期小字、一个大标题、
  三个大数字、一条细进度、一个墨黑按钮。下面才是清单。
  （这是**首页**那张卡的用法。背诵设置页原来也叫「今天背什么」，后来改叫
  「背诵范围」，再后来范围那一张卡自己用了这个名字、页头让位给一句短话 ——
  见下面「六句话六件事」。）
- **一屏只有一种「大」**。首屏那三个数字是这一屏唯一的「大」，
  其余全在正文那一档上。上一版靠主色卡、金边、印章三处同时喊，谁也没被听见。
- **进度给两次**。数字说「几首」，横条说「走到哪了」。只有数字的话，
  扫一眼不知道走到哪；只有横条的话，又不知道总共几首。
- **门禁只有一张脸**。13 个页面都有「未登录」这道门，收进 `components/lock-card` ——
  一枚墨黑圆标 + 一句人话 + 一个登录键，措辞各页自己给。
  以前是各页各写一份，用户看到的是每页一个说法。
- **可点就得有反馈**。挂着 `bindtap` 的行、卡片、选项，一律有 `hover-class` 或 `:active`。
  点上去没反应是手机上最差的一种体验 —— 自检里有一条扫全部页面守着它。
- **空状态给出路**。不只写「没有」，而是一枚淡圆标 + 一句人话 + 一个下一步。
- **慢的时候先立版式**。首页读语料要时间，先上骨架屏再换内容，
  观感上是「很快」而不是「卡了一下」。
- **颜色只在令牌里定一次**。页面样式表里再写一遍色值（`#1c1c1e` 也好、
  别的也好）就算回归 —— 自检守着这条。
  （原先还额外禁了一张「上一版八个身份色」的黑名单，**已撤**：
  用户明确那些颜色可以使用。禁的从来是「写死」，不是某几个色值。）
- **门禁要能开，也要能关**。这一轮顺手跑页面时发现阅读页从 PR #6 起就
  **一直停在「登录后可用」那张卡上** —— 正文一个字都渲染不出来，
  因为 `locked` 设了 `true` 却从没设回 `false`。
  之前的检查只问「这个词出现过没有」，三项全绿也照样放过它。
  现在改成真把页面挂起来跑一遍 onShow，`locked` 必须落回假。

### 设计系统：令牌不只是颜色

「从 UI 到交互到体验都不行」这句话，落到能改的地方其实只有一件：
**同一件事不许各页各写一个数值**。色漂了有人管（自检盯着），间距和字号漂了
没人看得出来，只是整页「说不上哪里不对」。

所以色之外的几件事也全在 `styles/tokens.wxss` 里，**一处定义、全站取用**：

| 一组 | 内容 | 为什么 |
|---|---|---|
| 形 | 圆角三档（`--radius-sm` / `--radius` / `--radius-block` + `--radius-pill`）、投影两层 | 多一档就多一个「今天用哪一个」的问题 |
| 字 | 字阶六档（`--fs-caption` → `--fs-hero`）+ 四个一次性大字号、行高三档、字距两档 | 页面里出现裸 `font-size: 27rpx` 就是没想清楚要表达什么 |
| 距 | 八档间距 + `--page-x` | 卡片之间的缝一眼看得出不匀，它不刺眼但整页会别扭 |
| 高 | 按钮三档 + 行高 + 输入框（`--h-btn` / `--h-btn-mini` / `--h-act` / `--h-row` / `--h-field`） | 「忘记 / 模糊 / 记住」那三个 112rpx 就是这么来的 |
| 动 | `--t-press` / `--t-move` / `--ease` | 按下 120ms、移动 280ms —— 慢了像卡，快了像没反应 |

**卡片的间距只在 `app.wxss` 的 `.card` 里定一次**，页面样式表再给卡片加
`margin-bottom` 就算回归。同理，**页头那句大标题不许等于导航栏标题** ——
同屏上下两行一模一样的字，等于什么都没说。

**圆角一律走令牌**、**大数字只有一套实现**、**页面样式表里不写死色值** ——
这三条由 V13 一节守着（都做过反证）。

自检里有六条断言守着这一节（字号走令牌 / 卡片间距只一处 / 页头不重复 /
门禁卡唯一 / 可点有反馈 / 空状态给出路），加上控件来源、门禁开合、
控件间距与按钮居中、「选一个」只有一套长相、图标与缩放令牌、
以及 V13 / V23 / V23.9 / V24 / V25 / V26 / V27 / V28 那几组共 **963 项**；
另有 `scripts/parity.js` 的 **28 项**守「网页版每一项能力都有交代」。

### 改界面时怎么「看见」

仓库里没有微信开发者工具，`scripts/shots/` 是一条离线预览的路子：

```bash
node scripts/shots/render.js          # 跑页面 → 编译 WXML → 出 preview.html
node scripts/shots/shoot.js           # 逐屏截图到 shots/out/shots/（38 屏）
node scripts/shots/shoot.js reader    # 只截名字里含 reader 的
```

它把每个页面**真跑一遍**（真实的 `onShow`、代理过的 `setData`），拿到最终 data，
再按 `wx:if` / `wx:for` 编译成 HTML，套进 390×844 的手机壳。

「答题中 / 交卷后」这类**中途状态**靠 `pages.json` 里的 `do` 往前推一步
（调页面自己的方法），不然考试页只拍得到「选范围」那一屏 ——
而这一版改的恰好是它后面两屏。

**它不替代真机**：布局、配色、文案、显隐口径是真的，原生控件外观、字体回退、
安全区是近似的。改完界面先在这儿看一遍，再去开发者工具过。**

`render.js` 里那个 WXML 编译器只够预览用（约 200 行），不要拿它当构建工具。

## 作者索引

用户对网页版 `/authors/` 的原话（Issue #480），这一页就是照它做的：

> 按时间朝代顺序，将中国所有作品的作者列在一页，上面是朝代索引列表，
> 点击朝代可以下面的具体朝代，朝代下面是各个作者，例如唐代 李白，
> 点击李白，显示李白所有作品列表，再点击列表，进入详情页，
> **详情页的上一页下一页都是该作者的作品**。返回就回到李白列表。

两层，都在**一个分包页**里（`packages/authors/index`），不新开页面：

| | 是什么 |
|---|---|
| ①**名册** | 朝代表 + 一段一段的作者。**540 位 / 2142 条 / 15 段**，段内按拼音排 |
| ②**一位作者的作品** | 复用列表页那一套（分组标题 + 行 + 已读标记 + 未读筛选） |

口子开在**搜索页**（不是课外阅读）—— 与网页版同一处，那边第二轮改的就是这个。

### 名册是「扫一眼有谁」，不是「读一行的详情」

一段里**只有**「名字 + 收了几条」两件事，排成一行行的格子。
一人一行、右边挂箭头与小字那种排法，一部《唐诗》就是上百行，
读者得点着滚动条把一整朝滤一遍。

排版按**内容**走，不按列数：名字长短差得远（「苏武」2 字、
「孔子及弟子、朱熹」8 字），等宽栅格会把长的挤成两行、短的留一大片空。
所以是 `auto-fill` + `minmax`，一行塞几颗由名字长短自己定。

### 名册现算，不进包

十部集子的索引本来就在包里（各集子的列表页要用），名册只是把它们按作者
重摆一遍 —— **540 位 / 2142 条、60ms**。比多背一份静态的「作者 → 条目」表划算，
也不会跟语料错开版本。（第二轮补录之后十部合计涨到 2253 条，名册收下 2142：
差掉的是结集 4 条，加课内已经背过、在选集里只剩一条壳的 107 条。）

两张归并表在 `utils/author-index.js`，与网页版 `data/author-index.js`
**同口径**（`check.js` V40 拿两端逐段比）：

- `ERAS` —— 把二百多种朝代写法（`宋 / 北宋 / 南宋`、`南朝·宋 / 南朝宋`……）
  收进一条时间轴。段名取归并后的（「宋」），不是原写法
- `ALIAS` —— 异名归一（`曹子建` → `曹植`、`班孟坚` → `班固`），
  否则《文选》里一个人的作品会拆到两处。共 **50 条**，`check.js` V40
  拿两端逐条比（差集双向都查，不是数条数 —— 一条改错、一条漏掉时
  总数可能正好一样）。第二轮补进三条：`孔子及其弟子 → 孔子及弟子`
  （《论语》那一批的两种写法）、`吕不韦等 → 吕不韦`、`刘安等 → 刘安`
  （先秦子书托名的「等」写不出人来，归到书上那位主人）
- `ATTRIB` —— **合编课文**的归属：`classic-gw-10`《古人谈读书》正文两段两家
  （前三句《论语》、「余尝谓读书有三到」是朱熹），显示与详情页一个字不改，
  名册里挂**朱熹**。`check.js` V40 也拿两端逐条比（**这一条是补来的**：
  #480 第三轮网页版加了它，这边只搬了 ERAS / ALIAS，名册上这一条归属就不同）

两处**故意与网页版不同**，都写在代码注释里：

1. **判重只认课内。** 网页版按作品 id（`WorksIndex.widOf()`）判「这一篇是不是
   已经在别处收过」；小程序端没有那张表，也不该为它多背 8KB ——
   做法是一篇在课内背过，它在《唐诗》里那条壳就不进名册
   （这正是网页版 `repOf()` 的裁定：课内优先）。代价是课外两部选集之间的
   重复现不出来，而那种重复在语料里本来就少
2. **结集不进名册。** 《礼记》的《大学之道》、《论语》的《子路曾皙冉有公西华侍坐》
   四条，作者一格填的是**书名**。挂上去就是「《礼记》写了《大学之道》」——
   那是编。它们在各集子的列表页照旧读得到，一个字不丢
3. **差的是哪几位。** 第二轮补录之后两边差了六位（网页版 495、这边 540）：
   崔护、刘歆、庄周、项羽、王十朋、杨基。都是同一类 —— 他名下的作品只在
   **课外两部选集**里各有一条（例如王十朋《读〈岳阳楼记〉》在《古诗》与
   《古文观止》各一条），网页版按作品 id 并成一篇、这边各收一条，
   于是这边反而多出作品、人也多冒出来几位。名单钉在 V41 里，
   哪天冒出一位不在名单上的，就是该回来对一次

### 下一篇只在这一位作者里走

用户那句话里最具体的一条，落在**评完分自动往下跳**那一处（小程序端的
「下一页」只有这一处）。从作者索引进详情页时 URL 带一个 `?from=李白`，
reader 认它：下一首在这位作者名下找，走到头退回**他的作品列表**。

⚠️ 这段有三个坑，都在注释里标着：

1. 只走**收作品的十部**。曾经这里扫了全站十七部 —— 于是李白的下一篇
   跳进了《成语故事》的「李白」词条（名册不收词条，下一篇凭什么收）
2. 作者名要**归一**：名册写「曹植」，《文选》里写「曹子建」，不归一就漏
3. 顺序要与②层列出来的一模一样（集子 → 组 → id），否则「列表里看到的顺序」
   与「下一篇跳到的顺序」对不上，用户当成 bug

这一条跨三个文件，静态扫描看不出来，所以 V41 是**真跑阅读页**验的：
连翻五首，每一首的 `author` 都得是李白、`bookId` 都得在那十部里。

## 内容跟着 poem 走，但**不偷偷跟**

语料不从仓库里搬，而是 CI 里从 [poem](https://cnb.cool/npu-gpu-cpu/poem) 现编译
（`scripts/build-data.js`）。所以那边补一篇宋词，这边下一次跑就跟着有 ——
听着挺省事，毛病也正在这儿：**「这一轮到底同步了没有」没有答案**。
网页版加了十篇、这边一声不响地也冒出十篇，谁也不知道两边是不是同一份。

所以把「跟的是什么」写下来，写进 `scripts/check.js` 的 V40：

| 判据 | 查什么 |
|---|---|
| 篇数 | 十七部集子逐部 + 课外合计 5604 条 + 带正文的 5855 条（这张表**会过期**） |
| 号段 | `gushi 1–126` / `songci 1–331` / `tangshi 1–469` 不许出现**新**空洞 |
| 归位 | 曹植《七步诗》只此一条、在《古诗「非唐代」》、朝代三国·魏；《唐诗》里非唐的只有记着的那一条（杨万里《闲居初夏午睡起·其一》，通用名篇那一段收的） |
| 朝代 | 收作品的十部集子里没有空朝代；《昭明文选》同一位作者只落一朝 |
| 时间轴 | 两端 `author-index.js` 的 `ERAS` 表逐段一致（CI 里刚 clone 了一份 poem，正好拿来比） |
| 异名 | 两端 `ALIAS` 表逐条一致（**这一条是补来的**：第一版只比 ERAS，poem 那边补的十条异名这边一声不响地落后了十条，名册上于是「桓温」与「桓元子」各挂一半作品） |
| 合编归属 | 两端 `ATTRIB` 表逐条一致（**同样是补来的**：`ALIAS` 落后是同一个教训 —— #480 第三轮给《古人谈读书》加了归属裁定，这边只搬了 ERAS / ALIAS，没搬 ATTRIB） |
| 出处两重 | 选本条目必须同时有 `source`（所出之书）与 `selection`（收它的选本）；《唐诗》《词》《曲》《文选》四部的条数逐部对（**这一条抓出过真漏**：`build-data.js` 原先根本没搬 `selection`） |
| 题名异写 | `aliases` 搬全了（11 条），点名的那几条一条不少（**与出处同一类漏**：构建脚本漏搬一个字段，界面上少一句话，谁也不会发现） |

于是 poem 那边一改，这边不是静默跟上，而是**红**。红的意思是「回来对一次」，
不是「坏了」—— 对完把 V40 那张表改掉、跑绿，这一轮才算真同步过。
篇数表会过期是**故意的**：一份永远不用改的表，也就永远证明不了什么。

这也解释了为什么号段判据是「不许有**新**空洞」而不是「连号」——
语料里本来就有洞，而且有理由（`gs-02/03/04` 是《诗经》里与课内重了的、
`sc-127` 并进了别的号、`ts-306/307` 是搬家留下的空位、`ts-427–442` 那一段是
几批补录接号时成段让出来的）。已知的空洞列在 `KNOWN_HOLES` 里；
哪天真补上了，判据会催着把它删掉，免得那张表越攒越大。

### 主包顶到 2MB 那一刻

第二轮补录 255 条（5599 → 5854）、出处勘正又给 1205 条加了 `selection`，
主包从 1.90MB 涨到 **2.05MB**（超限 46KB）。**这不是「再删几篇语料」的事** ——
正文一个字都不能动。做的是把索引里**冗余的字段**从落盘那一份里摘掉：

- `b`（集子 id）与 `n`（集子名）：各 76KB / 60KB，而**每个文件里它们是同一个常数**
  （索引本来就按集子拆文件了）
- `hasT`：63KB，5854 条**全是 true**
- 空字段（`aka: null` / `sel: ""` / `gr: 0`）：几十 KB 的纯空

摘完落到 **1.61MB**。补回来的地方只有一处：`utils/corpus.js` 的 `ofBook()` ——
它读文件时按文件名把 `b` / `n` 填回去（`hasT` 直接给 true）。语料的每一层都走
`ofBook()`（列表 / 检索 / 阅读 / 作者索引 / 试题），所以外面看到的形状与从前一模一样。
自检里两条断言分头守着：一条查 `ofBook()` **补回来之后**的归属对不对，
一条查**盘上那一份**确实是紧凑的。

> 两轮的来龙去脉见 Issue #61。第一轮（2026-10-06）对的是 #461 / #471 / #480：
> 宋词与古诗补录十轮、曹植《七步诗》归位、《昭明文选》145 条空朝代回填。
> 第二轮（2026-10-09）对的是 #505 / #510 / #512 / #516 / #517：补录 255 条、
> 出处勘正（两重出处）、成语 138 条朝代归位、11 条题名异写、两处合并勘误。
> 第三轮（2026-10-10）对的是 #539：poem 补录 `gw-288` 王安石《答司马谏议书》
> （有正文、非课内、非词条壳），classic / cards / withText 三个数一起 +1 ——
> 号段与出处两重不受影响（它不记 `selection`、也没接新号）。
> 这些**不是在小程序端的数据里做的** —— 数据一直是现编译的；
> 两轮做的都是把口径钉下来，让「同步」这件事有据可查。

## 数据放在哪

正文**不全进包，但课内那 251 首进包**。实测全部正文 24.3 MB（gzip 后 4.9 MB），
而主包上限 2 MB、总包 20 MB，一部《昭明文选》就超了；课内 251 首只有 223 KB。
所以分三层：

- **包内**：各集子索引（1.0 MB）+ **课内 251 首的正文与译文**（223 KB）；主包合计 **1.30 MB**
- **云端**：其余 5348 条正文切成 119 个约 200 KB 的分片（合计 23 MB），放腾讯云 COS + CDN 按需取
- **本机**：背诵进度、设置、已读标记

课内正文进包是刻意的：首页「每日背诵」与详情页都靠它，223 KB 换掉一次云端往返，
省下的是每天真正被打开的那两个页面的等待。边界由自检验着 —— 课内进包、课外走分片，
同一份正文不许两边各存一份。

详细推演见 [`docs/architecture.md`](docs/architecture.md)。

## 后端怎么部署

后端在 [`npu-gpu-cpu/poem`](https://cnb.cool/npu-gpu-cpu/poem) 的 `api/` 里 ——
**本仓库没有后端代码**，只有部署描述（`deploy/`）。镜像由 CNB 流水线构建
（源码取 `poem`，Dockerfile 从这边取），云托管按**镜像**部署。

```bash
git checkout main && git pull   # 推 main 就出镜像
```

然后照 [`docs/wx-cloud-setup.md`](docs/wx-cloud-setup.md) 一步步做：建服务（填镜像
`ghcr.io/ashleyzhang2028/poem-wx/wx-api:<poem 短 sha>`，端口 8080）→
配环境变量 → 建 `wx_accounts` 表 → 加 request 合法域名 → 填 `baseUrl` → 验。

⚠️ **镜像地址填 GHCR 那份，不要填 CNB 制品库那份**（Issue #71）：CNB 的 Docker
制品库可见性跟着代码仓库走，本仓库 Private → 制品私有 → 云托管「从地址拉镜像」
那一栏拉不动（它只收公开镜像），要么配拉取凭据、要么把整个仓库改 public。
所以流水线一次推两份：GHCR 那份是**公开包**，云托管直接拉，**不用配凭据**。
CNB 那份留着当回滚路（私有，要凭据才拉得动）。两份是同一棵树。

⚠️ **推 GHCR 那两个密钥里，`GHCR_TOKEN` 必须是 classic PAT**（密钥仓库
`wechat-ci.yml` 的 `GHCR_USER` / `GHCR_TOKEN`）。GitHub 原话是 *GitHub Packages
only supports authentication using a personal access token (classic)* —— 所以
**fine-grained token 的 Permissions 里没有 Packages 那一栏，不是藏得深，是不存在**。
`write:packages` 是 classic 的 scope，走这个链接建：
<https://github.com/settings/tokens/new?scopes=write:packages>。
（同文件里的 `GH_PAT` 是另一码事 —— 同步代码用的，fine-grained 的
`Contents: Read and write` 就够。两个别互相顶替。）

⚠️ **别选「部署方式 = 代码仓库」**：指本仓库，它按仓库根找 Dockerfile 而那儿没有
`api/`；指 `poem`，拿到的是 49MB 全量镜像，小程序一条静态资源都读不到。
流水线为什么这么构建，见 [`deploy/README.md`](deploy/README.md)。

消息契约在 [`docs/wx-login-server.md`](docs/wx-login-server.md)（含
`device` vs `deviceId` 那个静默坑）。

## 还没做的

**逐项对照与记账各自有一份文件**，别凭印象估：

- [`docs/parity.md`](docs/parity.md) —— 与网页版**逐条**对照（内容 / 背诵 / 大会 /
  账号 / 反馈 / 平台形态），四类记号：✅ 两端都有、⚠️ 换个做法、⏸️ 没做、❌ 是缺口
- [`docs/todo.md`](docs/todo.md) —— 「未做、可能要做的」全在这里，
  外加一张「明确不做」的表（免得把「不做」误读成「以后要做」）

下面是摘要，细节以那两份文件为准：

- **朗读不做**：TTS 通道个人主体申请不下来，界面里一处朗读元素都没有（见
  [`docs/todo.md`](docs/todo.md) 第 1 条，以及上面「朗读：不做，界面上也没有」一节）
- **付费档不能小程序内下单**：微信不允许个人主体做虚拟支付，
  `pro` / `max` 只能由管理员发兑换码，或后端名录里改档
- **后端要配一遍**：接口契约写死在 `utils/remote.js`，**报文形状收在 `utils/wire.js`**。
  服务端代码已就绪（微信登录两条路由 + 会话认 Bearer + 白名单，都在
  [`poem#532`](https://cnb.cool/npu-gpu-cpu/poem/-/pulls/532)），
  同步与管理复用 poem 已上线的那几个。管理页里可以直接填 `baseUrl`。
  没配之前一律降级，不做任何「假装成功」
- **`node scripts/e2e-wx-sync.js` 是这一块的真判据**：它把小程序端 utils 与
  poem 服务端接起来真跑一遍（登录 → 同步 → 设置/头像/进度真落库 → 换台手机认回来）。
  上面那些静态自检验得了「报文形状对不对」，验不了「两边合起来通不通」——
  而这一轮的坑（**登录通但同步一律 401**、字段被服务端裁掉、换机认不回来）
  全都是合起来才显形的
- **跨端同步要服务端配合一次核对**：小程序发的报文已经按 poem 的
  `sanitize*` 逐字段对齐并写进自检（自检会直接 require poem 的源码来验），
  但**「同一个人在两端的 uid 是同一个」这件事只有服务端能保证** —— 见文档末节
- **客户端档位不是安全边界**：改本机存储就能提档，真扣配额必须在服务端做
